# 任务工作台

正式前端采用用户确认的 B2：紧凑蓝色工作台、可展开左导航、画布优先与按需详情。使用 React 18、TypeScript、Vite、React Query、Zustand、React Flow、ELK、Ant Design 6.6.5、Ant Design X 2.9.0、Ant Design Icons 6.3.4 和 react-resizable-panels 4.14.3。

## 开发与验证

```sh
make web-install
make web-types
make web-check
make web-build
make web-dev
pnpm --dir web e2e
```

开发服务器默认将 `/api` 代理到 `http://127.0.0.1:58000`，可通过 `BBX_API_URL` 指定独立服务。pnpm 缓存在 `/private/tmp/bbx-pnpm-store`；镜像配置见 `.npmrc`。先构建 `web/dist`，再执行 `make image-blackboard`；blackboard 静态托管构建产物并支持页面深链。

E2E 的入口是 `e2e/run.cjs`：所有业务请求使用 Mock；真实浏览器附件下载由隔离的随机端口 HTTP 服务提供，未登记请求返回 501 并使测试失败，不回退到本地生产 API。不需要真实模型或靶机。覆盖与实际结果见 [B2 重构报告](../docs/tasks/UI-rebuild-report.md)。

## 页面与交互

- `/login` 使用 Cookie 认证；任务列表、新建任务和 Agent 配置由左导航进入。右上账户菜单提供退出。详情归属任务，进入详情时不会新增“协作画布”全局菜单。
- `/tasks` 显示任务名、短 ID、模式、状态、金额和时间。完整目标仍是任务内容，列表与顶栏只呈现简短标题。列表明确区分模式、运行状态、已记录费用/预算与运行耗时，结束不等于目标已通过，未知费用显示“—”。手机纵向展示全部信息；搜索与分页状态在详情往返时保持。任务删除使用明确确认并保留原清理流程。
- `/tasks/new` 保留普通黑板/CTF 模式、模型、推理强度、预算、初始附件、完成要求和网络配置。上传仍由原队列及 API 管理，创建不自动调用模型。
- `/profiles` 集中配置 Worker、CTF 角色、模型与 MCP。提示词与工具并排，低频设置折叠；保存保留草稿、版本冲突与原生凭据语义。普通 Worker 提示词下一次调用生效；CTF 配置与全局运行配置用于新任务。
- `/tasks/:id` 默认完整画布。点击 Agent 打开连续会话；点击 Fact/Intent 或题目打开详情。右侧可拖动、方向键调宽、双击复位、放大/还原及 Esc 关闭；窄屏使用工作区内全宽详情；断点切换不卸载当前会话，覆盖的画布不进入键盘焦点。
- 顶部“目标”在画布列就地展开原目标、完成要求和初始附件，长目标有全文及原文入口，背景按需展开。查看目标不重建会话、不清草稿、不改变已操作的画布视角。手机暂时隐藏原详情，收起目标后恢复。
- 普通黑板的事件、裁定、回放、工作区从“更多任务操作 → 复盘记录”打开；报告、归档、历史轮次和续跑保留原入口。CTF 题目提供概览、解题流程及文件，成员的停止/恢复/移除在会话菜单中。
- CTF 自由协作黑板以 Lead 为协调入口，同题只有一个节点，主责实线、协作虚线、团队结构无箭头；选中突出直接关系。题目显示最新共享记录，详情按时间呈现真实分配、工作状态与记录，可展开原文和证据；Lead 调度按钮查看真实历史。正式布局为明亮环绕：Lead居中，成员内圈、题目向外；短关系线常驻，团队线按需出现，分配/进展/交付由真实更新触发一次性光束。手动坐标与视角按浏览器和任务保存，刷新保留；改派仅移动相关自动节点。已完成题目可折叠并通过定位打开，大图支持全图总览。实施与回归结果见 [环绕协作报告](../docs/tasks/CTF-orbit-report.md)。

配置子页支持 `/profiles?section=models`、`ctf` 和 `mcp`。未保存时离开配置页会确认；保存期间等待结果，避免草稿直接丢失。模型必填价格会展开并定位错误；非人民币旧单价需要重新录入。MCP 连接修改需保存后才能读取对应版本的工具清单。新建任务缺模型时可在新标签页配置，再返回刷新，不丢失当前内容和已上传附件。

历史工作区按所选轮次读取目录、文件及下载归档，缓存按轮次隔离。报告任务信息读取失败可单独重试，不隐藏已获取的正文；历史报告经过登录仍保留轮次。补充回归范围见 [使用细节复核报告](../docs/tasks/UI-detail-review-report.md)。

## 对话与数据边界

Bubble 和 Sender 负责紧凑呈现与输入，仍调用原消息 API；幂等 ID、未知结果重试与未发送草稿在当前任务的 Agent 切换、面板开合和响应式布局切换间保留。历史回放只读，任务结束保留会话，删除任务按原生命周期清理。

Think 仅显示服务实际保存的推理文本或摘要；ThoughtChain 显示工具参数及配对结果。初始上下文、黑板同步注入、模型响应、工具和结束回执可按来源读取；正常历史与 checkpoint 保存的结果均保留。不展示不透明回放字段，不根据 token 数推造思考内容。当前按完整响应 checkpoint 更新，不冒充逐 token 推理流。

Markdown 不执行 HTML 或自动加载外部图片，长代码独立滚动并保留原文。普通黑板按作者颜色关联 Agent 与其创建的 Fact/Intent；认领不改变作者。CTF 的工作完成、候选、平台真实/模拟验证和任务终态分开显示，人工确认入口不恢复，历史验证只读保留。

事件按版本还原与去重，原生 EventSource 负责断线续传；语义重复由 Agent 自行判断。用户平移、缩放和拖动后的视口保留，ELK 仅按普通黑板布局需要加载。普通黑板已有节点和用户视角不随新增关系或容器尺寸改变；CTF只对关系改变的自动节点作局部调整，用户视角保持，画布卡片使用专用语义按钮维持节点布局，其余通用控件、图标、主题、浮层与短时动效由组件库统一；支持减少动态偏好。详见 [视觉规范](DESIGN.md)与[使用和部署](../docs/使用与部署.md)。
