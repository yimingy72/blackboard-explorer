## 2. 发现的问题

### 2.1 预算准入存在立即重新认领的空转路径

87个 turn 中82个 interrupted，77个无用量；82次 authorize_member HTTP409，产生62条 assignment_result 系统回执，无 model_error。Lead 自己的两次成员管理不能解释全部回合。

当前模型上限393216与明确128K输入界、CNY费率形成单次最坏预留3.401728元。三个并发请求需10.205184元，超过任务10元预算。`ctf.py:claim_turn` 先以零新增预留认领，Mailbox 随后申请实际预留；被拒绝时 interrupted 结算，而未交付的指令再次进入认领。代码路径确定存在，现场计数高度吻合，但现有日志没有保存每次409响应正文，不能证明82次都因同一预算原因。

建议后续先将准入等待与真实执行中断区分：无法获得预留的工作等待预算/并发释放，不生成一连串派工失败回执，不立即启动同一请求；预算真正不可继续时有一次明确的结束或等待结果。不要靠降低官方输出上限或增大本次预算掩盖调度问题。具体修复仍需单独实现和针对性回归。

### 2.2 币种显示确切错误，未发现重复计费

CTF profile 两角色价格为CNY，普通任务详情 API 的 cost_currency=CNY。CTF state task 未返回该字段；`CtfWorkbench.tsx` 用 state task 整体覆盖 initialTask，使金额格式器误显示“币种未配置”。

54个用量账单ID全部唯一，turn、成员、任务费用及各类token的汇总一致，按配置费率独立计算同为2.01116604 CNY。output104668中reasoning83802是子集，未重复累加。本次只核对平台记录，不代表供应商账单对账。

### 2.3 模型推理已经保存，前端没有展示

三个 Session 保存54条非空 provider `text_reasoning.text`：Lead30、runner11、verifier13。它们不是只有推理token计数；会话读取接口保留这些字段，但 `conversationEntries` 只接受普通text，忽略tool角色与推理内容，工具只显示总次数。

“公开活动”是按事件归纳的执行摘要，包含大量回合和状态通知；点击Agent目前默认打开它。用户关注的是实际交互过程，正式改版应默认直接进入连续会话，系统事件仅在调试入口按需查看。

展示范围：服务返回的推理文本或摘要、模型正文、定向消息、工具参数与结果。`protected_data` 等不透明回放数据不展示；usage推理token数不等于推理正文。后台继续保留完整Session以便恢复，面向用户的展示数据应明确投影，不直接暴露整个内部对象。

当前Session在完整响应后保存、页面每3秒刷新，现有数据可展示历史推理；逐token展示需要另接增量事件，不能把当前轮询包装成实时推理流。

## 3. 三种界面方案

原型是实际HTML/CSS，使用示例对话、推理与工具结果；图中任务名、短ID、时长与金额参考本次任务，消息不是本次Session原文。不连接真实API、不发送聊天、不提供正式续跑。原型页顶部有明确预览标识。

三案共用：

- 桌面顶部任务信息压成58px主行与34px题目状态行；长目标、初始上下文与附件按需展开，不改变任务内容。
- 去掉持续占空间的解释文字和黄色整条提示，保留简洁的候选待验、任务结束与结束原因。
- 点击成员直接进入连续对话；Markdown正文、可折叠推理、工具调用与结果、证据引用在同一条阅读流程中。
- 不再有默认“公开活动”页签；系统事件放到次级入口。
- 单独显示运行终态与候选验证状态。保留复盘问答输入；重新执行仍需显式续跑。

| --- | --- | --- | --- |
| A 并排工作台 | 左侧43%画布，右侧57%对话 | 同时看分工关系和实际执行 | 对话宽度比现状大，仍分配较多空间给画布 |

## 5. 用户选择后的 C 方案修订

用户选择画布优先，并明确详情主要指画布中的题目节点。更新后的C默认右侧关闭；Agent节点打开会话，题目节点打开详情。两种详情共用可拖动分隔线，关闭/Esc恢复完整画布；拖动宽度在当前页面内保留，支持左右方向键和双击复位。窄屏使用工作区内的全宽详情，关闭可返回画布。

题目详情分为三页：

- **概览**：当前已登记结果、工作与验证状态、参与Agent、关键证据。完整题目描述与连接信息折叠。来源保留，点击成员进入其对话，点击证据进入文件预览。
- **记录**：按来源阅读候选、复核、尝试、求助和更正原文。可回到关联Agent。版本号与内部JSON不占主要阅读空间。
- **文件**：已登记产物列表，查看原文与下载入口；统计应取相关全部记录/产物，不仅当前分页。

当前模型没有独立题目总结/结构化TODO/精确答案字段，不应为新UI凭空新增或生成它们。正式实现“当前结果”可使用当前verification.summary或明确标注的最新记录摘录；没有则不展示。过去的求助不自动当作仍未解决的待办。平台/人工/模拟验证来源需要分别标明，不把工作完成、Agent候选或模拟accepted当作真实通过。

这是设计预览的可交互修订，尚未替换正式应用。截图新增 `canvas-default.png`、`canvas-agent.png`、`canvas-agent-wide.png`、`canvas-challenge.png`。检查新增默认关闭、指针拉伸、键盘拉伸、题目页签、证据预览、关闭与窄屏返回画布，全部通过；数据继续为明确标记的示例，不连接真实任务。
