# P5c · AgentGateway 原生保存确认与恢复报告

## 完成内容

P5c.1 排查原生 Provider 保存报错。现场 Provider 已存在于原生存储，原请求标识同时出现在原生滚动注解和两个消费者的维护保护中。旧入口没有记录失败阶段，不能追溯究竟是哪一次确认失败，也不把原生对象存在当作旧页面收到成功回执的证据。

P5c.2 修复现有管理入口的保存确认。原生写入和滚动仍各最多一次。已确认滚动之后，仅对短暂不可达、暂未同步或新资源尚未读到等情况，在同一 20 秒窗口内重试只读检查；只有原生同步并且保存回执与资源标识、版本、值和创建时间一致，才释放两站原请求。认证、无效响应和资源冲突立即保留保护。未知写入或滚动不重发。保留阶段、原因和请求标识，避免将配置值、凭据或底层报文写入日志。

P5c.3 本地现有入口已更新。恢复前确认旧请求处理已退出、原两站空闲保护和代次一致，并在原网关、原存储卷上重复比对当前同步配置。以未变化的现有原生配置为基准，两站均确认释放同一个旧请求，数据库回执均已持久化。保留已有的 1 个 Provider；没有重发保存、改动用户配置或请求推理。旧请求的原回执仍无法确认。

## 如何验证

- 运行 `pytest -q deploy/agentgateway/test_admin_ui_proxy.py`：9 项通过。包括短暂连接失败、同步迟滞、缺失后补齐、持续不可达、认证拒绝、无效写入或读取回执、资源冲突、未知原生写入与滚动；核对唯一写入、唯一滚动、两站释放标识及日志不含配置值。
- 运行 `make check`：Ruff、Pyright（0 错误）、5 项 Pi 测试及 2,568 项 Python 测试通过，487 项非本次常规范围测试未运行。入口测试不在默认收集范围，已单独执行。
- 用固定原生 AgentGateway、独立 SQLite 存储及合成 Provider 走实际 Provider 保存 API。在同一存储重启后注入首次读取失败：旧入口返回 503，两个测试保护仍在；新入口返回 200，两个测试保护均释放。两边均只有一次 PUT、一次原生重启，持久资源版本均为 1。新入口只增加只读请求。测试用隔离消费者回执，未发送真实推理。[实际固定版对照回执](../../.data/p5c-agentgateway-save-20261109/docker-real-provider-readback-proof.json)。
- [本地原生管理入口](http://localhost:15815/ui/llm/providers)保留原有登录和中文界面，实际只替换管理入口镜像。两站同请求释放均获 HTTP 应答及数据库确认，原配置摘要、网关和存储身份不变。[现场恢复回执](../../.data/p5c-agentgateway-save-20261109/live-p5c-recovery-receipt.json)，SHA-256 `4a6d66fef275a3c1c9e43fa8ea7eb61d783286bcf46cb2ad2673f417c6ea89bc`。

## 偏差与待决

- 切换入口镜像后的第一次现场只读探测遇到本地转发过渡期 HTTP 502，按原条件回退，未释放保护。第二次仅在部署验证工具增加有界只读等待，入口稳定后完成恢复；产品源与固定版对照一致，未改原生配置。

- 当前修复仅针对已经确认同存储滚动后，运行时和资源读回的一过性失败。未知 Kubernetes 滚动或消费者释放回执仍保留保护；必要时按实际证据恢复，不将未确认写入改为成功。
- 不改动 AgentGateway 原生配置单源、平台模型选择、费用预算、虚拟 API 密钥或中文界面；未联系真实上游服务，不能确认实际提供商密钥及推理能力。
