# 任务 M5 · 评估与调参

依据：`docs/design/黑板系统开发方案.md` 第 7.2 节（评分、运行方式、判断标准）、M5；`eval/answers/mini-shop/answer.yaml`；`eval/runner/README.md`。

前置：M3b 与 EVAL-2 已合并。先阅读 `AGENTS.md`。

## 范围

`eval/runner/`：批量运行、评分、对比报告；单 Agent 基线配置。实际的评估运行（调用 DeepSeek、耗时耗钱）由用户执行。

## 已定的实现决定

1. **基线配置**：新增 profile `profiles/single/`（与 default 相同，但参数中 `derive_enabled: false`），任务预算 `max_concurrent_agents=1`。`derive_enabled` 是新增参数（默认 true）：需要在 `Params`、设计文档第 9 节与调度器 `decide()` 中同步增加（为 false 时 5.4 的 derive 触发不生效，探索停下来后直接走裁定与终结收尾）。**先改设计文档，再改代码。**
2. **运行器**：`python -m eval.runner.run --task mini-shop-review --profile default|single --n 5 --out eval/results/<时间戳>/`：通过 blackboard 接口创建任务、启动、等待 finished / failed（带超时），导出每次运行的报告、最终黑板（事实、意图、验收状态）、用量与耗时。
3. **评分**：`python -m eval.runner.score <结果目录>`：
   - 把报告与黑板中的事实（优先带 `satisfies` 与 tool_backed 证据的）与 `answer.yaml` 的 P1–P6 匹配：先按文件与函数名、关键词自动匹配，输出"自动匹配结果 + 需人工复核的条目"。
   - "找到"= 定位（文件与函数）、机制、可复现证据三项齐全计 1；只有定位和机制计 0.5。
   - 指标：召回率、精确率（报告 D1–D3 必为误报；植入列表之外的发现标为待人工复核）、证据可复现率（在全新执行环境中重跑报告里的复现脚本）、接口覆盖、耗时、金额与缓存命中率、争议数、satisfies 命中率、裁定次数、Agent 结束原因分布。
4. **对比报告**：Markdown，多 Agent 与单 Agent 各指标的平均值与最差一次，并按开发方案 7.2 的判断标准给出结论。
