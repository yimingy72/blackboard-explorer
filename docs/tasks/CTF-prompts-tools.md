# CTF-prompts-tools · 系统提示与协作工具

用户于 2026-10-11 要求继续优化系统提示和工具。沿用 CTF-cooperation 工作树与分支，保留上一轮已部署但未提交的调度改动；本轮不混入 ui-rebuild 前端改动。

## 范围与依据

- Lead/teammate 系统模板：按当前消息与 Session 的信息缺口读取记录，明确独立工作并行、及时共享、已有成员续接、最终回答与结果通知的关系，合并重复说明。
- 工具反馈：结构化 JSON、可安全呈现的 CAS 冲突及参数提示；保留未知错误、停止/权限/代次/预算控制，不开启全局原始异常回显，不自动重试写入。
- 工具 schema/说明：与服务端状态枚举、revision、action 参数组合、登记产物和求助权限一致。
- 记录/题目分页落到数据库；记录可按版本增量读取，旧参数、返回形状、排序、作用域和完整历史读取保持兼容。
- 依赖 `CTF-team-mode`、`CTF-cooperation` 报告及 `docs/proposals/CTF-team-mode-design.md` 第 6、7、11、13 节。提示词仅优化通用协作流程，不加入任何特定靶场攻略、命令或答案；角色、验证、必要文件、单 Session 写者与收尾规则保持。

主会话审查整合；GPT-6.1 Sol high 子代理分别实施提示词、工具反馈和数据库分页，避免共改文件。采用原生 MAF 脚本化模型、随机端口数据库及普通/集成检查验证；不调用真实模型，不操作靶机，不读取/修改 .env，不新增依赖/迁移，不修改 docs/design。

如本地检查通过，以原平台 Worker API 更新两角色提示词，核对保留模型、价格、工具启用、资源及其他配置；已有任务的固定快照和 Session 不改写。写中文报告说明实际检查、效果边界、部署/配置变化及建议提交划分。
