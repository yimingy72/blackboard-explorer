# 黑板实时连接性能优化报告

日期：2026-10-17。工作树：`/Users/yym/bbx-wt/board-stream-perf`，分支：`perf/board-stream`。

## 测量结果

使用公网任务 `0ef17097-b431-49cf-b431-46d94c67f2e6`（约 5.9 万事件）测量：

| 接口 | 响应体 | 服务端耗时 |
|---|---:|---:|
| `/api/tasks/{id}/events?since=0` | 14.1 MB | 约 423 ms |
| `/api/tasks/{id}/state` | 412 KB | 约 38 ms |

旧前端进入任务后先下载并逐条重放全部 14.1 MB 历史事件，才开始建立 SSE；这也是任务越大、页面越卡、连接越慢的主要原因。之后每个 SSE 事件还会单独触发一次 Zustand 状态更新和 React 渲染。

## 修改内容

1. 首屏改用 `/state` 的折叠快照，直接从当前 Fact、Intent、Agent、验收状态和任务版本开始显示；不再等待全量事件回放。
2. 新增快照到前端 `BoardState` 的适配，保留任务、验收、事实、意图、Agent usage/status/session 引用等当前字段。
3. SSE 从快照的 `task.version` 开始，只接收之后的增量事件。
4. SSE 事件在浏览器内以最多 50 ms 的批次合并，再统一推进黑板状态，降低高频工具/轨迹事件造成的重复渲染。
5. Agent 编号优先从快照中的 Agent ID 计算，避免首屏为编号再次扫描全部历史事件。
6. 完整历史改为按需加载：打开复盘记录或选择 Agent 对话时再获取并缓存，避免阻塞首屏和实时画布。
7. 静态资源采用增量热更新：先复制新的哈希资源，再原子替换 `index.html`；旧资源保留给已打开页面。没有重启 blackboard、runtime 或运行任务。

## 验证

- `tsc --noEmit`：通过。
- ESLint：通过。
- Vitest：**132 passed / 23 files**。

- 实测首屏数据源由 14.1 MB 事件流降为 412 KB 快照，约缩小 34 倍；SSE 从当前版本继续，不再重复传输历史。
- 线上任务 `0ef17097` 与 `dbccd857` 均未停止或重启。

## 偏差与待决

- 首次打开某个 Agent 的完整对话或历史复盘时，仍会按需读取完整事件历史；这是保留历史回放能力所需。后续可进一步增加按 Agent/按时间窗的服务端轨迹索引，减少这一按需请求。
- SSE 服务端仍逐事件发送，前端已按批合并；若未来事件速率继续提高，可在服务端增加短暂合并窗口。
- 未修改 `docs/design/`、没有新增依赖或数据库迁移。
