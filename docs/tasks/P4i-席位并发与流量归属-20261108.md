# P4i：席位并发与逐 Agent 流量归属

已审实施方案，基于 `51c798c`。沿用 [平台架构重构方案](平台架构重构开发方案-20261105.md) §5、8–10、12、15、[P1 执行接缝](P1-执行接缝验证-20261106-report.md)、P3h 和 P4a–h。GPT-6.1 Sol high 开发，先完成独立审核再按本方案实施。

## 1. 交付边界

- 用真实 PostgreSQL 事务验证一个 Task 的 20 个可占用席位：18 个主 Worker 与两个不同原父的 helper 同时有效，Lead 独立计；满位即时拒借，主 ready 工作优先取得下一个可用席位，清理未确认不重用。没有把 20 席位说成 20 个真实模型、重型命令或 Pod 同时运行。
- 新原生 Task 冻结启用逐 binding 采集 profile，真实 Lead、Worker、helper 都用可信独立 netns/veth/IPv4 到达同一隔离目标；以原物理采集源绑定原 Agent、角色、父 Agent（如有）、binding、Assignment、generation、epoch、Sandbox Pod UID/执行上下文和 netns inode。席位再借用时新网络源与旧历史独立。旧 Task/共享 `worker-a` profile 不热改，不在界面上冒充逐 Agent。
- 本片最小网络面为 Task 的已核数值 IPv4 TCP 隔离目标，采集原 root veth 在 SNAT 前实际越过接口的包。原始包只做原网络作用域归属；不能用包证据推断同作用域的 command_id、目标收到请求、未观察到的协议或其他 Agent。复用原流量只读入口、原生 PCAP 解析/查看与已有 Task 访问控制。不增加命令审查、处置或审批。本片不扩真实来源/VPN、DNS/TLS 解密、IPv6、eBPF/全连接覆盖、跨宿主 daemon、HA 或 P5 全产品。

## 2. 20 席位事务及原 32 上限

复用 `NativeWorkers.reconcile/idle_members/_assign/_drain`、`NativeHelpers.reserve/_release` 和现有 Task advisory lock。主 Worker、helper（含 draining）及空位是相斥的同一批 `ctf_members`；主任务和 helper 取席位、绑定、generation、写唤醒同事务。真实 PostgreSQL 用独立并发连接/启动屏障发起原生调度及不同父的借位，核对无双领或双唤醒，而非直接向 active map 填 20 行。现有健康 helper 不因后来出现 ready 主任务被抢占，优先级只决定下一个空席。

必要场景先实际发出 18 个主 Assignment，两个独立原父用真实准入借完 2 席；并发重复或额外借位不能超限。再登记一个独立 ready 工作，在满位、旧子或主 Worker 未清期间不转让；收到原 SDK/命令/网络的各自正证后，同一席位只转给 ready 主工作一次，使用新 binding/generation。验证旧 permit、迟到通知和旧网络证据不会影响新席位。只让必要父/子走合成 SDK 回执，其他槽验证持久事务。

P4f 的 **32 是同一原 epoch 全部历史 binding 的恢复 manifest 上限，不是并发席位**。本轮不把健康主派工额外硬限到 32，也不扩 P4f 恢复协议。沿用 helper 达 32 拒新增；PG 核一条 32 边界且主规则不变、超过上限的既有恢复明确阻断。逐 binding 网络源额度与 32 分开，达到本 profile 有界额度报告容量不足，拒绝无归属新执行，旧 Task 保留原合同。

## 3. 网络来源、采集、归档

1. 在 BB 的原 Task 锁下，只为新 profile 当前 binding 的首个 `exec_command` 登记不可变网络作用域及一次创建意图。受信快照含 Task/epoch/binding/Assignment/generation、角色及原 Sandbox/Runner host UID 和执行上下文。每个 Sandbox incarnation 用有界单调序号分配唯一 netns/veth 和一对 IPv4 地址，不在原 Sandbox 内复用地址或命名；用该 Sandbox 独立的保留 IPv4 地址池按 /30 单调分配；源数量上限不超过现有每 run 256 个 native source，独立于 32 的恢复门槛。原业务 binding/Assignment hash 不在首次调用后改写。新 profile 所有 `exec_command` 都走同一 gate，不按文本猜测网络需求或提供绕过。只有官方低权限文件工具不创建网络作用域。重复同源查证原结果；已领取、响应缺失或资源 UID 替换不二次创建、不凭 404 认未创建。待收尾按原网络记录独立枚举，不能只依赖已生成 SDK execution_id 的命令行。
2. 原 trusted Sandbox Host 经已绑定的官方 execd 固定 argv 请求 root 管理入口。复用 P1/G1 能力下降、地址/入口校验、根 INPUT 拒绝控制面和 FORWARD 约束；不从模型参数或可写工作区取名称、IP、接口或凭据。root-private 记录保护真实 netns inode、host veth ifindex、capture PID/start ticks、原执行上下文。新 scope 默认不转发；抓包确认已监听原接口后才开启冻结的数值 IPv4/TCP 目标白名单，禁止控制面和跨 Agent 链路。发命令前再核对接口与同一个原 scope、采集仍就绪、原 host/owner 仍有效。转发必须依赖单调内核时钟自动到期的原 scope grant：截止不晚于当前 BB owner、binding permit、helper 原父 binding permit 和子截止（如有）及原 Task 截止；双向逐包检查，不能只在建连时检查后对 established 包永久放行。采用实测 xt_recent 只读匹配、固定 7 秒内核窗口，叠加保守整秒 UTC 绝对上界，不允许流量自续。UTC ceiling 依赖可信节点时钟和已核保守偏差；单调窗口不因时钟回拨重新打开。可信 Host 先向原 Sandbox 读受保护的单调采样，再向 BB 领取每源严格递增的 grant_revision；授权包为 source_id、grant_revision、issued_at_ms、authority_until_ms（BB 两时刻差最多 12 秒，并受上述截止夹紧）。原 Sandbox 只在该授权剩余区间能覆盖自预采样起的实际耗时、7 秒和固定保守余量时续开，迟到、同号/旧号、原 capture 失效、关闭墓碑或写入不明均不能刷新；不从接收时点白送新 TTL。采集器与维护者一起失联时，旧 grant 自行到期并拒绝继续转发。以不晚于原截止且双向 established 都被截断的探针为门；`setns` 前核实际打开的 inode，对不匹配或非该 scope 拒绝。现有 `sdk_admitted` 原派发点在真就绪之后才允许官方 SDK 一次执行；旧 ABI 及旧 launcher scope 序列化保持兼容。Task 锁内只做意图和回执 CAS，创建、采集、传输和对象读回都在锁外。
3. 首片每个源只采集一份有界、不可覆盖的 dumpcap 输出的 classic Ethernet PCAP 段：snaplen 512 字节、至多 7943 包（文件头及逐包开销计入 4 MiB 上限）。截断明确显示，不称完整 payload。root-private spool 的保留额度独立于历史源数量：启动前保留 4 MiB，每原 Sandbox 最多占用 96 MiB；同源 ACK 且本地字节清除后才还额度，积压满则拒绝新作用域。文件工具/用户命令不能伪造内容或来源。首片新 profile 只采用 required 采集；达到大小/时限上限或采集器故障时，关闭该 scope 的转发及新执行并保存明确缺口，不静默切 best effort。采集收尾核对同一原进程的退出/刷盘，独立核验段长度、SHA-256 和完整 PCAP 包数；`complete` 只表示原 veth 的本段观察边界有正证，需已核截流、正常刷盘及匹配计数、无内核丢包。合法头部的空段、强制截断、尾部可分离的损失及缺计数按覆盖证据如实标记；无有效头或损坏完整记录不能当成可核封存。未确认原段不虚构零包 source ref。不同 sandbox/epoch/source 永不混成一个索引。
4. 复用现有 `TrafficNativePart/SourceIndex/SourceRef`、`traffic/{task}/run-{n}/native/…` 的对象格式与既有 PCAP parser，不重建 envd 或给 Solver 对象存储凭据。可信 Host 通过原 report capability 登记原 scope 的 sealed 段（长度、包数、摘要及覆盖状态），再提交有界的原始字节；准备就绪和归档分别确认。BB 核 Task/run/scope/原 host 与固定 digest；先写并读回内容寻址的 part 和 index，最后短事务落原 `SourceRef` 确认。重复只接受同源同摘要，读回前不 ACK、不删本地源。**新 profile 的 manifest 从已确认 scope 记录只读投影**，不让多个上传并行覆盖对象 manifest；legacy collector 只写旧档案路径合同。旧档案读取、权限和存储对象不改。
5. `TrafficNativeSourceRef/Index` 可选新增 immutable scope 元信息；查看时同时核 Task/run/原 scope 一致，旧索引和源引用不新增序列化 `scope:null`，保留原对象字节和索引摘要。展示和查询可按原 binding/source 精确筛选，同一成员编号复用时显示原 generation/epoch/角色。复用 TrafficDrawer/PacketInspector 及受控读取/下载；native-only 源在现视图能打开默认查询，不能因无 legacy preview 就显示“没有流量”。公开作用域不携带原执行上下文 nonce、host 凭据或 root 文件路径；这些仅用于可信对账。只读 UI 不展示未证命令归属，不新增审批、编辑、写流量入口给用户。

### 可信窄接口

- 在现有 Sandbox Host `claim` 回执中为新 profile 附原计划 scope（独立于旧 AssignmentBinding v1 字节）：source_id、原 binding、Sandbox incarnation、root/peer 接口和计划 IPv4、固定目标清单与一次创建领取。旧 profile 不附字段。只有确切的原 `observe ready` 回执可以登记同源的实际 inode/ifindex、采集 PID/start ticks 与就绪证据；`sdk_admitted` 复核原 scope。真实创建或授权未确认时，不向模型派发命令。
- Host 按原 source 调 `permit`，只有可信原 Host 能在当前 Task/owner/binding permit 下取得上述短 grant。关停与待归档按原网络记录枚举，`seal` 回执绑定该同源的最终退出、覆盖、段长、包数和 SHA-256，再用原身份上传 bounded PCAP。源已关闭仍可核已有迟证，不能再开 grant 或更换来源。模型没有这些控制入口。

## 4. 停止、暂停、恢复和删除

- **普通停止**：先持久撤执行准入并请求原 host 停转发、收尾和封存。Runtime 对原 Sandbox 的预封存等待有一个不可续长的截止：第一次持久 stop 的时间 +20 秒，与原 Task 硬截止取较早；仅短轮询确认，不等待对象上传协程。硬截止已到、原对象实际丢失或预封存超时，沿既有正证终止路径继续，不把采集等待变成新的硬停条件。BB 的对象写入在独立请求/归档锁，不在 Task 锁或 Runtime 唯一 stop 协程中；`ObjectStore.put` 的 shield 只保该写入源/归档锁至实际返回，不阻塞 kill。已经读回确认的原段保留，缺失部分标 partial/unknown。
- **运行中席位及暂停**：只有原 scope 明确从未领取，或核到同一个 scope 停转、命令/cgroup 和捕获进程退出，且 sealed 段按原摘要已读回归档，才通过独立网络收尾条件；可复用 `close_proven`。明确掉包、截断或采集限额是 **known partial**，正证封存的原段及明确缺口都保存，满足原终止和读回时可以释放原席位或结束暂停。缺创建/退出/flush/字节证明、对象写结果未知或无正证的 404 是 **unknown**，不释放仍运行 Task 的原席位、不结束暂停。续跑产生新的 binding/source，不重新使用旧地址或旧抓包来源。
- **跨 epoch**：P4f 冻结捕获原 scope；恢复不是显式停止，旧 Host 可达时先查原归档前置，不能先销毁仍可读原数据再以归档未知阻断。精确物理退出只证明原执行已停止，不能合成原采集。已归档的 known partial 可以参与既有恢复前置，原 scope/归档 unknown 仍阻断 required profile 的恢复；旧卷/归档保留。迟到可信证据仅在其原不可变身份/已登记的段上对账，不附到新 epoch，不推断未知原效果。
- **删除与迟写**：BB 同 Task 使用独立归档互斥键（与控制 Task 锁分开）；覆盖存储写入/读回以及同 Task purge。原封存和对象写意图在短事务登记固定键/摘要及领取状态；持归档键后再短事务核未关写与原 scope，外部 I/O 不持 Task 锁。写入账依次为 claimed、put_confirmed、verified：只有领取原写的协程收到对象 PUT 成功回执才持久确认写入终结，随后读回原摘要；仅 GET 同字节不会清除 claimed。缺 ACK、进程/锁缺失或 TTL 到期不算最终证明。原退役正证后，purge 先在短 Task 事务关闭新写，再查归档键及原领取账：仍有实际写入或领取结果未知返回可重试的待清理状态，不能在 `put` shield 未结束时清前缀，也不能仅凭迟到回执 CAS 被拒绝就删除。关写后只接收既有写入的原终态证据、不允许二次 PUT 或新投影。取得归档键、核无在途写后才清已登记确定键/原前缀；Task 消失不可能重建 manifest。原物理退出明确、采集有损但写入账均有最终证明时可按原显式删除；不说成完整归档。本片不增加主动确认丢失、强行清未知写入的产品流程；既有原命令、费用等独立清理门槛不放宽。
- 不加采集 PVC 或自动 HA。原 Sandbox root 控制区中尚未封存字节只在原对象可达时可保全。主流程不凭进程缺失或计时器捏造覆盖，不把显式 Task 终止与采集证据的完整度合并。

## 5. 预计路径与必要验证

| 落点 | 最小改动 |
| --- | --- |
| `native_worker_dispatch.py`、`native_helpers.py`、PG 现有测试 | 复用 Task 锁和席位入口；只补真实并发发现的缺口和独立旧网络收尾 gate |

| `bbx_blackboard/{traffic,native,native_api}.py` 与共享 `bbx_contracts.traffic` | 有界原段写入/已确认 manifest 投影、原 source 作用域、现查询/详情授权；不另起产品流量服务 |
| `services/sandbox-execution/launcher`、`bbx_runtime/{sandbox_mcp,runner_resources,native_runner}.py` | 同源隔离、严格固定控制操作、真实有界 capture/flush/导出，沿现原 Sandbox host 和停止路径 |

必要测试：一条真实 PG 20 席位模拟及旧 32 边界；一条归档定向故障/权限验证（摘要冲突、跨 source/Task/epoch 拒绝、不可确认不 ACK、同成员号旧新 scope 可分、失败保留）；一条隔离本地 Kubernetes Task，用脚本假模型让 Lead、两个 Worker 和一个 helper 按阶段/重叠访问同一受控数值目标，并复用一个已清理席位，验证真实不同 veth/IP/捕获源、归属存储读回、旧源未串、新旧只读查看、原控制面和跨 Agent 直达拒绝及停止保全。PG 模拟不用 20 个真实模型。Native decoder 仅 Linux；计划用现有带 sharkd 的 Linux BB/worker 临时夹具验证原已归档数据的授权 query、packets、detail 和 scope 一致性（`native.py::_source_index`）。Mac 的 503、对象摘要读回或离线 tcpdump 都不算该查看链通过；若未能运行 Linux 查询，报告只到可读归档已核，不宣称只读查看实证。仅必要的已有暂停/恢复/退役定向回归，不扩 20 个真实模型、VPN、外部来源、daemon 或 HA。最终干净候选 `make check` 和生成合同检查；不调用真实模型或靶场。
