已审实施方案，基线 `eae0477`。沿用 [平台架构重构方案](平台架构重构开发方案-20261105.md)、[P4i 已证流量链](P4i-席位并发与流量归属-20261108-report.md) 和 P1 原 Kali 镜像接缝。本片只补可使用的创建入口、正式部署配置和原镜像接入，不增加命令审查或处置。

1. **专用部署**：现有 legacy 和原生 Runtime 共用 PostgreSQL 实例锁。本片不改锁或宣称两者在同一部署混跑。默认无发布文件，现有创建/启动/恢复保持原合同。管理员显式配置专用 native CTF 部署，部署前收尾原有可执行任务；该部署只开放新的原生 CTF 创建，并明确拒绝旧任务重新启动或恢复。已有历史、流量及命令记录继续只读可查。缺失/错误的发布配置不降级创建另一种任务。
2. **发布和冻结**：只读的管理员部署文件发布一个环境的 ID/修订/名称、确切 CTF profile 版本、现有平台模型版本与网关 alias、可信 FX 以及完整 Runtime 资源配置。服务器校验固定 profile、镜像不可变身份、目标 namespace 和规范 IPv4 TCP 端口（与 Runtime 同一验证器）及预算可表示性。对用户仅公开创建模式、名称/修订、可用模型 ID/版本；不公开 endpoint、镜像、目标地址、FX 或任何密钥。版本戳同时绑定完整已发布配置，避免复用人工版本号接受旧表单。浏览器只提交环境引用、模型和原已有输入组；原用户域名备注不转为网络授权。单一发布能力非环境注册中心，不在界面提供任意目标、镜像、汇率或运行设置的编辑。Runtime claim 在创建任何外部资源前核对冻结的配置摘要，后续继续受原不可变配置和恢复约束。专用部署的实际就绪由发布验收验证；配置页只说明发布状态。
3. **公开创建**：沿原 `POST /api/tasks`。原生 CTF 固定自动派工和 1–20 席，首片仅接管理员明确发布的现有 CTF profile/模型版本，无额外推理覆盖或附件。使用本人空输入组做幂等，不把附件静默丢弃或宣称已物化。在已有 Task、输入组及创建事件事务内同时插入原生启动意图；不走 legacy provision，不允许浏览器访问私有启动。完全相同的重复请求按原 input owner/hash 返回原 Task 和原意图，不重读新发布、不重建预算；改环境或请求冲突。同一用户的普通旧请求保留原 input-group 摘要字节。
4. **现流量入口**：复用 P4i Task 流量查看器、按来源筛选、授权解析和原始 PCAP 下载；配置有效的原生 Task 在尚无来源时显示等待封存。首片仍限可信隔离目标的数值 IPv4 TCP。无新 VPN/真实题目来源、附件物化、任意用户网络/镜像配置、全站改造或 20 个重型会话的并发承诺。命令记录只读。
5. **原镜像**：原有 P1 Kali 工具层为 `bbx-exec-env-kali@sha256:c79ded7b50e9a7ea2433e9740c48417ce08601948196ec497ad403c779da58ae`；P4i 实际采集基于隔离的 Ubuntu 工具镜像。交付可重现的只读来源核验、构建和接入指南，优先使用精确原制品；找不到时可按原工具配方重建新版本，记录基础层及配方摘要、差异和新制品 digest，不冒充原制品。管理员放行须有绑定来源、派生镜像、模型映射及网关目录的实际验收回执；独立 Ubuntu 假模型 fixture 只可验证产品接缝，测试发布不在正常进程启用。

## 管理员发布示例

普通部署保持 `NATIVE_CTF_PUBLICATION_FILE` 未设置。专用部署先准备原生 Runtime、对象存储、平台模型版本和已验证的捕获镜像；管理员把下列配置与同目录验收文件以只读方式挂到 Blackboard，确认已启动的原生 Runtime 使用对应配置，才设置 `NATIVE_CTF_PUBLICATION_FILE=/etc/blackboard/native-ctf-publication.json`。以下为字段示例，尖括号为必须替换的私有引用或值，不能直接启用：

```json
{
  "id": "isolated-ctf",
  "revision": 1,
  "label": "隔离 CTF",
  "release": "verified",
  "ctf_profile_version": 1,
  "model": {"id": "<平台模型>", "version": 1, "gateway_alias": "<已验收网关别名>"},
  "exchange_rate": {
    "rate_cny_per_usd": "<已批准汇率>",
    "source_ref": "<可信来源>",
    "observed_at": "<带时区的观测时间>"
  },
  "runtime_resource_config": {"<替换为完整生效配置>": null},
  "acceptance": {"file": "capture-acceptance.json", "sha256": "<文件原始 SHA-256>"}
}
```

`runtime_resource_config` 复制 Runtime 的完整实际 claim 配置：取 `RUNNER_RESOURCE_CONFIG_FILE` 内容，去掉仅用于退役的 `retirement_single_apiserver`，加入去除尾部斜杠的 `runner_blackboard_url`、`runner_model_proxy_url`。验收文件使用同一派生镜像、平台模型版本/alias、网关目录修订和原/重建工具层 digest；重建额外记录配方摘要。环境目标地址和内部资源配置均不从浏览器输入。普通启动不接受 `test_only`。

验收 JSON 字段为 `schema_version: 1`、`base_source`（`original` 或 `reconstructed`）、`base_tool_image`、`traffic_sandbox_image`、`catalog_revision`、与发布文件相同的 `model` 和 `public_create_and_archive: true`；重建时还要求 `recipe_sha256`。这是管理员根据实际验证发布的私有回执，加载器核对摘要和身份，不自动把文件声明当成集群当前就绪。
