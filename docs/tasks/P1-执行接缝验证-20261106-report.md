## 3. 实际验证

在本机 Docker 29.7.2 / linux-amd64 执行。隔离容器使用 testcontainers、随机 loopback 主机端口、`bbx-archv2-` 名称；1 CPU、1 GiB 内存、256 PID 上限。只有明确 `SYS_ADMIN/NET_ADMIN` 能力例外和测试所需 AppArmor 设置，未启用 privileged；没有安装集群组件、修改 CNI 或连接现有平台。

初轮普通测试 **2 passed / 5 deselected**、真实容器场景 **5 passed / 2 deselected**；追加代理损坏配置拒绝、文件 worker 能力断言后，受影响两个场景 **2 passed / 5 deselected**。

独立审核修复后，ruff format/lint 全通过、pyright **0 errors / 0 warnings**；普通测试（新增前/后台干净 EOF 和乱序前缀）**5 passed / 5 deselected**；只重跑受影响的真实前台与后台场景，**2 passed / 8 deselected**。未重跑无关的网络/能力场景或根仓库全量检查。

| 场景 | 实际断言与结果 |
| --- | --- |
| 前台身份与环境 | UID/GID=10000，supplementary groups 清空；basic 的 CapEff/CapBnd=0、NNP=1。控制 Token、EXECD_ENVS、测试控制标记与加载/解释器变量均不进入 Solver 环境 |
| 控制启动 | 恶意 LD_PRELOAD/BASH_ENV 在静态控制启动前被移除；官方初始化探针也不会加载测试 poison。空 Token 启动与连接检查都拒绝，不触发官方空令牌兼容放行；Token 不在 execd argv 中 |
| FD 与 exec | 可信父进程故意传入可继承 root 文件 FD 9，Solver 中不可见；普通 UID 直接调用启动器返回拒绝。launcher 证据 PID=实际后台 Bash $$=PGID，start_ticks 与 netns inode 有值，execution ID 对应原 command_id |
| 前台结果与输出 | 管道/脚本实际运行，非零退出 7 保留匹配的明确 error.exit_code=7，即使官方没有 execution_complete 也为已知终态。100000 字节以上的 SDK 文本全部入证据库，skip_accumulation 保持结果列表为空，预览固定 65536 字节并标 truncated；不宣称原始二进制输出完整 |
| 共同文件身份 | 二进制（包含 NUL/非 UTF-8 字节）读写一致、两 Worker 互读共享文件，实际 owner/group=10000:10000；root 控制区、只读启动器和符号链接指向控制文件访问失败；特殊 mode 被拒绝 |
| 后台与取消 | 官方后台状态/日志关联原 execution ID；“你好”＋非法 UTF-8 字节的 source cursor 是 9，SDK 文本重编码为 11 字节也正常保存并标损失可能；从中文中间 cursor=1 拉取同样保留观察。重复从 0 拉取不重复计算来源字节；不宣称 raw 完整。官方 interrupt 后核验原父、子 PID 均从 /proc 消失，启动 ack、取消受理和实际停止分开保存 |
| 代次与未知 | 其他 generation 不能读取/取消原绑定命令；同 invocation 不能再执行。仅传输不确定性使用脚本化 transport：ReadError 与 init＋部分 stdout 后干净 EOF 都保留 unknown；EOF 的原 execution ID 和输出仍在。关闭重开库仍拒绝重派，同 ID 换输入拒绝，派发计数为 1 |
| 乱序输出投影 | 先保存 [5,10) 的 fghij，显示 [0,5) 未收集；随后补 [0,10) 的 abcdefghij 并重复尾段，预览完整重建为 abcdefghij、来源字节只计 10，先前缺口被补齐。source cursor 不由文本重编码推导 |
| 归属与采集 | 两 Worker＋helper 同时访问同一隔离目标，代理记录的 Agent、Assignment、network_identity 和真实源 IP 一致；每个 veth 的 PCAP 含本成员地址。不把共享代理后端连接的包冒充逐命令精确归属 |
| 控制面与代理 | 冒用另一来源的有效口令拒绝；在 `0.0.0.0/0` 与 `::/0` allow 下，实际根网关、容器 Pod IP、loopback、unspecified、IPv4-mapped IPv6 控制地址仍为 403；HTTP 重定向至控制端口拒绝；损坏 grant 配置失败关闭。Solver 直接连接网关/Pod IP/IPv6/本地 loopback 的 execd 失败；可信宿主缺失或错误 Token 得到 401 |
| FORWARD 与 NET_RAW | 普通直接 TCP 经 FORWARD 到隔离目标可用；受信 net-raw 档 CapEff/Prm/Bnd 仅 0x2000，NNP=1，本地 raw ICMP echo 收到目标回包。basic 不可创建 raw socket；两档都不能 setuid(0) 或以 NET_ADMIN 建链路。文件 worker UID10000，effective/permitted/inheritable/ambient 能力均为零 |

## 4. 偏差与待决

1. 实测发现污染 execd 启动环境会早于命令启动器影响其探针，因此补了同一静态二进制的固定 `--execd` 启动模式。它拒绝空 Token，并在 daemon 之前清理控制环境；Kubernetes 官方 bootstrap/注入链必须保留同等保护，尚未验证最终 Pod 装配。
2. 官方 owner/group 参数解析账号名，不把数字字符串当 UID；固定使用镜像中的 `bbx-solver`。读取 `/proc/self/status` 的通用下载遇到 seeker 限制，使用官方已有 offset/limit 按行接口验证文件 worker，无 root 退路。
3. 代理扩展只开放数值 IP HTTP。主机名失败关闭；完整 DNS、TLS/CONNECT、连接池跨身份与 IPv6 正常业务仍待 G1。这里不是可直接发布的通用网络代理。
4. 本轮没有部署 Server、Controller、Ingress、Namespace/Tenant、任务卷或 Kubernetes/Cilium。未验证 G2 跨 Task/租户/Pod IP/卷拒绝、创建回执丢失、Pod 替换、停止留卷/归档；均维持未验证。
5. Runner 单 VPN、内部三层隧道、可信 Lead 提交出口及凭据边界没有改动或测试。未增加第二 VPN，不在 Solver 内终止 VPN；未启用官方 Egress。
6. 命令下发登记与可选进程观察分开：本包进程观察 `disabled`。未核验 execd-ebpf/BTF/轮转和丢失，PCAP 只是局部样本，没有永久 sealed-chunk 上传或完整性承诺。取消证明仅覆盖测试中的同进程组父子；setsid/detached 等残留的冻结与排空仍属 G1/G5。
7. 这批证明不是完整 G1 或发布许可。实时 epoch 撤权、网络身份代次回收、共享平台调用账本、命令/流量归档配额、拒绝调用投影和产品 UI 均在后续阶段；不能把 P1 本机 SQLite 变为另一套业务权威。
8. 官方 SDK 命令日志公开接口返回解码文本；本轮没有私改 SDK 或另起下载通道。所有命令输出视图明确 raw_bytes_retained=false。非 UTF-8、字符中间游标或无法精确映射的重叠切片保留原文本观察与损失/缺口标记；不能把 base64 编码的 SDK 文本称为原始命令字节保全。文件二进制接口的字节保真与此是不同能力。
