# P6b · 独立 MCP 管理与双目标接入

基线 `4ac69dcd0482fe103737d801871ac4ef365e13d6`。承接[已审 P6 方案](P6-Pi原生模型与MCP迁移-20261110.md)和 P6a；本段使用同一隔离候选与本地分支，不改现场、不改 P6a 模型和计费合同，不清除 AGW 工作负载或历史数据。

## P6b.1 平台可视化与外部 Server

- 复用平台账号及现有 PlatformCatalog，显示 Server 名称、公开 HTTPS 地址、版本、启用状态、认证方式/是否配置（不回显密钥）、连接测试结果。工具详情从真实 `tools/list` 读名称、说明、输入 schema、必填参数/类型/描述、可选输出 schema 和服务声明注解，显示该结果来自哪一版本；未测试、失败或过时明确展示。连接测试从平台侧发出；真正工具调用在普通可信 Runtime 或原生 Blackboard 业务宿主，界面分别标注网络，不能拿发现成功当执行证明。
- 主站现有加密 `platform_configs` 是唯一目录；只有 P6a 已配置的操作者可创建、编辑、探测和发布，普通用户与副站只能读授权范围内的版本。公开 HTTPS 由操作者保存即批准，不需为每个 Server 改部署。保留可选部署收窄；首期明确不支持私网、stdio、项目/用户任意扩展、自动执行或 OAuth 新流程。发现和真实发送都解析并固定实际公网连接地址，保留原 TLS/Host，拒绝重定向、任意 URL、控制面和元数据；换 origin 或认证头/机制不得静默复用原密钥。
- 外部运行角色为普通 Explore，以及原生 CTF 的 Lead、Worker（API 中为 `lead/teammate`）。连接测试不授予任何角色；平台操作者在发布时选择允许的角色和具体工具，普通 Worker 设置继续选择 Explore 工具，原生 CTF 创建页按 Lead、Worker 分别为本 Task 勾选明确工具与发布版本，默认均空。拒绝草稿、通配、越角色及停用 Server 的新授权。Helper、Derive、Close、只读复盘不获得新外部能力；历史 CTF 平台连接、旗标用途/适配规则不变。对新外部工具，平台验证 Task、角色和当前有效的 Worker Assignment；这不自动收窄任意上游参数或远端账户权限。操作者须使用受限上游账号和工具，服务声明的只读注解不构成安全授权。
- 运行时仅暴露冻结的名称、描述和参数，并核对实际工具 schema；服务后来增添或更改工具不自动授权。普通执行在可信 Runtime，发送前在原会话检查点锁定调用，同任务换 Agent/重启也不会重发未明确结果的外部调用，只有原返回证据和原调用一起落盘才能解除待确认。原生 CTF 执行在 Blackboard 私网业务 MCP host 的受信出站，详情分别标注连接测试、普通执行、原生执行网络。旧冻结版本只在旧已获准运行中读取；旧通用凭据接口不能取出新发布密钥。

### 外部 HTTP 合同

| 入口 | 行为 |
|---|---|
| 原 `GET/POST /api/platform/mcp-servers`、`POST /{name}` | 保留已有浏览与版本化保存；主站指定操作者才能写。副站用受信服务读取主站，不另写目录。保存只产生待测试配置，不授权工具；启用草稿保留上一个已发布版本及 `published_roles` 供选择。保存停用后禁止新授权和新任务冻结，已经冻结的任务仍读取原发布版本。 |
| `GET /api/platform/mcp-servers/capabilities` | `can_manage`、`external_roles:["explore","lead","teammate"]`、`discovery_network:"platform"`、`execution_network:"trusted-runtime"`、`native_execution_network:"blackboard-business-mcp"`、`private_supported:false`。 |
| 版本下 `POST /discover`、`GET /tools` | 前者仅操作者发真实 Streamable HTTP 测试，用官方 Python MCP SDK 完整有界分页，拒绝循环 cursor、重复工具名及超量/泄密元数据；后者只读已存预览或发布清单，不出站。结果含 `status:untested/ready/error`、`version`、`published`、精确发布 `roles`、`discovery_digest`、`checked_at`、脱敏错误和每项 `name/description/input_schema/output_schema?/annotations?/schema_digest`。 |
| 版本下 `POST /publish` | `{discovery_digest, tools:[明确名称], roles:["explore"|"lead"|"teammate", ...]}`；仅当前原版本且相同成功发现快照可发布，冻结所选完整工具与角色上限到一个新不可变版本。预览可更新，但不能改变已发布版本或 Task 原授权。 |
| `GET /api/runtime/mcp-servers/{name}/versions/{version}/material` | 只给已有专用可信 Runtime 身份取冻结已发布版本，副站从主站私有控制接口转取；普通登录、Agent、通用服务令牌不取得新版本明文。与内部 Task 能力完全分离。 |
| 原生 `POST /api/tasks` | 可选 `native_mcp:{lead?:[{name,version,allowed_tools}],teammate?:[...]}`，仅 direct-v2 新 Task。服务器读主站确切发布版本、核验角色和明确非空工具，冻结在 Task 资源记录中，保存目录 authority、Server revision、canonical alias、wire name、描述/schema/digest；不接受 Task 自带 URL、密钥、定义或任意目标。省略字段保持旧请求哈希、旧 Task 和原生环境发布合同。原生创建能力只在 direct-v2 可用时返回 `native_ctf.external_mcp:true`，其他环境不提供选择。 |

发现结果存现有平台控制存储，不新建通用注册服务。工具 `schema_digest` 对规范 JSON（UTF-8、键排序、无多余空白、无非有限值）的 `{input_schema,output_schema}` 取 SHA-256；不存在输出 schema 用 null，发布保存原结构。原连接凭据若出现在工具元数据，拒绝该预览，不展示或记录原文。测试失败、分页超界和元数据不可用不改变已授权工具。

## P6b.2 Native 双目标及身份

- 新版本在可信 Task/资源记录冻结 `mcp_transport:"direct-v2"`。RunnerBootstrap 的 `mcp_targets:{business?,sandbox?}` 与旧 `mcp_gateway_url` 互斥；SessionSpec 用 `mcp_target_credential_refs` 和 `mcp_tool_routes: canonical → {target,wire_name}`，目标与名称来自冻结授权，不能从模型请求中选。旧绑定缺该 discriminator 只走原旧路由，新的请求失败不回退。
- Pi 1.5 已有官方低层 `McpClient`、`StreamableHttpTransport`、`toLlmContent`，每目标一个连接；不另写 MCP 客户端，不引入通用 broker。官方高阶扩展可供标准会话使用，但本边界需要原工具调用 ID、`_meta`、可等待 journal/permit 和严格一次执行，不能用会丢失这些信息或自行重发的接法代替。
- Business 只走已验证的 Blackboard 私网 `/api/tasks/{id}/business-mcp-v2/`，Sandbox 走同 Pod `http://127.0.0.1:8766/mcp/`，各自新 issuer/audience 分别为 `bbx-runner-business-v2/business-mcp`、`bbx-runner-sandbox-v2/sandbox-mcp`。新旧入口在切换前就互斥验证，未过期的旧 `aud=mcp` 和跨目标令牌也拒绝，不能等 owner 换代。父 helper 管理动作由原业务控制能力授权，helper 自己只有 Sandbox。
- 初次 SDK 初始化、已初始化通知、工具列表只允许当前有效 binding/role/owner/epoch 且非空声明 SDK ID；已登记后必须精确匹配。尚未登记的首次读取不能升级为调用；`tools/call` 仍要求原持久 SDK/journal、稳定 invocation ID、冻结目标/参数、一次许可、真实结果/unknown。允许现有受控的 ping 和取消通知，不新增不明 SDK 方法；认证拒绝重复/冲突头、浏览器来源、跨目标或重定向。未知效果不重派，迟到原结果只对原证据。
- 原生外部调用复用 Business-v2 现有同一 Pi 连接，不添加第三目标、新通用代理或新 SDK。工具向模型使用有界 `mcp_<server>_<tool>_<digest>` 命名空间；canonical alias 由平台生成，冻结后检查冲突，不能覆盖内置工具。业务列表、准入和实际执行都核对 Task/当前角色/Assignment 的同一冻结条目；注册/重建只可重用原冻结授权，helper 不继承。
- 仅 Business-v2 的外部工具专用分支能以冻结条目读取精确版本的上游凭据，由已有官方 Python MCP 客户端和固定公网 HTTPS 连接调用一次。发送前按已核准 schema 校验参数；SDK initialize/list 只读取，校验实际工具 schema；请求只发所选上游认证和工具参数，绝不转发平台服务、Task 能力、journal、Sandbox 或 Runner 凭据。不支持远程 schema、任意上游、stdio、新路由或结果触发内部 Flag/任务写入。沿用原 `runner_calls` 的稳定 invocation ID/许可、结果与未知，单次认领和实际发送前的当前身份/许可复核均锁 Task；同一 Task 尚未确认的外部调用会阻挡其新外部派发，不能通过切换 Worker 或恢复代次绕过。校验阶段可证明未调用就保存清晰错误，真实 POST 后断开/未确认结果保留 unknown 并拒绝重发。返回前持久化原结果，密钥回显不返回、不落明文日志。
- Sandbox host 的冻结 `mcp_transport` 与任务一致，`POST /api/tasks/{id}/sandbox-host/authorize` 先以原报告凭据确认实际 host，再核 sandbox scope 及声明 SDK ID；仍用现有 catalog/claim/admit/result 执行。报告凭据、inbound、execd/VPN 等不进入 Runner。保护命令及各模式流量/旧抓包只读。direct 的新 Task 不创建旧 AGW MCP 路由，移除其新路径依赖；保留旧冻结任务清退/恢复的有限链，P6c 再停止旧部署，不提前删除数据。

## P6b.3 必要验收与分工

1. Core 负责 Blackboard 与共享合同/生成物、目标身份与权限、目录/发布、生命周期、PG 与报告。Runtime 负责 Pi 双目标、sidecar 及可信普通外部 MCP 接线、Web 和隔离实际 SDK 验收。独立审核检查每个发送/重放边界；当前范围同步 P6 迁移说明及实现架构；旧 CTF Profile、自动 Lead 本机命令禁用和旧 Flag 适配不作改写。
2. 一条隔离实际 SDK/PG 接缝覆盖 lead/teammate 业务和各自获准外部工具、helper 仅沙箱、首次 metadata、旧/交叉/过期凭据、未知不重发、暂停/换代或明确保全；断言 direct 无 AGW MCP 出站，原 P6a 模型仍工作。
3. 一个外部注册/真实合成 Server 场景覆盖操作员许可、连接失败/分页、schema、预览不能执行、发布显式工具后 Explore 与原生 Lead/Worker 各自通过、未授权角色/变更拒绝、密钥不外泄。Chromium 验证 Server 测试/工具详情/明确发布及原生新 Task 按角色选择。
4. 仅必要定向检查及提交前一次最终 `make check`；候选导入验证、无真实模型/现场改动。精确审核后提交本地既有 P6 分支，原工作区 104 项不动，不推送。
