# Direct-egress · 执行容器默认直接出网

来源：用户确认没有要求Ubuntu执行容器只能通过白名单代理访问公网。2026-09-26实际任务访问自建靶机时，旧默认配置产生`403 Filtered`；在普通Docker网络中，同一地址直接请求返回200。

依据：实现架构1.1、2.4、11；开发方案0、4、7、9；AGENTS.md。先同步设计，再修改代码。

## 范围和决定

- 新任务的执行容器默认接入有网关的`exec`网络，执行命令不注入HTTP(S)代理；运行时仍通过该网络访问每任务envd的内部接口。
- 保留现有代理隔离模式作为显式部署选项：选择该模式时`exec`必须是internal网络，envd通过egress-proxy访问白名单目标；网络模式不匹配时在创建容器前失败。
- 任务已有的egress_allowlist字段仅记录需求；默认直连模式不把它误称为访问控制。用户界面、API说明和部署文档同步。
- 不改Agent身份、证据权限、资源限制、MCP鉴权、调度和模型密钥边界；不修改.env或全局Docker配置。

## 完成标准

1. make check、make test-integration、web-check通过，不调用真实模型。
2. 新建容器在默认模式下不携带代理变量，能直接访问公开网络；代理模式仍只在internal网络成立。
3. 本机当前服务切到新配置，确认现有任务已归档、数据卷不删除；从新执行容器直接访问用户提供的靶机地址得到HTTP响应。
4. 中文报告写入Direct-egress-report.md；更新HANDOFF并按用户已授予的Git权限合入main。
