# P5d · AgentGateway 原生聊天演练场

基线：`3ffc6d0e79d72685e1b295714846459064400564`。保全原工作区 102 项（30 项已跟踪、72 项未跟踪）。用户决定先修入口，暂不创建测试密钥；以后单独配置的演练密钥不设额度。本轮现场不发送推理。

## 1. 根因

固定版 AgentGateway 1.7.0（`26f5aebe99a36a037fe54f8080a608aca5547e15`）原生聊天演练场的「应用 CORS」对 `/api/config/resources/llm.policy/cors` 发 PUT。现有管理入口只允许保存模型、提供商和费用目录，拒绝这个策略写入。即使写入成功，原生浏览器仍按内部监听端口构造 `http://localhost:4000`；实际宿主端口是映射到 4000 的 HTTP 15814，管理页面是 HTTP 15815，独立的私有管理监听使用 HTTPS。

## 2. 修复

1. 在现有中文原生 UI 补丁上增量适配聊天演练场。经认证的静态入口按部署状态标记演练场使用页面同源；启用时只接受当前页手动输入的独立演练密钥，未配置时显示明确原因。独立 MCP 演练场不改，聊天演练场不会把专用密钥传给 MCP。
2. 在同一个管理入口只增加固定路径 `POST /v1/chat/completions`，启用条件是可信原生数据地址和专用密钥 SHA-256 同时存在。请求须来自精确页面来源，且带匹配的专用 Bearer 和 JSON；不允许管理身份、平台复盘密钥、任务密钥或目录密钥代用。仅转发必要头部，分开管理与数据客户端，不转发或保存数据 Cookie，不追随重定向、不重试已发送的请求。和现有受保护保存共用互斥，避免本入口保存滚动中打断演练。
3. 保留已有管理认证、原生模型保存和两站保护、任务 USD 额度及全站共用的独立复盘密钥。原生配置、数据库、用户模型和提供商不改；不开放 CORS、结构、策略或密钥写入，不变更现有数据端口与 TLS。

## 3. 必要验证

- 运行独立入口测试和仓库 `make check`；从固定上游源码应用 P5b 和 P5d 补丁，使用原冻结依赖验证 UI 构建和上游测试。
- 用隔离的固定版网关、合成模型和独立密钥走浏览器页面 → 同源入口 → 原生数据监听 → 模拟上游的实际路径；验证拒绝错误来源、其他密钥、非目标路径及策略/密钥修改，原生模型授权仍有效。
- 现场只切换已有管理入口。验证模型和提供商、原生数据与存储、两站目录与维护状态不变；聊天演练场提示缺少专用密钥，端点拒绝，现场无推理、无配置写入。
