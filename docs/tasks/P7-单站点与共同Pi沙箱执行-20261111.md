# P7 · 单一平台与两模式共同 Pi/OpenSandbox 底座

基线 `117c46667cc74b4f309020f309d4cdbdd6191326`，承接 [P6c](P6c-独立模型演练与AgentGateway退役-20261110-report.md)。用户目标是两站一个账号和入口、创建时区分黑板与 CTF、黑板也使用 Pi 与 OpenSandbox。目标是统一账号、任务目录和历史，创建时明确选择黑板或原生 CTF。P7 只重构通用账户、数据、模式路由和共同运行底座；原生 CTF 的既有角色与授权边界保持，不为整合引入新的外部工具、自动化攻防行为或权限。保留当前站点，候选未证明模式可用和历史完好前不切换。

## P7.1 共同平台

- 用户入口目标为 `http://127.0.0.1:15800`，保留主站账号及会话签名、同一个任务目录、数据库、对象库、模型/MCP 目录和账本。Native Runner、OpenSandbox 和可信 Pi sender 是内部组件。任务创建按显式模式分派，模式由各自的已验证配置决定是否可用；读取 CTF 历史不授予创建、工具或执行权限。一个模式不可用时不禁用另一个模式，也不回退到未经验证的执行链。
- 费用维持 USD 累计阈值及在途可能越线的合同，未知不归零、不重发。终态只读复盘仍不限额，模型演练仍有自己的用途和原请求身份。保留已持久化的任务、会话、命令、成果和费用等证据及既有只读权限。

## P7.2 黑板 Pi/OpenSandbox

- 黑板继续用 Fact/Intent、Explore、Derive 和 Close，保留座席并发、停止/恢复、成果整理及只读复盘。调度仍是黑板自己的领域规则；不给黑板伪造 CTF 身份。共用现有 Pi 1.5 会话、OpenSandbox 生命周期、授权回执和 journal。目标为一个监督进程和原有 PG 锁，不新增第二完整执行器，也不以旧可变 Docker 镜像名作新执行凭据。验证时使用现有已核准、固定的工具镜像，原 `profile.exec_image` 只保留其历史含义。
- 仅对原 Task 当前 AgentRun 与角色授予黑板协作动作；领域写入时在同一 Task 事务复验运行代次、绑定、角色和 journal。仅原规则要求 Intent holder 的动作才校验持有者。Closing 只能在有限窗口内执行已授权的 final Close，超时后不增加 Explore；黑板的既有 grace/裁定规则保持。
- Explore 的正常命令和工作区文件仍经过统一 OpenSandbox 的现有 SandboxMCP 授权路径，切换验证后移除旧 Docker/envd 求解器。保留 BoardSync 增量、active 用户输入的原消息确认和 Derive 轮次投影。不得用文本模拟替代实际文件证据或会话确认。
- 保持黑板已有默认、平台强制 VPN 和平台强制 SOCKS5 的配置含义；各自用本机无害合成端点验证正确接入和失败不会直连，不把未证路径作为已交付。原生 CTF 既有按需网络选择规则不变。
- 使用合成模型和受控工作区材料验证正常协作、持久回执和费用只记一次。故障恢复使用原 run 和 journal，未知状态不会换请求身份重发；显式终态续跑创建新执行代次，同时保留原材料、费用和只读历史。不为只读复盘新建求解权限。无法证明旧任务可安全恢复时明确保留并标记阻塞。

## P7.3 数据保全与迁移门槛

现场只读盘点时，两站 PG 0032 的任务、会话、附件、Runner、费用和未决均为 0，两桶对象、版本和删除标记均为 0；切点必须重验。主站有 1 个缺凭据的模型草稿，两站 MCP 0。两站各一个相同登录配置，保留主站；签名、加密及服务秘密独立，不明文导出或合并。主 `default@1` / `single@1` 与副站同名版本的 `exec_image` 不同，留主站原值。副站独有 `ctf@1` 只作精确配置保全，候选首启自动生成的行不算迁移证据。

1. 当前只做只读盘点与候选验证，先不停止或合并现网站点。任何后续切点须先验证两源写者已停，原 PG/MinIO 与各自配置备份可恢复；主站非终态/暂停、未确认写者，或副站出现 Task、费用、对象、密文或新配置时均阻塞。零数据快路径不会尝试对新业务数据合库。
2. 保留主 PG / MinIO / 目录、原账身份和权限，原副站备份保留只读；按原值校验确切配置，同值重复允许，不同即拒绝。原表、迁移、费用精度、对象 URI、运行回执和备份不删除，未知金额不重算。停止重复入口前须验证两种模式能力不倒退、历史可读及原数据可恢复。缺乏任一证据时保留原入口，不把部分候选当作已切换。
3. 候选验证只用合成模型、无外部目标的惯例协作工具及惰性历史数据。核一处登录、模式/历史视图、账本读回、黑板协作收尾与安全恢复；原生 CTF 的既有边界只用惰性测试材料验证，不创建或执行外部目标的攻击链。黑板已有的网络策略配置不得被悄悄降级或回退直连；任何未获验证的配置只阻塞相应能力。现场不接用户付费模型；当前草稿未配置凭据和价目，不把可登录误写为已实跑。产品改动完成后按仓库要求做必要检查，独立审查精确范围后本地提交，不推送或合入 `main`。

## P7.4 分片与验收

- P7a：正式设计、明确模式的公开 API/创建界面与数据迁移合同。P7b：普通黑板共享底座和单一监督进程，旧执行替换后删重复代码。P7c：精确制品和停写切点验证后发布同一登录，并仅退役本任务拥有的重复应用、端口、Runtime 和专用 peer 配置；保留 OpenSandbox 私网服务、主账号和源数据。若候选在切换后已产生新写入，修复应保留新写入，不能把备份盖回去。
- 同一个候选、同一 PG、同一监督者，合成模型与无害文件/文本验证两模式从同一账号可选并并发运行；遇资源限制时明确排队；检查独立可用性、源权限、一次费用回执和只读历史。黑板实证关闭后仍可完成合法 final Close、故障续接原 journal、显式续跑使用新代次而原材料可读。网络只验证部署配置不会退回未授权连接；不向外部目标发送验证请求。任何制品改变后只沿用实际未受影响的证明。
- 迁移定向用例只验证空源策略、配置精确复制、重复同值和冲突拒绝；实际两源若出现未解决的业务数据就阻止切换。执行候选来源核对与 `make check`，独审实际变更和最终发布证据。仅完成部分时明确列出缺失门槛，不声称已单站部署。
