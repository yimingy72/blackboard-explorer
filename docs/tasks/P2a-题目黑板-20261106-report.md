### 实际接口和版本含义

统一前缀为 `/api/tasks/{task_id}/ctf/knowledge/{challenge_id}`：

| 方法/后缀 | 行为 |
| --- | --- |
| GET 空后缀 | 题内 Fact/Intent、challenge_revision 与 board_version |
| POST /facts、/intents | 当前有效 Agent 写入；返回原操作对象、事件及两个版本字段 |
| GET /objects/{id}?depth=0或1 | 限本题对象与限本题关联，越界对象不返回 |
| GET /search?q=&k= | 限本题文本搜索 |
| GET /snapshot?max_lines= | 复用已有有界 YAML 快照 |

`expected_revision` 明确指 **题目元信息 revision**；知识追加不会递增它。它用于发现题目/分配元信息已变化，不是知识 CAS。返回的 `challenge_revision` 是本次核对的题目版本，`board_version` 是 Task 持久事件水位；并发追加可使用同一题目元信息版本，认领/关闭互斥仍由事务和当前状态判断。

用户与内部服务沿用现有 Task reader 读权；两者不能通过此新写入口冒充 Lead/Worker。新路由保留基础 Task 鉴权，仅由自身处理器替代旧预算 middleware 的重复特有授权。

Fact 的材料预检先短暂核验身份/分配/登记材料，再释放数据库事务，锁外执行总等待上限 10 秒的 exists 检查，最后锁内重新验证。超时返回 503；底层客户端线程是否已经结束不被用作停止证据。幂等已存结果通过当前授权后直接读取，无需再探测存储。原普通 BoardService 外部检查语义未改。
