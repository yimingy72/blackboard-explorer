# P8 · 配置工作台与角色合同实施报告

2026-11-11 已更新唯一正式入口 [127.0.0.1:15800/login](http://127.0.0.1:15800/login)。应用和共同 Runtime 的源代码为 `d70f2f91`，应用镜像为 `sha256:f99563e2801917329b7eb3c526011327fe4167475c6692ab7d66f1cbf328694e`。原账号认证、黑板与原生 CTF 两种创建能力、五个配置页面及两个旧链接均通过实际 Chromium/HTTP 读回；没有创建任务或调用真实模型及外部 MCP。

## 实施

1. 五个已确认页面进入正式应用：普通 Worker、CTF、成果整理、模型管理和外部 MCP。普通 Worker 按角色展示实际工具及参数，Explore 的命令和读写文件一组开关；Derive 与 Close 不提供 Sandbox。普通提示词、工具和调度发布给新任务，既有任务与续跑继续读取各自固定版本。执行资源与网络由部署决定。
2. CTF 读取部署固定的 Lead/Worker 模板和工具。Lead 仅使用发布所允的任务网络选择；Worker 不改网络，平台强制 VPN/SOCKS5 不可由 Agent 关闭。部署没有新增 CTF 写入口或权限。命令及逐 Agent 流量继续只读核对。
3. 成果整理提示词与工具下一回合生效；任务首次启用整理时冻结模型和费率，使用独立 USD 预算。新默认正文由平台在认领时交给 Runtime，已自定义正文优先。任务事实、派工、验收和终态不属于成果整理写权限。
4. 模型管理沿用 OpenAI 兼容接口与输入、输出、缓存读、缓存写四项 USD 费率。未定价连接仍可测试，任务使用仍核对启用、凭据、能力和价目。
5. MCP 继续使用公网 HTTPS Streamable HTTP 的草稿、发现、明确工具/角色、发布。目录发布与具体任务授权分开，仅 Explore、CTF Lead、CTF Worker 可获授权；没有删除与自动发现。

## 偏差与待决

- 前两次切换在发布核验脚本中触发回退：一次为 Python HTTP 辅助函数命名冲突，一次为浏览器检查误要求并非产品合同的旧链接片段。两次均恢复原应用和共同 Runtime。修正验收脚本后以同一产品源码成功切换；重试复用已经追加并验证相同的提示词版本，未重复追加或覆盖数据库。
- 旧集成用例 `test_worker_settings_and_gateway_task_keep_original_profile_versions` 的创建段缺 P7 要求的共同执行环境发布配置。在原部署源码 `a67d2a5` 的独立源码副本中复现相同 503。该用例在此前的设置读取、保存、冲突与变量校验均已走通。本次另用 P7 原生黑板派发与真实 PostgreSQL 的 P8 发布用例覆盖有效路径和冻结版本。

- 历史工具设置键继续兼容；公开目录列出当前运行名称。已冻结普通任务、CTF 任务和发布验收证据无需回写。
