# P4g：原生 Worker 前台 helper 接入方案

实施方案，基于 `feabda1`。统筹、插件接缝和事务状态三路审核同意仅开前台切片，后台保持关闭。沿用 [平台架构重构方案](平台架构重构开发方案-20261105.md) §4、5、11、12、15，[P1 Pi 接缝](P1-Pi接缝验证-20261106-report.md) 和 P4a–f 已交付控制；本阶段已实现并通过前台实际链路；数据库、插件、真实 Kubernetes 分阶段结果与未覆盖边界见 [实施报告](P4g-原生helper接入-20261108-report.md)。不修改设计正本；只有冻结启用的新 Task 可用。

## 1. 本片交付

让已经持有当前 Assignment 的原生主 Worker 从真实 Pi 模型工具循环发起一条前台委派，在同 Task Runner Pod 中通过锁定的 pi-subagents 前台执行真正的子 SDK 会话。helper 有独立 binding、代次、journal、模型/MCP 短凭据和 Sandbox 命令身份；借用一个已有空闲 Worker 席位，不获得题目 owner，不启动新 Pod/Sandbox，不改变原预算 key、Task 硬截止或命令界面只读合同。

首片每父最多一个未清 helper，只开放一个有界局部目标、当前题目经校验的 Fact 引用和预期产物。系统从原 Assignment 有效快照继承模型、推理级别、适用的 Sandbox/题目工作目录、已获准工具与 Skills，并与 helper 上限取交集。生产原生 Runner 当前关闭 Skills，首片继承空集；必要题目信息由可信控制注入到全新上下文，不复制父对话。首片工具上限固定为 Sandbox `read_file` 与 `exec_command`；题目信息只由可信宿主注入，无 board 工具或 `get_command`/状态、输出、取消命令工具。后端在原调用准入和实际派发核验 `background` 只能缺省或为 false，命令期限不得超过 child 剩余期限；命令仍需按子作用域清理可能残留的进程。产物由本次工具结果回父，不开放任意业务写入、Flag 登记/提交、Intent 关闭、换题或递归。文件目录是组织约定，不声称构成同 Task 文件安全边界。

不开放后台 helper、插件的通用 `subagent`/resume/fork/async/daemon、自动重试、任意 agent/extension 参数、外部 Runner 或通用子工作流。P1 的后台接缝证据不等于已接生产监督，后台 gate 保持关闭；本片要求前台完整执行与正证退出，不能只交合同。只对使用受支持 Runner 构建且在初次 native launch 冻结启用的**新 Task**发布 helper；默认关闭，旧 Task 不热改 route、角色、启动请求或权限。

## 2. 持久事务与借位

1. 父工具只接受有界 goal、当前题目引用和预期产物。Runner 确认父 journal 后用现有 `ToolInvocation` 身份（原 binding、SDK、持久 assistant entry、tool call、参数摘要和游标）走专用委派准入；不让普通 MCP 路由直接触发插件。BB 在同一个 Task advisory lock 内校验父必须是当前已准备的主 Worker、当前 Assignment/turn/generation/epoch/scope_revision、预算和控制状态、Task 冻结发布能力，及输入引用确实可由父读取。
2. 复用 P4a 的可派主任务谓词和排序（ready 状态、题目当前 scope、无 owner、材料/环境满足）。主派工与借位同锁；先实际处理可派的独立主工作，再借剩余空席。用已预建的空闲 `member-N` 作为唯一席位及该次临时 helper 身份，分配独立代次/turn/binding；不改 Challenge.owner。借位表按 seat 防止主派工/第二子占用；无位、已有未清子或会超过 P4f 原 epoch 32 条绑定上限时立即返回有类型的普通结果，父继续执行，不排队等子位。先在同锁内完成本轮可派主工作，再按当前 epoch 已注册全部历史 binding（包括 helper）及尚未入表的在途 reservation 计数；正常路径 reservation 与 binding 同事务，因此无另一个隐形在途名额。主派工已有的历史绑定上限不扩大。
3. 优先复用 `runner_bindings.business` 保存不可变 ChildRun 关联（child ID、父 binding/turn/Assignment/代次、scope、seat、epoch）；`ctf_control` 只保存仍占用的 child 索引；父委派的 `runner_calls` 持久化 launch claim、固定参数和受保护的结果，继续使用已保存结果的摘要和加密存储。父委派这一条与子自身 model/tool 账本分开。注册子绑定与建立席位在同事务，不引入新的通用执行队列。
4. 专用本地控制合同分为：`reserve` 返回已登记或有因拒绝，`launch` 同调用只领取一次并携带唯一的插件 owned prepare，`status` 只读已登记、已领取、draining、已保存结果或 unknown；独立结果/关闭回执按原 ChildRun 持久保存。它们使用短 HTTP 请求和轮询/事件，不通过长 MCP `tools/call`，不改普通工具等待合同。父 SDK 工具保持前台等待，不把登记回执当作结果；期限冻结为现有父 permit 的 `min(now+60s, Task 硬截止, 父原 capability 到期)`，包含准备及执行，续凭据不延长它。若投影无法在该界限内满足，从已核对的 Task Runner 控制通道在 launch 回执只签发本 child 的短能力，留在可信进程内存，不让模型/插件参数接触它；不依赖 120 秒投影等待或放宽 MCP deadline。
5. 只有取到一次启动许可的一方可调用插件；同调用换参数拒绝，已保存结果只读回，领取后回执不明、插件启动结果不明、已发送副作用不重放。无位/超限等拒绝立即返回普通工具结果。父等待超时或 abort 结束只撤权并触发 draining，不等于子已经完成；子或原结果仍未知时，原调用和占位保留，父 Assignment 不转派，不用新 ID 绕开。确证从未领取/从未启动才按对应记录结束。已知结果或明确取消回执确认后才可交原父；旧父无效时只保留原历史，不通知新题或唤醒已停父。

## 3. 实际 Pi 接缝与上线门槛

- 固定当前生产 SDK 同一套版本与 pi-subagents `0.85.0` 精确源码 `b6647222bd2e849021054292927ef39fea0793ed`，复用 P1 可重建锁定补丁/制品方式。官方未补丁版不能满足 G3；不升级 Pi、不复制私有 auth 标记、不 deep import 插件或写第二个 Agent 循环。仅 Worker session 显式加载可信扩展，以公开 required-child-extension/capability-ceiling 限制；模型只见平台封装的本地委派工具，不见插件其他工具。以测试证明 model wire 的工具白名单只在该原生父 binding 增加此名称。
- 可信封装从生产的父工具执行路径取确认游标与一次启动许可，调用插件公开的 foreground ToolDefinition。单次调用用进程内窄关联把获准 ChildRun 与插件 run 对上；父子不同凭据，不在 prompt、daemon env 或参数中传 token。插件接受的配置、agent 定义和工具由可信模块固定，禁用用户目录发现、本机工具、扩展和网络模型旁路。
- **前置门槛**：P1 的 `sessionHost` 在插件建好 SDK 后才安装，仅靠它无法为 P4f 固定 `<epoch>/<child-binding>/session.jsonl`，也不能阻止默认 ModelRuntime/Skills 发现。需在同一锁定补丁增加窄的公开 pre-create 宿主工厂：在任何默认 session/model 探测前由生产 Runner 提供精确的 session manager、effective model/settings、MCP custom tools 和可信路径，再在首次 prompt/session_start 前对**同一** raw SDK 安装现有增量 journal、model/tool 硬屏障。缺宿主、错配、安装失败或关闭竞态必须拒绝发布。普通 prepare 命令行仍用于 acquire/receipt 证据；插件 owned prepare 只由 launch 交给可信宿主，排除于普通 prepare poll，单一 child slot 接收既有 lease-renew/close。初次 journal + prepared 的同身份回执（或确切只读确认）是子首次 prompt 的前置。
- **前置门槛**：前台插件必须经真实 public 启动/取消路径提供可在生产合同核对的同一 run、SDK、最终 journal 和唯一 disposal 证明。固定插件的前台 `dispose()` 失败可被吞掉，晚创建还可能异步清理。首片须在启动前建立独立 terminal Promise，补一个窄的 await pre-dispose 接缝：宿主负责冻结/abort、最后 journal 和 MCP 清理，插件拥有唯一 raw SDK dispose，按原 run/SDK 明确回报完成。两边共用幂等关闭，超时或失败只记 unknown，不以普通 subscribe、通知或 wrapper 返回作正证。控制事件独立于父模型等待处理；父工具被 abort 不推断子已结束。
- 子模型/工具沿现有 journal CAS、`RunnerGateway._scope`、NativeFees、MCP 和 Sandbox host 走独立 capability。Task 共用原 Agentgateway key/高水；fresh 子 journal 每次模型发送前确认，拒绝使用 SDK usage 默认零值。失败时返回 SDK 可消费终态且上游零调用。child 的 MCP role 不等于 teammate，所有数据访问都重核父 scope；单独的 CEL 只授权 Sandbox target 的两项工具，业务 server 单独拒绝 helper 业务会话/调用。必须实证当前多 target 路由 helper 的 Sandbox 握手、工具目录及业务 target 负例；如果固定网关无法做到安全隔离，不以宽放行换跑通，保持能力关闭，先报告最薄专用路由选项。保留原父和子 attribution，不给 helper 通用业务写入。若不能做出上述可复用的宿主、真实 model-selected 调用或正证终止，停在关闭 gate 的接缝结果，报告阻断。

## 4. 生命周期和旧执行

- 正常父 Pi 回合结束不取消有效 Assignment。父 Assignment 撤销、换题、题目完成/取消、scope revision 变化、预算/人工暂停或 Task stop/delete/deadline，先在 Task 锁下撤销子新准入并标记 draining，级联向真实前台插件与 Runner 发停止/关闭；不依赖父继续 prompt。父 `NativeWorkers._drain` 不在子清理完成前释放/转派。子席位也保留到原 SDK/最终游标关闭、插件正证退出及该 child Sandbox scope 清空/封存；远端命令结果未知仍保留原记录，不补写 sealed，不重新发送。单纯费用待核沿原预算 hold，不能反向授权执行。
- P4c/P4d 的 pause snapshot 包含仍占位的子 binding，复用原 `close_proven` 和受限原日志尾路径。恢复只继续原 Task 的主工作；旧 helper 已知/未知结果均留在原 ChildRun，不自动重建。P4e/P4f 同样纳入冻结活动清单、原 binding manifest 与原 epoch 账本；未决启动、journal、tool/model/费用均按现门槛阻断，原物理全退出可证明作用域无进程但不能洗白结果。正证后回收旧子索引，不将子能力绑定到新 epoch。旧回执只按原身份接收。
- 绑定的身份取可信 BB 记录：helper 独立角色和 parent_agent_id 到现有 Sandbox launcher/netns/命令归属，`SandboxCommandSummary.role` 扩为可读 helper，保留父关联；命令视图只增加只读 helper 标签/关联（若现有展示需要），不新增审查、取消命令或审批按钮。Task 级 stop 的终态清理由原 Runtime 路径完成，不能以缺失回执冒充已停。

- 先过实际插件与 Pi 的一条前台接缝：父假模型生成受信工具调用；实际公开插件创建子 SDK；仅正确继承的工具/模型可用，独立 journal/凭据；注入确认或安装失败，子上游零发送；注入一种 abort-during-create 或 dispose 吞错、确认无正证不放位；父/子取消与待保存结果回执丢失不二次启动。原后台 fixture 不作为本片产品通过证据，也不跑完整旧矩阵。
- 一个真实 PostgreSQL 并发场景覆盖 ready 优先/最后一个席位不双领、并发重复请求不双启动、旧父 scope/epoch 越权、父撤换等待子 drain、manual/budget 与旧 epoch 清单兼容。至少覆盖一种晚证据/已知结果回读与一种未知保持阻断，明确正证释放与未知不释放；可复用 P4a–f fixture。
- 一个产品纵切以假模型验证真实父/子、同原预算身份与累计、真实 Sandbox 工具调用及子/父归属、helper Sandbox target 握手与非 Sandbox target/角色负例、取消后不再发和确定停止后才释放。如果现有隔离 K8s/固定网关探针可以无额外基础设施复用，优先一条真实本地链；若阻断则标明未验证边界，不能用 P1 假宿主冒充产品运行。命令记录保持只读。最终在干净候选跑 `make check` 和必要生成合同检查，不调用真实模型/靶场，不顺带扩 20 席位压力矩阵。
