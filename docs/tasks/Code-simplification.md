# Code-simplification · 全仓库代码审查与精简

依据：用户明确要求审查所有代码并精简；code-simplification技能及AGENTS.md。子代理统一GPT-6.1 Sol high。

## 范围与约束

- 覆盖packages、services、web、eval及工程/部署脚本；生成文件、锁文件、第三方依赖和历史迁移按用途检查，不机械重写。
- 精简重复流程、过密条件、命名与无效包装，保留所有输入输出、错误、副作用及顺序。理解调用链与历史原因后才改动。
- 不更改设计、模型提示词、API/数据库合同、调度/计费/权限/归档规则，不引入依赖或配置。发现功能问题独立列入报告，不混入纯重构。
- 原有测试不修改。每个独立精简先运行对应原测试，失败则恢复本次改动或重新审查；以可审阅的小批次提交。
- 同一工作树分目录并行，主会话负责前端/工程和最终审核，子代理负责各自分配的后端目录。共享文件由主会话协调。

## 完成标准

- 给出全仓库覆盖清单，区分已精简、保留现状与待后续处理；不得把未修改等同于已重构。
- make check、make test-integration、前端check/build及原浏览器测试全绿，无测试或业务行为变更。
- 复核事务顺序、取消/重试、流式响应、会话、账本和数据安全边界，保留必要复杂性。
- 中文报告docs/tasks/Code-simplification-report.md记录改动理由、实际检查、提交划分及限制。
