# P10 · 公开本地部署流程

把已运行的 P9 流程整理为仓库内可复用入口。先测试、独立复核并同步交付分支，再用已同步的同一提交在本地重新部署。正式入口仍为 127.0.0.1:15800；不重新迁库，不更改任务、角色、网络、模型或费用合同。

1. 区分首次安装、镜像或发布变更和现有站点原地重部署。首次安装须具备同一 Kind、Cilium、OpenSandbox、TUN、镜像和证书能力，用隔离合成数据核验新发布。不把未验输入、占位镜像或默认零副本清单套到正式站。说明精确 Git 来源、镜像摘要、集群载入、私有发布/认证输入和全部前置条件。
2. 原地重部署仅操作已安装站点的原应用、Runtime，以及显式要求重建的存储 Pod。使用指定 kubeconfig/context、只读检查与 reviewed fingerprint；停止入口写入并二次核对任务/调用，优雅停 Runtime 并确认锁释放，再按依赖顺序启动，核对原卷/密钥/模板、数据摘要、Pod imageID、锁代次和两种创建能力。发生故障时只恢复目标集群原规格；不启旧站或另建卷。
3. 说明备份恢复边界和浏览器重连。PG 整库与全局对象、MinIO 同版本全盘及加密密钥分别保留，独立验证恢复，Retain 不是备份。修正使用指南中过期的模型协议、计费、工具、环境和续跑说明，旧行为链接历史记录。
4. 仅做受影响的定向测试、静态检查和必要的提交前检查。正式验收保留实际制品、原数据和重部署回执，不调用真实模型或外部 MCP。
