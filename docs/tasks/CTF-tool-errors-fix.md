# CTF-tool-errors-fix

## 授权与范围

用户要求复核 `CTF-tool-errors-report.md`，继续审核 CTF 团队模式的相关及其他问题，并实施性能优化。沿用 `ctf-cooperation` 工作树；前端使用当前 `ui-rebuild` 工作树，保留其中已有改动。

1. 用当前部署源码及原生 MAF 路径验证报告结论，区分可复现根因与历史上尚不能逐条归因的失败。
2. 修复工具参数、观测、持久化及错误反馈链路；保持认证、代次、预算、停止和不确定副作用的保护边界。
3. 审核派工、成员生命周期、消息与收尾，修复有具体复现的缺口。
4. 减少会话保存及数据库读取的重复开销，保留费用凭据、恢复和幂等性。
5. 复用 MAF 公共中间件、Content、原生函数输入模型及已有 PostgreSQL/SQLAlchemy 能力，不修改 SDK 内部实现。
6. 验证后更新本地环境，保留已有任务、会话、配置和对象存档；报告实际结果与限制。

## 完成标准

- 原生 Agent 搭配实际观测与 checkpoint 中间件可提交带 UUID 记录、附件引用的交付。
- 可恢复拒绝提供固定错误码及必要字段；未授权、控制故障及未知副作用不能变成模型的盲目重试。
- 移除/重开负责人不会丢失 Lead 的派工通知，也不改变已取消题目的终态历史。
- 性能结论有操作数或投影字节数的验证，不以邻近事件时间替代实际调用耗时。
- `make check`、复用已有依赖镜像的 `make test-integration`、前端检查及构建通过。
- 不调用真实模型或靶机，不读写 `.env`、不读取真实答案，不改 `docs/design/`，不提交、合并或推送。
