## 后端与架构优化

### 普通黑板

- 心跳、conclude、工具登记等按命令读取所需的任务与目标 Agent；需要整图决策的命令继续走原领域 `decide` 和完整 Fact/Intent 状态。
- Fact 引用工具证据只读取所引用的工具身份元数据，保留同任务/同作者及重复编号判断。
- 注册、trace及心跳元数据检查不再读取整块黑板与所有工具输出。
- 搜索只读取可搜索字段，仍保留原 `casefold()`、排序及筛选语义。
- 事件游标与结束原因使用明确排序的有限读取；修复原 `array_agg(..., order_by=...)` 未生成 SQL 排序而可能取到旧结束原因的问题。
- 调度器不因纯 trace/tool 日志反复读取状态；领域事件、progress和定时兜底继续唤醒。

### CTF 团队

- 邮箱认领批量更新，保留 generation、turn、purpose、claim token 校验与顺序；超过1000条时分批处理，没有截断消息。
- Checkpoint 批量读取/更新投递状态，每条投递仍有自己的持久事件；每批提交只通知一次，SSE 按游标取得全部事件。
- 不可见私信正文在 SQL 投影阶段清除，仍经过原最终访问策略；不把他人的私信载入再丢弃。
- 邮箱去重从逐项扫描改为集合，空邮箱不扫描完整历史；注入复用 MAF 原生 `enqueue_messages`。
- 上下文 token 估算使用字节转换实现原公式，ASCII控制空白与Unicode行为不变；不是更换计费 tokenizer。
- 原生 Session 已序列化快照直接用于确认摘要，减少逐条重新构造 MAF Message；冷恢复仍走原有框架路径。持久 checkpoint 次数、CAS、取消、预算和租约语义不变。

### 共享接口

新增兼容接口 `GET /api/tasks/page?q=&status=&mode=&limit=20&offset=0`，返回 items/total/status_counts/limit/offset。计数与条目共享读取快照，鉴权保持；旧 `/api/tasks` 数组接口继续可用。`status_counts` 应用 q/mode、不应用当前 status，供筛选标签计数使用。

新增迁移 **0017**，只增加结束事件部分索引，没有业务数据重写或新配置项。上线时需执行既有迁移流程，并选择不会打断任务的窗口。
