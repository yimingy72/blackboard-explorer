# P4b：Lead 题目更新与范围切换

## 完成内容

新建原生自动派工 Task 冻结工具目录 revision 3，Lead 可通过 `board_update_challenge` 更新标题、题面和要求。旧 revision 1/2 Task 的工具权限不变。工具沿现有 Runner 绑定、MCP 准入、Lead 角色、Task 锁、请求幂等与题目版本 CAS 生效。标题修改保留原范围和分配；实质改变题面或要求才增加 `scope_revision`。

变更范围时移除旧就绪意图。Lead 可在更新中明确声明新范围就绪，或等原分配清理后再标记；不能沿用旧的就绪状态。已有 Worker 时先保持原席位和 owner，撤销旧范围的新模型、业务和命令准入。已准入调用可能迟到，其结果仍按原绑定与调用身份保存。原 Pi close、已确认 journal、Sandbox 范围封闭排空及未决执行门都通过后，才按明确的新就绪意图重新排队，为同一题生成新 Assignment；撤回和整 Task 停止优先。

当前 Worker 的黑板、搜索、对象和事件只读当前范围，过滤历史事件时保留游标。旧 Fact、Intent、命令和 Flag 不删除，Lead 和用户仍可查历史。写入只能引用当前范围的 Fact、Intent 和已保存的原命令；共享 Task 输入仍可作为独立对象证据，不能把合法 URI 与旧命令 ID 拼成同一证据。Flag 值和当前 Worker 列表同样按验证轮次收口。同题已发送且未决的 Flag 会挡住范围变更，未发送的旧轮次准备记录通过原事件取消，旧回执沿现有轮次校验只归原账。原生 Lead 现在可收到发给自己的同 Task 题目通知，Worker 的原题门保持。
