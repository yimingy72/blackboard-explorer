# P4m：任务网络职责分离

需求复审后续实施版，基线 d61dbfbd。**同一 CTF 产品流程按任务配置决定使用默认网络还是共享 VPN：不需 VPN 就正常执行，不连接；需要时由 Lead 按任务说明配置，Worker/helper 直接访问共享 VPN 可达的题目地址。黑板任务可以不配 VPN/SOCKS；一旦平台绑定，Agent 不能修改、关闭或绕过。两种协作模式的所有网络路径都需要采集 Agent 流量。** 命令记录只读，不做审查或处置。

## 复审结论与现状

P4l 已证 OpenVPN/TUN、内部 WireGuard、原 Lead 操作回执、短租约、停复与逐来源抓包。旧专用 VPN 发布在未连接时阻断求解命令，也不提供同一入口的默认网络分支；这是旧切片的限制，不是 P4m 产品行为。P4l 为可验证的小切片固定 peer、凭据和目的 IP/端口。它的逐目标白名单是实现限制：沿用到 P4m 后，来源 API 新返回的题目地址会被拒，不能算 CTF 正常工作流。**新方案不做逐题目标增删、登记工具、目标版本管理或管理审批。** 逐 Agent 归属继续依靠执行 binding、Assignment/epoch、veth 和抓包来源，不依赖目标名单。

前次多 Agent 通过的是已被修订的固定目标首片；当前按网段执行、同入口按任务选择默认网络或 VPN、以及五条路径均采集的方案尚需后续合同评审、实现与验证。当前隔离候选已经有未完成的动态 peer、私有资产、受限 HTTPS 获取与状态接缝，仍采用上述不合适的初始固定 targets；它既未通过本阶段验收，也不得发布或作为产品提交。旧候选和证据保留供续作。用户已确认按下列新合同先审后开发；仍未完成实物验收，不发布旧固定目标候选。

## P4m1：同一 CTF 入口按任务配置网络

1. **任务配置决定网络，上传可选。** 同一 CTF 创建和执行流程按任务配置区分默认网络和共享 VPN，不要求切换部署，也不额外确认无 VPN。默认网络任务不会拨 VPN；命令按默认网络策略与采集门正常执行，不依赖 VPN ready。选择共享 VPN 的任务由 Lead 按说明连接，等待或断线时不得悄悄退回默认网络。需要 VPN 时，Lead 可用任务说明中的普通、无凭据公开 HTTPS 下载地址，或用用户通过专门入口上传的同 Task 私有连接资产引用。私有资产不走普通附件：普通附件进入 /workspace/shared/inputs，同 Task 低 UID 可共同读取。原始 .ovpn、私钥、下载凭据不进入 Solver、共享卷、工具回执或平台下发给模型的日志。公开 HTTPS URL 可以出现在工具记录；不支持带认证查询、签名 URL、任意 Header、私有网页登录或让模型代持密码。私有文件需本人权限、原 Task 创建绑定、领取后不可替换；其他 Task 猜到 ID 不能读取或使用。
2. **两条来源共用同一个可信执行入口。** 原 Lead 身份、确认 journal、owner epoch 和 Task 锁下，一次保存原调用与意图；受理不等于拨号或 ready。真实远程获取用受控 HTTPS origin、固定受信解析的连接 IP 和原 TLS 主机名，限制时长和字节，拒绝重定向、代理和控制区地址；不依赖还未建立的 Solver VPN。私有字节加密保存，不在公开资源记录；唯一原出口领取在固定安全路径进入私有 tmpfs，不向 Runner/Host/Sandbox/模型返回。副作用未知只对账，不重取或重拨。首片限定传统 OpenVPN TUN、单 remote、UDP4、内联 CA/证书/私钥与可验 tls-crypt；其余指令按实际支持严格解析，不原样执行任意 .ovpn。拒绝脚本、include、额外文件、任意路由/DNS 等。服务端 TUN 地址由可信出口只读查询同原 OpenVPN PID 的私有 Unix 管理状态，核地址/原接口后设置 /32，不要求用户重新输入。
3. **一次形成 Task 可达范围。** 从任务来源的网络说明、经可信校验的结构化路由或部署已有通用网络边界，得到本 Task VPN 可达网段；管理员不按题预填 IP/端口，Lead 不为每个新题补登记。经平台永久禁止区裁剪后，同一已确认网络范围内的新题地址和 TCP 端口可直接使用。禁止区含集群 Pod/Service/节点与控制地址、元数据、内层链路、环回及链路本地等；还排除原外层 peer 和其他底层地址。对不合格地址直接失败，不回退直连。若某来源无法提供可证明的安全范围，不能把任意服务端路由直接安装到控制路由表；应明确该来源能力缺失，先验证来源边界。新版本的具体默认范围、重叠网段裁剪算法及拒绝条件在实现前审查，禁止把一个样例 CIDR 变成永久按题维护的白名单。
4. **外层 peer、系统探针、求解网络分别约束。** 原 Task/资源代/Pod UID 的 Cilium 规则只允许冻结实际 OpenVPN peer 的 /32 和 UDP 端口；在读取策略所有权、UID 和生效证据后才允一次拨号。可信系统同路 TCP 探针保持独立的 IP/端口，只用于证明路径，不能变成 Worker 的目的地址白名单。正常运行时，WireGuard、独立策略路由、Sandbox/Runner 的双层短许可及过滤按同一冻结 Task VPN 范围，管理禁区优先、无直连或默认路由回退。模型/MCP/平台控制走原路径。仅在共享 VPN 分支，待机或断线时模型、控制和文件读取仍可用，VPN 求解未获许可的命令明确未发送；默认网络分支不受 VPN 就绪门限制。运行后 API 返回同一可达网段内的新目标，Worker 普通命令直接访问。可信系统流量不归到 Agent。
5. **复用原生命周期。** P4l 原两 Pod、四个容器身份、两层短期许可、P4i 逐来源抓包与原留卷保留。主动暂停关闭旧流、封闭作用域和抓包。默认网络任务沿原身份与采集条件恢复，不依赖 VPN。共享 VPN 任务仅在确证原外层连接仍在时，以原 pause ID 和新 binding/source 受控恢复，不重拨；VPN 失权、断线或结果未知同代不重开。普通 stop 不等待外部获取或采集，关闭转发后按原 CID 正退出；跨资源代不自动重取或重拨。原每部署一个连接占用，未知/普通断开保留，原全部正退出才释放；独立远端身份和并发未经实测不发布。私有资产只在可证明原写入和资源终态后退役。P4l 已冻结固定 peer/target 的历史合同照旧；旧部署不原地热切。新能力启用后，同一发布和创建入口内按 Task 选择默认网络或共享 VPN，旧非 VPN 创建兼容。是否开放运行中主动换网由后续合同决定；若支持，不复用旧连接和来源证明。
6. **验收门与范围。** 修订合同重新独立评审后才继续。只做必要的组合 PG/HTTPS 验证私有上传、跨 Task、限量及 pin/TLS、原回执与未知、网段和控制禁区；从同一个创建入口证明默认网络任务正常命令执行、从未拨 VPN，以及无附件 VPN 任务由 Lead 实际 HTTPS 获取、使用动态 peer 和实际分配 TUN，并由 Worker 低 UID 执行、归档、停复/停止。Worker 在没有重新配置或注册目标的情况下访问预检之后新出现的不同 IP 和端口；同时证明同网段获准目标可达、管理/越界地址、直连旁路与过期许可均拒绝。使用本地对端、假模型和明确的普通创建链，不碰真实 TSec 或凭据；最终干净候选 make check，精确差量独审后才提交。

### 已复审的实现合同

- **首选由 Lead 完成。** 新发布创建时 Task 原子冻结 capability 和完整发布摘要，网络为 unselected；任务说明仍是 Lead 决策依据，不扫描关键词，不要求用户再录入模式。模型、业务 MCP、文件读取先可用；所有 Solver exec 在未选择时返回已保存的“未发送”，不留下未决调用阻塞 Lead。原 Lead 首次用内部 network_use_default（空参数）或 vpn_configure（普通 HTTPS URL 或本 Task 私有 source_id 二选一，另有独立 TCP preflight）在 Task 锁和原调用回执中冻结 mode。默认选择幂等；竞争的异类选择不获许可，已启动命令期间不换网。允许默认任务持有未使用私有资产，但不能领取或使用它。Worker/helper 无模式工具，只继承原任务生效网络。
- **两条路径使用同一冷启动模板。** 新发布保留完整冻结 deployment，Runtime 不因选 default 删 vpn 能力配置。原两 Pod 带可待机的独立 egress 容器和 TUN 容量；这是新双路径部署的节点前提，非额外用户操作。初始无求解默认 Cilium 放行、无 VPN peer 许可。默认分支在原 Sandbox 粗网段策略正读回、原来源捕获就绪后正常 exec；永远不领取 VPN 材料、占用凭据槽、拨号或等待 VPN ready。即便闲置出口也按原四个 CID 停止。VPN 分支只装原 peer 策略，在同路真实预检后开放，失效不回退默认。旧 P4j/P4l wire、镜像和冻结合同保持。
- **网络和来源的数据。** 新 Task 投影 native_network 取 unselected/default/vpn，与发布能力分离。默认持冻结 route_policy 与 network_digest、独立策略正回执；新 Runtime 通过 network_default_ready 提交该 digest、原 policy 名与 UID，只有 Task/代次/原实例匹配才从已选待机到可执行。VPN 继续 vpn_prepare_source / vpn_peer_ready / 唯一 claim，network 中包含独立 peer、preflight、route_policy 与 network_digest，不含逐题 targets。原 bootstrap 身份不因新选择改写。新逐 binding scope 持同一策略与身份；VPN 额外绑定原 VPN operation/network digest，旧固定 targets 保留旧协议。
- **执行面的策略。** 新 route_policy 由可信发布的通用 IPv4 范围及可信部署/实际集群地址产生，有界去重规范化的 allow_cidrs、deny_cidrs 分开存；可信来源范围如已验证只可收窄。与控制、底层和保留范围相交的地址在两层按拒绝优先处理，禁止广范围配置覆盖禁区；解析不全、策略不能精确安装或无法读回则不放行。默认只允许从原 Agent veth 经 Sandbox eth0、实际 Cilium 许可到获准范围；VPN 只经同 Task WG→TUN，另留外层 peer /32/UDP；均先按真实来源采集。允许范围内 TCP 不维护逐题端口。探针只用于实际 VPN，同预检边界但不定义可达范围。路由、捕获及源的复用以 Task、资源代和原实体身份为条件；默认恢复不查 VPN，VPN 跨代仍须显式操作，不重复领取历史效果。
- **本片实物。** 一个私有 K8s、同一发布/创建入口的两个必要 Task：默认 Lead 选择后正常 TCP/独立捕获/停止，确证无 VPN 领取、拨号或凭据槽；VPN 无附件真 HTTPS 下载→Lead 选择→实际 TUN→Worker 访问预检之后新出现的不同 IP/端口→独立归档/停复/停止。用同一夹具和组合 PG 证据覆盖私有文件、异类选择拒绝、未选择未发送、原身份和禁区，不重复全套。实际 K8s 前，低层实现需要证明拒绝优先，不能以单层字符串比较替代。

### 实际来源后续

TSec 可另接其任务规则要求的业务 HTTP 预检（例如实际 HTTP 200 且 body status=ok）、题库 GET、题目 POST start 与可信提交。系统 TCP 探针不能替代业务规则。业务预检失败按来源规则停止，不换地址或静默重试。题目启动返回新 IP/端口后，Worker 直接通过原 VPN 访问同一获准网络范围；**不另做逐题目标授权版本或工具**。若真实来源确有独立跨网范围，优先澄清任务授权范围，不预造管理平台。普通用户未要求的 DNS、UDP/ICMP、IPv6、回连、任意配置和完整真实来源不计入首片 TCP 验收；可信业务请求的凭据和回执与 Worker 网络/PCAP 分开。

## P4m2：黑板可选的平台 VPN / SOCKS

平台可以保持未配置，黑板任务沿正常默认网络路径；流量采集仍是平台能力，不随 VPN/SOCKS 配置省略。若平台按部署或可信任务配置绑定了获准的 VPN/SOCKS 环境，平台在执行前固定版本并进行原预检；运行中 Agent 无权更换、关掉、通过环境变量、旧 API、直连或恢复入口绕过。配置后不可用应明确显示阻断，不能回退到未配置。新配置不热迁移旧历史任务；存量读取不变。

黑板现在走旧 Docker/envd，不是原生 CTF。现可选 TinyProxy、HTTP/CONNECT 以及 HTTP_PROXY 环境不等于 SOCKS5 或网络强制。平台独立出口持真实 VPN/SOCKS5 客户端及凭据，执行网络不可被 Agent/旧 envd 特权命令改写，且实际 Solver 同路预检先于执行。验收配置 VPN、配置 SOCKS5、未配置旧行为、断线、清空代理环境与直连绕过；只有实际验过的 TCP 模式可发布。若只能支持显式 SOCKS TCP，必须如实说明并在网络层拒绝直接 socket，不宣传透明能力、UDP ASSOCIATE 或完整代理。控制流量独立、记录只读、来源保留原绑定；无逐 Agent 正证时不能拿共享出口包冒充。

黑板接续从已有 legacy Task 真实启动入口冻结服务端发布身份和网络模式（未配置保留默认，无浏览器或 Agent 传任意出口）。配置分支用专属受限执行网络与独立可信出口，在 Agent 无权操作的边界强制；复用原 envd 来源网卡/采集链；默认兼容仅指路由，旧 TRAFFIC_ENABLED=false 不能成为新受支持任务跳过采集的开关。旧 envd sudo ALL 或其他提权能更改 netns、停采集或更换 Agent 来源，强制路由与采集须在该权限之外，或先限制执行权限并实证这些操作失败；核代理环境和恢复入口同样不可旁路。明确先在隔离 Docker 做路径与非旁路能力验证，再选实际可复用的 VPN/SOCKS 客户端，避免另写协议实现。仅当前已有 evidence 精确匹配的默认采集可复用，否则补同夹具代表路径。黑板三模式具实物证据才写完成，不以配置页或 HTTP CONNECT 代替。

## 独立流量采集与最小验收

- 采集常驻于 Agent 执行网络的入口，独立于 VPN/SOCKS 是否配置和连接状态。CTF 的 Lead、Worker、helper 如存在，黑板的 Agent，按各自实际执行绑定及来源归属；现有 Assignment/epoch/veth 可作为原证明的一部分。默认路径在来源汇聚前采集，VPN 在 VPN 加密前、SOCKS 在代理汇聚前采集；这里的抓包对象是执行环境实际网络流量。模型、MCP 与平台控制调用沿独立控制路由，保留按原 Task/Agent/调用身份可关联的观测；系统探针单独标记。共享出口整包不能冒认某个 Agent，也不拿控制调用记录冒充执行流量。配置缺省不能关闭采集；采集失败、已知丢包、未知或部分覆盖必须可见，不记成零流量或完整归档。
- 需要变更网络路径、暂停恢复、归档或停止时，封闭原执行来源及许可，保留原绑定和归档证据，获准的新执行以新身份接续；不得用新来源填补旧缺口。停止按实际资源终态执行，不为了等归档无限阻塞；缺证单独记录。命令记录只读，不做审查或处置。
- VPN 加密前抓到的应用层 TLS 仍可能是密文。首片只承诺实证覆盖的 IPv4 TCP 路径及原包/连接归属，不承诺 TLS 明文、解密、完整载荷或全协议覆盖。

| 必要路径 | 最小证据 |
| --- | --- |
| CTF 默认网络 | 同一 CTF 创建入口可用；不拨 VPN；命令正常执行且有原 Agent 来源归档。 |
| CTF 共享 VPN | 同入口由 Lead 配置；Worker 可访问范围内新题地址，抓包在 VPN 加密前并匹配真实来源；覆盖一次停复和停止。 |
| 黑板默认网络 | 未配置平台出口仍可执行，Agent 来源可归属并归档。 |
| 黑板 VPN | 已配置时强制走 VPN，绕过失败；原 Agent 流量在 VPN 加密前可归属。 |
| 黑板 SOCKS | 已配置时走真实 SOCKS5 TCP，直接绕过失败；代理汇聚前可归属。 |

五条为产品验收覆盖，不要求重复五套端到端矩阵。优先复用与最终合同、执行路径和来源等价的 P4i/P4l 及旧黑板实证；合同变化或现有证据缺失的地方以同一隔离环境中的组合场景补测。身份链、失败保留和归档停机选代表路径证明，另在每条网络模式确认实际来源。
