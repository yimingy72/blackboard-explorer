# P7 · 单一平台与共同 Pi/OpenSandbox 实施报告

当前为候选验收记录。两站现场尚未切换、未导入配置或停止原应用。原工作区 `30ce04a3`、默认索引和 104 项用户变更保持原字节、模式与状态；设计独立提交 `abc91171`、`47f1d274`，产品在隔离候选开发。

## 实施

- 一个账号与任务入口，创建显式选择黑板或原生 CTF；两模式独立验证发布。公共应用只用本地模型/MCP vault 与同一账本，保留原站点账务身份，不联网拼接旧站复盘，也不将旧价目或未知费用换算为新值。已移除旧模型、MCP、复盘站间透传。
- 普通黑板沿用自己的 Fact、Intent、Explore、Derive 和 Close，复用同一 Pi Runner、OpenSandbox 资源、逐 Agent 流量和只读命令。普通的 Task/AgentRun/SDK/确认游标是实际授权源，不伪造 CTF 成员。原已发布外部工具权限保持明确范围，默认不自动授予新权限。
- 只读记录源自已确认的 Pi journal。普通工作台复用命令抽屉，只有可验证原件时提供原始会话下载；只读复盘把经过 SHA 校验的原历史作为有界资料，旧工具调用不进入可执行状态。独立 tar 保留原 `.bbx/task.json`、manifest、实际证据/附件和原 JSONL 字节；历史元数据不恢复进求解工作区。
- 任务和原 Close Agent 在同一实际裁定事务结束，并登记原资源停止意图。归档验原停止、PVC/运行代次及对象完整字节；续跑使用新的原生身份，保留旧账、会话、流量和工作区；缺原证据或存在未知效果时不重发。旧黑板公共 Docker 创建/启动回退及旧执行网络回执写入口已在候选移除，旧证据可继续读取。

## 已取得的证据

- 隔离同一 Blackboard、PG 和监督者，两种任务真实并发执行。`shared-smoke-receipt.json` 记录黑板 8 次、CTF 6 次合成模型调用；原生工作区命令、78,000 字节完整文件、Fact、裁定/最终报告、原资源停止和归档、原附件/证据、原会话读回通过。无商业供应商请求。
- `workspace-receipt.json` 记录实际保留 PVC 的受限读取、原归档相同字节复用、替代工作区材料读回、恢复 ACK 丢失后不重写。它是独立真实资源证明，不能替代同站 Task 显式续跑的联合验证。
- Core 定向真实 PostgreSQL 覆盖定点迁入、旧执行拒绝重启和旧数据读取、附件重试、预算追加幂等、原 CTF 发布、原角色控制、关闭、归档与新代次。旧入口退役核心定向 8 项通过；新增原会话 SHA 读回和导出元数据实际 PG 2 项，复盘与独立归档 37 项通过。前端 TypeScript/ESLint、命令抽屉 Ant Design lint 通过。测试均用候选 Python 源码和合成数据。
- 最终 `make check`、联合显式续跑及强制网络现场候选验证、精确制品独审和生产切点回执尚需补入本报告。不会以只读盘点、局部验证或源代码代替这些验收。

## 切换与保全

[方案](P7-单站点与共同Pi沙箱执行-20261111.md)约定保留主账号、原主 PG/MinIO、vault、模型草稿、原账和原普通配置。定点迁入只写副站原 `ctf@1`，重复接受完全同值，任何来源业务数据、身份、版本或配置差异会阻止迁移。运行用 `bbx_blackboard.site_migration` 的默认检查和显式 `--apply`；它不做通用非空合库。

本地执行单和 CMS 备份准备见原工作区 `.data/p7-unify-20261111/cutpoint-runbook.md` 与 `p7-cutpoint-backup.py`。实际由 Runtime 在新鲜停写窗口核对原容器、PG/MinIO 数据与已验证备份；旧 SQLite/PVC 和两套原卷不销毁。若新 schema 已变化，即使没有用户写入也要先在克隆验证旧版本兼容性；有新用户写入后向前修复，不拿旧备份覆盖主数据。
