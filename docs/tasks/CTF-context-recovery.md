## 依据与核实

工作树 `ctf-cooperation` 保留全部前序未提交改动；前端仍使用已发布的 B 自由拓扑。已读 AGENTS、HANDOFF、CTF-team-mode 提案及前序 cooperation/prompts-tools/batch-hardening 合同与报告。原测试报告和判分产物保持只读，不读取答案或运行靶场命令。

最新任务 `d11f03ea-e182-4a3a-8bf9-511e9995c490` 的 465 次成功模型回复都有用量，任务/成员/回合/trace 合计一致：输入命中 2,102,825，未命中 7,113,978，命中率 22.82%。264 次调用排除前缀增加，命中率 3.60%；其余 201 次为 49.87%。保存的模型窗口为 1,000,000 token，任务要求 max_steps=4000/context_threshold=400000，运行时却只取 profile 的 60/128000，并将阈值当字符预算使用。部署相关源码散列与检查代码一致。

缺 claim_turn 不证明 coordinator hang（只认领 ready_member_ids）；满预算 15–20 题不能从一次运行线性外推。按报告补全各来源范围并强调 owner 完成后的状态更新，不把候选自动当可信通过，不写入题库名称、答案或漏洞路线。

## 实施范围

1. 任务级有效 max_steps/context_threshold 保真；创建时省略值继承选定配置/模型窗口，超窗明确报错，不静默降级。已保存任务快照和账本不修改。
2. 以模型可见输入的 token 保守估算管理窗口，计入固定提示与工具 schema、输出预留和一次安全余量。工具结果预览持久且稳定，原文/工具结果配对/会话保留；历史超限后批量降到低水位，避免每次调用改前缀。
3. 复用 MAF 公共分组组件，保留 CTF 持久 cutoff、预算、generation、receipt 和新输入不可静默裁掉的业务规则。框架默认压缩会变化旧前缀或增加摘要模型调用时不直接启用，不升级依赖。
4. 封锁后新回合建立稳定任务目标与黑板恢复上下文；超大新输入仍阻挡。每成员每 run context_blocked 最多一次、step_limit 最多三次自动同任务续跑；显式 resume 重置次数并保留 Session。新用户消息可请求恢复并返回明确投递状态。保持 Lead 派工，后台不擅自分配题目或变更验收结论。
5. 协调器慢等待增加阶段观测，不依据日志缺失盲取消正在恢复/排空的操作。窗口较小的模型统一限制请求与预留的输出量，保留输入空间。

## 验收与发布

运行有实际保障意义的离线回归及隔离 PostgreSQL/执行环境检查，完整 make check/test-integration；不调用真实模型，不重新跑或续跑用户任务，不读写 .env，不改 docs/design、依赖或 Git。部署前核对无活动任务，更新服务源码镜像与新任务模板，保持 B 前端资源、模型/价格/工具配置、任务/会话/数据卷/归档，检查发布前后指纹。最终中文报告区分实测缺陷、推断和未验证的求解效果。
