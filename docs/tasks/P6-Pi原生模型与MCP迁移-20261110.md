# P6 · 移除 AgentGateway，迁移到 Pi 原生模型与独立 MCP

状态：开发前方案，已通过多 Agent 方案审计；实施前的环境、身份和运行门槛仍需真实验证。基线 `30ce04a343fafe4e4df7f4c967e9b93d17db9c64`。用户的新架构决定替代 P3c–P5e 对 AgentGateway 的后续投入；本轮不写产品、不停止服务、不切流、不删数据、不改正式设计。工作区原 102 项保持原样。

## 1. 目标边界

平台用现有用户账号提供模型接入、费用与额度，以及独立的 MCP Server 管理与工具可视化。Pi 负责实际模型协议、鉴权适配、流解析和原生用量计算；平台只负责可信模型选择、凭据、任务权限、发送许可和账本。退出 AgentGateway 管理页、虚拟 key、策略代理、价格目录刷新和 MCP 路由发布。不部署替代的通用模型网关，也不复活旧的零费率直连配置。

主站既有 `platform_configs` 是两站模型目录、MCP 注册与加密凭据的唯一权威。模型项保存平台 ID、用户可见别名、Pi API 与 provider、实际 provider model ID、可信 base URL、能力和限长、凭据引用、已批准价目版本。当前没有完整管理员 RBAC；实施前核对现部署的稳定用户 ID，以明确的 UID 允许列表或现有单用户操作者约定授权主站写入。Agent、普通登录用户和通用服务身份不因此获得写配置或解密权限。两站通过受信服务接口读 `(authority, modelId, revision)` 冻结版本，执行用户只选已启用模型。不建独立副目录，不跨库双写，不合并数据库或重建控制服务。长期 provider 凭据仅对受信 Runtime 发送者按模型范围可用。配置/日志/会话/浏览器只见掩码或引用；求解、整理和复盘共用对应模型凭据，不再用 AgentGateway 的 per-key 语义隔离。

## 2. Pi 接入与费用账本

| 调用面 | 现状 | 目标 |

| Native CTF Runner 主/子 Agent、压缩、终态复盘 | `task-runner/src/session.mjs:126–133` 用 Pi 1.5 强制 OpenAI 兼容和零价；`model-boundary.mjs` 的 journal/许可/回执已有发送护栏，但费用由 AgentGateway 对账 | 保留 Pi 1.5 会话、工具循环和 journal；长期 provider 凭据留在既有可信 Runtime 执行侧，复用 Pi 发送 worker。Runner 通过现有私有 scoped 调用接口申请同一调用许可，收 Pi 的事件/最终消息；仅给 Runner 短期用途凭证，不传 provider key，不保留可公开调用的 `/v1/chat/completions` 代理。压缩和子 Agent 必须穿过同一边界。 |

当前前台和后台 hosted helper 均在 Runner 信任边界内运行；后台 helper 的结果由父方异步接收，不能视为独立的凭据隔离。不要给 Runner、helper、执行 Sandbox 或客户浏览器挂载 vault。只在已有可信 Runtime 环节做出站域名/端口限制与安全校验，模型地址由批准的目录绑定，不信任请求指定的目标、不跟随跨源重定向、不放行本机/元数据/内网等非授权目标。保留调用超时、取消、持久 journal、原 lease/epoch 与重放保护。两套 Pi 不因这次迁移强行升级；先验证 1.4→1.5 的私有事件合同和真正 SDK 回调，再决定是否合并锁文件。

每次**实际 provider 调用**在所属站的 Blackboard 现有 PG 持久登记一次，额度和费用也由该站原子更新。主站操作者主动演练为独立 `purpose=playground`：原账号和 request ID 绑定模型版本及单轮文本摘要，没有 Task、Agent 或额度；原结果和已观察费用同一账本终态保存，未知不重发。其他用途仍由 Task 冻结授权。`site_id` 由受信部署绑定，不读 Agent 提交值。以 `(site_id, callId)` 唯一，绑定不可更改的用途、输入摘要、冻结模型与价目、独立 attempt ID 和 provider request ID（如有）。Task 用途额外绑定 `taskId`、`agentId`、`turnId`、原 journal、owner/epoch 及动作（普通 turn、压缩、分支总结、helper 等）。原身份生成并持久化在实际发请求之前，不能靠重启时生成新 ID 覆盖。成功重放只回原账本结果或已持久结果，不重复发请求；同 ID 改 payload/用途/模型拒绝。关闭每个 SDK 隐式付费重试；任何明确允许的新尝试必须单独许可、占额度和记账，未知发送结果不得重发。

**摘要路径**：普通 1.4 只运行 `pi-agent-core`，现有宿主截断/压缩不是自动付费摘要；任何新增模型摘要与现有成果整理仍走同一可信 Runtime worker。固定 1.5 的 `AgentSession` 手动和自动压缩、分支总结都将当前 `agent.streamFunction` 传入摘要代码；底层 `completeSummarization` 在缺少此参数时会直接 `completeSimple`。Hosted helper 均通过 `prepareSession/installSession` 安装同一宿主边界。SDK cache warmer 可直接调用 `ModelRuntime.streamSimple`，保留当前禁用；不允许任意 extensions、provider fallback 或 Runner 直接出站，不允许 SDK 隐式付费重试。摘要和主调用各绑定稳定身份；不能以 `sessionId` 是否存在推断不限额复盘。可信 Runtime 记录覆盖所有实际发送，不能证明不绕过的路径先关闭。

1. **用量和费用来源**：复用 Pi `AssistantMessage.usage`、`calculateCost` 及 SDK 的 provider 事件。用适配器可证明的完整终态用量与原始数值关系校验（输入、缓存、输出、总量），只保留必要数值和引用。普通 `pi/worker.mjs` 已接 `onProviderStreamEvent`，但现有输入/输出布尔与 Pi 归一化结果不能替代完整终态证据：SDK 可能钳制负数或重算总量，断流也可能留下部分累计值。不要用 Pi 初始化的零值、`stopReason` 或最终消息存在推断计量完整。规范化输入、输出、缓存读写及推理子集一次；费率或币种缺失、超时中断、计量字段不全按 `unknown`，不记成 0。某协议不能证明用量完整时先明确不支持带额度，不能为它新增自研 SSE 计量器。
2. **来源分层**：若已验证该 provider/协议确实回传可信、同币种金额，可标 `provider_reported`，保留外部引用。完整用量及冻结 USD 价目由 Pi 计算的金额标 `estimated`，表示平台核算，不冒充发票；同一行以批准的来源进入本地额度，不能同时累计两种金额。明确免费/实报零且证据完整才允许零。不得把别名当作官方费率关联，`BaiZhi/deepseek-flash` 的中转费率由中转商实际报价或受权用户确认。保留 Pi 的原始缓存分类（含 `cacheWrite1h`），不用现有 Python 普通用量 DTO 折叠后的字段重新计价。无法表示的条款不静默转为基础价，不复制旧 Python 计价公式。数据库金额用 Decimal/Numeric 聚合，不把 JS 浮点总额冒充精确发票。
3. **并发额度**：维持已交付的累计费用停止阈值：所属站 PG 在行锁内检查已核算累计、许可有效性和未决费用保护，只有低于阈值才给新的唯一调用发许可；记录占用后释放数据库锁，保留既有多席位并发。已在途调用可能越过阈值并须如实结算，页面明确这不是硬封顶。只复用已有可证明的预留，不能拿平均值或最大上下文长度盲算，不把严格预留当迁移先决。可信 worker 在放行最终消息前持久提交用量、价目、结算和占用释放；只对明确未发送的调用释放，未知保留并阻断不安全新派发，旧 owner 只可提交原调用证据。严格封顶、精确 token 上界、各可达 tier/缓存时长的保守上界及向上舍入是后续独立能力，不在本轮扩大。
4. **去重和用途**：子 Agent 实际调用、压缩/分支总结各凭原 `callId` 单次记账；父工具结果中的子 Agent 汇总、Pi `turn_end`/`agent_end`、复制的分支条目或 `getSessionStats()` 都只供显示/核对，不能再次入账。用户主动发起且通过原终态/只读权限的复盘不设金额上限，与任务和成果整理分账。跨站按同一受权用户身份和 `purpose=review` 聚合，以 `(site_id, callId)` 去重；任一站不可用时标明覆盖不全，不把缺项记作零。自动/陈旧任务消息不能借复盘绕过额度，复盘仍执行访问控制、原只读工具限制与调用追踪。额度增加、续跑绑定原额度与原调用 ID，不重置累计花费或把未知当作新额度。

## 3. 独立 MCP、身份与恢复

- 保留平台已存在的外部 MCP Server 管理、凭据加密、版本、工具发现及角色授权，显示版本、授权角色、工具 schema 摘要、认证是否配置、实际执行网络和独立的发现/连通结果。现有管理/探测入口需先收紧到管理员并限制可信 Runtime 出站目标，任务仅消费已发布版本。普通 Explore 与原生 CTF Lead/Worker 都可使用明确发布到该角色且为该 Task 冻结的外部工具。普通从可信 Runtime 执行；原生通过既有 Business-v2 由 Blackboard 受信出站执行，helper 不继承，详见 [P6b](P6b-独立MCP管理与双目标接入-20261110.md)。发现权限与实际执行分开；首期只保留现用 Streamable HTTP 与静态认证，不启用任意项目扩展、stdio 命令、环境 MCP 配置或默认工具自动执行。
- Native Runner 用现有 `@earendil-works/pi-mcp@1.5.0` 的 `McpClient`、`StreamableHttpTransport`、`toLlmContent`；普通 Runtime 保留已用 Python MCP SDK。Pi 官方高阶扩展存在但默认工具分发不携带 BBX 的 permit、callId、journal 和业务 fence；第三方 adapter 不装入产品执行链，不替换当前窄调用护栏。
- 移除动态 AGW MCP 路由后，受信 Runner 分别访问 Blackboard 私网 `/api/tasks/{tid}/business-mcp/`（按 lead/teammate）及同 Pod Sandbox MCP sidecar 的受限 loopback（helper 只访问其获准的 Sandbox）。保持 inbound、report、执行环境凭据分离；initialize/list/call 都要验证短期能力和 Task、binding、role、SDK session、owner/epoch，执行额外核对 permit 和原领域事务。只在私网服务隔离验证通过后去掉旧 gateway backend-secret。拒绝跨目标、浏览器来源、重复身份头和重定向；保留冻结的工具别名、SDK checkpoint 与 journal 哈希。旧身份在暂停、租约失效、恢复换代、停止、归档后不能发起新调用；迟到的原回执只能绑定原调用证据。独立 Sandbox Pod/execd 不获得模型密钥。保留单写 journal/PVC、清理和回收证据；未决调用不能靠删除 AGW 或重启消失。
- 在任何 direct 切换前，业务与 Sandbox 两目标各上线独立的新 issuer/audience（例如 `bbx-runner-business-v2` / `business-mcp`、`bbx-runner-sandbox-v2` / `sandbox-mcp`）。两端严格拒绝旧 `aud=mcp`、交叉用途及旧入口凭据，不能等 epoch 变化后才拒绝。短时间新旧路径共存时分别验签，不能同时给同一操作两个发送权。

## 5. 开发验收（只跑必要检查）

1. 用合成 provider 覆盖普通和 Native Runner 两条 Pi 入口：模型选择、普通/工具回合、自动或手动压缩与分支总结、hosted helper、缓存/推理用量、`estimated`/明确零/无计量未知、同一 callId 二次回执。按 turn、summary、helper 逐笔比对实际收到的 provider POST、一次发送许可和可信费用回执；未发送取消单列，SDK 统计变化不作为验收证据。
2. 一个并发事务用例覆盖阈值前多席位可进、阈值后拒绝新调用、在途越线如实结算、未知保护、暂停续跑、防自动重试和跨站不限额用户复盘；验证旧 USD/CNY 展示不变。一次无权限/错误用途验收检查低信任容器不能拿到 provider key、不能选择任意出站目标。
3. 一次隔离 Native MCP 验收同时覆盖 lead/teammate Blackboard 工具、helper Sandbox 工具、跨角色/过期 owner 拒绝、暂停恢复同 journal、工具调用去重及已执行结果回放；不运行真实攻击任务。加一份旧暂停快照，验证在新执行代次安全恢复，或因无法证明映射而明确阻塞。浏览器验证用户登录后的模型、费用、MCP 发现/授权，以及旧账只读。完整验证终态是两站不再有 AGW 依赖且未调用真实付费模型。
4. 实施提交前按仓库规则运行 `make check`；方案轮只有只读审查和文档差量检查，不运行大套件，不安装候选插件。详见[开发前审计](P6-Pi原生模型与MCP迁移-20261110-audit.md)。
