# 任务 M4 · 工作台

依据：`docs/design/黑板系统实现架构.md` 第 8 节（前端）、第 9 节（可观测性）；`docs/design/黑板系统开发方案.md` M4 与检查点；`docs/tasks/M1-W-report.md`。

前置：M1-W 与 M3b 已合并。先阅读 `AGENTS.md`。

## 范围

`web/` 的工作台功能，以及它需要的少量后端接口（`services/blackboard` 中新增，只读）。

## 已定的实现决定

1. 时间轴回放复用 M1-W 的 `reduce(events)`：滑块选定 version，用 `events.filter(v <= version)` 重建视图。
2. 证据查看器按 `evidence.type` 选渲染器：`http`（请求 / 响应两栏）、`log`（关键字高亮）、`code_ref`（文件与行号片段）、`script`（脚本与输出）、`command_output`（命令 + 输出）、`text`；超过 200KB 只显示头尾并提供下载。
3. 报告页用 `react-markdown` 渲染 `reports/{task}.md`。
4. workspace 目录树：blackboard 新增只读接口 `GET /api/tasks/{id}/workspace/tree` 与 `GET /api/tasks/{id}/workspace/file?path=`，从 MinIO 中的 `workspace/{task}.tar.zst` 读取（服务端缓存索引）。
5. Profile 管理使用 M1b 的 `/api/profiles` 接口；新建版本时在前端做 YAML 校验，服务端以 `AgentProfile` 为准。
6. 节点超过 300 个时默认折叠已关闭意图的下游。
7. Playwright 冒烟测试放在 `make web-e2e`（不属于 `make check`），浏览器下载使用国内镜像（`PLAYWRIGHT_DOWNLOAD_HOST`），由用户运行。

## 任务

| # | 内容 |
|---|---|
| U.1 | 详情面板：fact（证据列表、争议链、被谁依赖、满足了哪些验收项）、intent（notes、attempts、结论事实、retry 链）、agent（步数、上下文、结束原因、回执、工具调用列表、花费） |
| U.2 | 证据查看器（六种渲染器） |
| U.3 | 顶栏：验收各项状态与最近一次裁定的理由 / 缺口、预算仪表（金额、缓存命中率）、启动 / 停止 |
| U.4 | 底部抽屉：事件流、Agent 列表、裁定历史、时间轴回放、workspace 目录树与文件预览 |
| U.5 | 报告页 |
| U.6 | Profile 管理：版本列表、编辑、对比、设为默认 |
| U.7 | 过滤与折叠；大图性能 |
| U.8 | 后端只读接口（workspace 树与文件）及其测试；OpenAPI 更新 |

## 完成标准

1. `make check`、`make web-check` 全绿；`make web-e2e` 冒烟测试可由用户运行通过。
2. 用户可执行的检查点：对一次玩具任务的真实运行，只用工作台就能回答——任务为什么结束；每条结论依据哪些事实和证据；每个 Agent 做了什么、为什么结束、花了多少钱。
3. 报告 `docs/tasks/M4-report.md`。
