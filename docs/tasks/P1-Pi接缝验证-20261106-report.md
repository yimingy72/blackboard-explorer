## 2. 验证方法与实际结果

在仓库根目录运行：

```sh
cd services/agent-runtime/pi-seam
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm ls @earendil-works/pi-agent-core @earendil-works/pi-ai @earendil-works/pi-coding-agent
```

`npm test` 先从锁定源码复制隔离 fixture，再应用明确 patch；原安装包和生产依赖不被改写。测试只访问随机本地端口，安装后的测试不需要外网。

已审基线结果：**13/13 通过**，包含 8 个主 SDK/工具/故障场景与 5 个官方能力/前后台补丁场景。初版 11 例通过后，独立审核指出工具 unknown 应冻结全部准入、挂起安装取消不能发布；补齐共享闩锁与安装前后屏障后，主 SDK 8/8、插件 5/5 均通过并获独立复核。直接依赖及插件 peer 统一复用 Pi 1.5.0，没有混入旧生产目录的 1.4.0；不据此报告生产性能指标。

必要证据对应文件：

- `src/gateway-session.mjs`：公开 SDK 接入、日志确认、错误流、最终 HTTP 准入与身份、usage unknown、可信工具 invocation 与结果存储。
- `test/gateway.test.mjs`：主/手动/自动压缩、普通 subscribe 不等待、持久失败后冻结、取消、429/503/断流、缺 usage、非协议 source 异常、跨 turn ID 碰撞及结果重放限制；真实 SDK 中副作用后保存失败拦住同批下一工具/新 ID/模型，并验证已知业务拒绝可继续。
- `test/plugin.test.mjs`：原版公开 API 拒绝新合同、补丁前台、独立后台存活与回收、独立后台确认失败；真实 factory installer 挂起时分别 dispose/abort，拒绝发布、无 session_start、raw dispose 恰一次且清理宿主引用。
- `test/fixtures/`：可信 required host 模块、真实插件 child 创建与独立进程 supervisor；模型和工具都由本地假服务提供。
- `patches/pi-subagents-0.85.0-session-host.patch`：可单独审阅的上游提案；`scripts/prepare-plugin-fixture.mjs` 核对版本/提交并只补隔离副本。

本目录全部新增实现，不涉及根 Python/Web 代码；按照本轮授权仅运行上述必要检查，没有重复运行已知含旧 WIP 失败的根 `make check`。最终提交仍由主任务结合原有检查结果与独立审核处理。

## 3. 公开能力与补丁能力的边界

**官方 pi-subagents 0.85.0 尚未通过 G3。** 原版公开 required-child-extensions 接口不接受 `sessionHost`，普通 subscribe 不等待，ExtensionContext 也不能直接获得原始 session.agent；强制加载扩展不自动产生硬屏障。Pi 的 before_provider_request 等扩展异常可能被捕获，不能作为唯一准入。

本次最小补丁复用既有 required extension 的 canonical 路径、身份检查、所有 Runner 限制和序列化快照，仅增加明确宿主安装阶段及其取消检查。公开类型说明该模块必须导出 `installChildSessionHost({ session, run })`；实际 child factory 在任何 session_start 或首次 prompt 前等待，缺失/抛错清理并拒绝。安装等待期间被 dispose/abort 的启动在继续后也必须 shutdown，不能把未加入 live 的 child 发布。后台收到相同强制快照，因此不依赖父进程内存里的 callback。

为测试尚未公开的安装位置，隔离 fixture 导入了上游内部源码；生产 `src/` 不导入插件私有模块，也未改 npm 原包。补丁未提交上游、未发布、未接入生产。`helperModes` 的 foreground/background 都保持 **false**，独立目录未被生产路径导入。

上述基线后台验证使用真实 runner launch builder 与 child factory 加独立 Node 承载，覆盖日志/取消接缝；它本身不等同完整 daemon/watcher 验证。第 6 节在该基线上补齐两条真实 daemon/watcher 代表路径；跨宿主接管或 Kubernetes supervisor 仍未通过。

## 4. 偏差与待决

1. `confirmJournal` 为 P1 故障验证全读、全 hash，代码已标注 ponytail 限制；未实现生产增量 confirmed_seq/hash，也不把本机 fsync 推导为目标 PVC 已具备相同持久性。生产接入须补增量游标/哈希链、单写者租约及目标存储故障验证。
2. `FileReceiptStore` 和假 HTTP 准入账本是隔离 fixture。已证明单次预留、发送意图先落盘、结果先落盘和未知不重放；未实现生产价格上界、币种/图像/缓存定价、并发公平队列、Task epoch、Assignment/generation 与已有数据库事务的完整整合。
3. 首版窄实现只验证获准 OpenAI-completions 网关路由；其他 provider/API、虚拟模型及额外摘要后台路径未开放。SDK cache warmer、自动/摘要/provider 重试全部关闭；实际 agentgateway v1.7.0 路由、凭据及重试部署配置须另验。本次服务模拟网关，没有运行真实 agentgateway。
4. 工具 unknown 仍需后续既有 invocation 对账服务决定；已发送无结果不会自动执行第二遍。独立 cleaner/远程命令收尾属于 G1/P3，未在此样例中冒充完成。
5. 不读取 `.env`、用户 Pi auth/settings 或真实密钥；未调用真实模型、靶场、Docker、Kubernetes，未全局安装。除固定依赖获取外无外网业务调用。

### 6.2 真实公开路径与结果

增量只新增 **2 个场景**，`npm run test:daemon` 实际结果 **2/2 通过**，运行约 13.6 秒；该命令本身先重建候选包再执行测试。共享 fixture 调整后，另复核既有 gateway 测试 **8/8 通过**；未重复扩展插件矩阵或根全量测试。收尾检查无本批父宿主/daemon fixture 残留进程。

最终定点审核另要求失败清理不能立即删除仍活跃 daemon 的目录，故只追加 **1 个清理故障回归**，不增加业务矩阵。相关 `node --test --test-concurrency=1 test/daemon/cleanup.test.mjs test/daemon/public-daemon.test.mjs` 结果 **3/3 通过**，约 14.8 秒；候选包及其摘要未变。

| 场景 | 真实路径和证据 |
| --- | --- |
| 正常后台闭环 | 加载候选包公开扩展入口，公开 required-extension/capability-ceiling API 限定 helper 与 bound_tool；SDK 公开 `getToolDefinition("subagent").execute(...)` 调用真实注册工具。工具进入原始 async-execution，启动真实 subagent-runner-bootstrap/daemon；helper PID 与原始 status.pid 一致且不同于父宿主；假远端工具仅执行一次、子模型两次；真实 result-watcher/notify 交付恰一条完成消息，父模型经网关准入唤醒恰一次；原始 process-terminal 为 observed，runner exitCode 为 0 |
| 取消/失联且不重放 | 假远端副作用已完成但回复挂起；宿主撤销父子模型/工具准入、abort 父会话，再经同一公开工具调用 stop。真实 daemon 取消、watcher 交付结果通知，获得 observed 进程收尾证明；原持久 invocation 保持 sent/unknown。公开 resume 明确抛出“was stopped and cannot be resumed”；副作用和子模型发送都只有一次，已停止父会话没有新增模型发送 |

接口事实：插件把 subagent 声明为 model-only；公开嵌套 `ctx.executeTool` 会按 Pi 设计拒绝选择它。本增量由宿主通过 SDK 公开 ToolDefinition.execute 及公开工具上下文调用同一工具执行器，由插件本身处理 agent 解析、权限上限、启动、状态、stop、resume 和通知；没有导入私有 child factory，没有替换后台执行模块、伪造状态文件或手工发通知。**未验证完整父模型生成 subagent 调用并完成其原生工具循环**，不以本节结果冒充该项已通过。

父宿主及其真实后台使用独立测试目录与干净环境，HTTP 仅允许本地假服务。teardown 不按旧 PID 直接发信号：只调用插件公开、具身份校验的 stop，然后有界等待与启动时 run ID、Runner process instance 都匹配的 observed 关闭证明。stop 失败/超时不视为已停；无法取得匹配证明则抛错，阻止 harness 删除目录。新增故障回归调用真实 harness 的目录清理回调，注入 stop 失败和属于其他 run/Runner 的 observed 文件，确认清理失败且整个运行目录与证据原样保留。

### 6.3 阶段结论与剩余边界

已审基线 **13/13** 与后续公开路径增量 **2/2** 分开成立；官方未补丁 0.85.0 仍不支持该宿主合同。锁定补丁候选包可供阶段集成审核，生产 foreground/background gate 仍为 false。

两条代表路径已覆盖真实后台启动、结果 watcher/通知、取消与未知不重放；并未覆盖插件的全部工作流、外部 Runner、并发多后台、进程硬崩溃后的跨宿主恢复、真实 agentgateway 或 Kubernetes Task supervisor。父 SDK abort 本身不自动取消 detached 工作；本场景按平台 STOPPING 合同显式撤权并调用公开 stop。生产开放仍须接 Task epoch/席位、预算事务、命令 cleaner 与经审核的 Runner 构建。
