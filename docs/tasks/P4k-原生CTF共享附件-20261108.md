# P4k：原生 CTF 共享附件安全物化

已审实施方案，基线 `adf416e`。延续[平台架构重构方案](平台架构重构开发方案-20261105.md) R6 与 §7.3、[P4j 原生创建](P4j-原生CTF创建与流量产品接入-20261108-report.md)。本轮只补用户创建时选定附件进入原 Task 工作卷；不接入 VPN/真实来源，不提供逐题文件 ACL 或命令审查处置。

1. **发布、创建与共享**：专用原生 CTF 的管理员发布明确启用 `shared-inputs-v1`，正常发布验收额外绑定实际 Host 镜像和此能力。现有 P4j 发布默认仍不接附件。GET 能力给出原生单件 16 MiB、累计 24 MiB、最多 20 件；上传页和服务端同时按限额拒绝，创建事务再次核对。沿现本人附件组锁，按选中 ID 冻结文件名、生成路径、精确字节数及 SHA-256；非空原生附件仅接受明确提交的全 Task 共享集合（`public_input_ids` 与选中集合相等），不会静默扩大访问。现用户任务下载保持；新原生附件组管理/下载 API 不授权 Agent，当前 Agent 由低 UID 工作区或现有受信任务读权限访问。legacy 50/200 MiB 及原输入组 idempotency 不变。
2. **原物理门槛**：以原 report key 和仍持有 PostgreSQL 原控制锁的当前 Runtime 校验 Host、Task、operation/resource generation、实际 Sandbox Pod/CID、execution context、原 workspace PVC UID。附件计划仅暴露冻结 ID、文件名、路径、大小与摘要；字节接口只能取得已领取的原 attachment ID 对应对象，不允许请求任意 URI。冻结文件摘要与资源绑定摘要分开；首次原生 material 之前可一次领取，所有完成证明都精确绑定同原 manifest、PVC 和 Sandbox。旧 no-attachment Host 配置与请求序列化不变。
3. **安全发布**：Host 在 pre-ready 使用官方 SDK 向固定 root-private scratch 写单个有界二进制文件，独立检查长度/SHA；受信固定程序按有界 manifest 再核真实 staged FD。对子进程显式清环境并以同 Task UID/GID 10000、无 capabilities 及 no-new-privs 写原工作卷；路径逐层以无跟随的目录 FD 打开，拒绝特殊文件、已有目标、冲突与越界，O_EXCL 构建临时全目录，fsync 后 no-replace 原子发布 `/workspace/shared/inputs/<uuid>/<filename>`，不解压或执行附件。不扩 64 MiB 原 PVC 规格；固定 root 暂存和工作卷各最多一份原数据、合计最多 48 MiB；安装前核工作卷至少有附件合计大小加 16 MiB 可用，空间不足不启动。共享文件可由同 Task 低权限团队成员读取及按原权限修改，不声称 Lead 私有。已有目标即使内容相同也不作为本次成功证据。
4. **恢复及错误**：独立门控 Host ready、Blackboard material（在 owner/预算/路由前）和 activate。原本地成功回执先落再对账 Blackboard；若响应丢失或控制器更换，只读对账原结果，不重新领取或覆盖。冲突/坏字节/无空间/未知都不发执行凭据，原对象和证据留存；stop 与附件 I/O 独立，不等待慢传输。暂停同 Sandbox 不复制；P4f 在原 PVC UID 保持不变时携带历史首次成功证明，不复核或补写团队之后编辑、移动或删除的内容。原结果不确定时不把无声退出当成功。
5. **必要验证与交付**：一条真实 PG 覆盖选择/共享、事务与原对象/门控/同 PVC 回执；一个 importer 文件系统定向测试核路径、无覆盖及坏字节；一个定向 Web 场景核共享提示/限额/重试；一个独立真实 Kubernetes Task 从用户上传二进制/空文件、公开创建、原工作卷低 UID 读取到正停止。沿用 P4j 已验证的重建 Kali 工具层及捕获能力，派生新的固定安装器镜像与 Host；保留原两个 P4j 制品。无真模型、VPN、外部靶场。干净候选 `make check`，独立核 exact 树后只在本地提交；保原 38 tracked、72 untracked、两个交付 Kali 镜像，不推送、不读 `.env`、不改正式设计或 AGENTS。

发布沿 P4j 管理员文件：仅在实际部署并验收后添加顶层 `inputs_profile: shared-inputs-v1`，使用已验的新 `traffic_sandbox_image` 与 `sandbox_host_image`。同目录的验收 JSON 添加相同 `inputs_profile` 和精确 `inputs_host_image`，更新原文件 SHA-256 引用。Runtime 原资源配置不新增 profile 字段；旧任务的已冻结配置仍按原合同读取。
