# P4m2：黑板任务网络与逐 Agent 采集

已审实施方案，基线 e23ef9d。续接 [P4m 任务网络职责](P4m-任务网络职责分离-20261109.md)。本片完成旧 Docker 黑板的三条实际路径：平台未配置时，任务仍用默认网络并采集；平台配置 VPN 或 SOCKS5 后，在 Agent 权限之外强制使用，不能改、关或直连旁路。命令记录只读，不做审查或处置。不迁移原生黑板，不重做 P4m1。现有原生 CTF 专用发布仍独占其执行部署；普通黑板用独立已支持的 legacy 部署，暂不改变二者共用的 Runtime 调度锁或承诺同一部署混跑。

## 服务端合同与版本门

1. **由平台选择，普通创建不增加字段。** 在现 POST /api/tasks 黑板分支的同一创建事务冻结新的 legacy 执行网络合同。平台可不提供 VPN/SOCKS 发布文件，合同此时为 default；若提供则只支持一个由管理员发布的固定 VPN 或 SOCKS5 策略。显式配置无法验证时拒绝进入执行，不回退默认。Task/浏览器/Agent 不能覆盖策略，egress_allowlist 仍仅是旧记录字段。版本、模式、策略摘要与旧用户请求摘要分开，原附件组幂等重试返回原 Task，即使部署配置之后变化。原任务历史 null 合同按原版本读取；不改既存执行资源、原模型/MCP 路由或历史采集归属。已配置强制网络的新版部署不能把历史未冻结任务的新启动或恢复作为绕过入口；历史已运行资源仍可停止、归档。
2. **冻结与投影分离。** 新的服务端 Task 字段（暂定 legacy_network，独立于公开 params 与 Task 事件）保存不可变 snapshot：version = legacy-agent-network-v1、mode = default/vpn/socks5、policy_digest（规范 SHA-256）。观察回执独立于 snapshot，按 Task/run_number 记录原 envd_id、envd_started_at、network_id，记录原固定 relay_id/relay_started_at/relay_network_id，配置模式另记 gateway_id/gateway_started_at/gateway_network_id；只凭原正证进入 prepared、starting、ready、fenced、exited，无法确认保留 unknown。默认也使用固定管理 relay，不虚构 gateway。Blackboard 与旧 Runtime 均可通过 LEGACY_NETWORK_POLICY_FILE 读取同一可信 JSON 的安全元数据：mode 和配置分支的 gateway（固定 image、uplink_network、upstream IPv4/port、VPN 对端身份、允许/禁止 IPv4 范围、独立 HTTP(S) probe、可选 credential_file/credential_sha256）。秘密文件只由 Runtime 验摘要后交原网关，默认双方使用同一个内建 default 摘要。VPN 的 /32 从原实际客户端状态取得；不向 Agent 下发配置原文。普通用户可看到安全模式与阶段；服务端版本化 Runtime 才能读取冻结合同和资源回执。私密配置/原认证文件仅网关读取；不在数据库公开投影、事件、代理变量、argv 或命令记录中输出。Runtime 按同一可信文件的规范摘要与原 Task 合同匹配；未配置默认路径也显式 required-capture。配置变更不重绑存量。
3. **防旧调度器误执行。** 旧 Runtime 使用服务身份直接 GET /api/tasks 和 /deletions，不认识新字段；受保护 Task 对未声明新 ABI 的服务旧列表/删除队列先过滤再分页，已知 ID 的旧服务 /state、running transition、清理/退役入口不能越过合同；公开用户读/启动/停止仍可用。新 Runtime 在服务认证请求带 x-bbx-legacy-execution: legacy-agent-network-v1，取得新合同。服务端新 execution-network 回执入口以同一 Task/run/摘要保存实际就绪；running 转移仅在原正回执成立时允许，不能仅凭 header 宣告就绪。正式 v1 Runtime 与创建受保护执行处理器的 ExecEnvManager 同版部署；不支持只更新客户端版本头而保留旧执行器。受保护 Docker 资源采用独立 bbx.managed=agent-runtime-legacy-network 与独立名称，旧容器扫描不能清理或启动它们；标签不能替代实际 ID 和拓扑核对。旧配置的浏览器只展示现有 Task；不强制用户再选模式或改任务描述。配置模式的外部 VPN 首片只支持一个部署内未结束占用：prepared 只记录原已创建但尚无数据面许可的资源并保留槽；starting 原身份只领取一次实际启动，响应未知不重发；ready 另要求实际路径/采集。VPN 未知不释放，直到原网关退出，默认/SOCKS 不占此槽。

## 三条实际路径

1. **默认网络。** 普通黑板默认保留 Docker 直连/NAT/DNS，不受 VPN readiness 限制，但每 Task 使用独立非 internal bridge 和固定管理 relay，不能同旧 envd 共用可被嗅探控制凭据的执行桥；不将旧 HTTP 代理设置悄悄改成直连，旧代理部署如需继续保留历史版本；新任务无论旧 TRAFFIC_ENABLED=false 都不能跳过原始 Agent 来源采集。兼容的新版 envd/启动器实际创建逐 Agent 网卡与来源，身份匹配 Task/run、原执行容器、Agent/netns/veth；Runtime 启动前核受控采集能力，每 Agent 执行前核原来源。运行时只接受平台选定的原 envd 制品，解析为实际 Docker 镜像 ID 后启动；默认用配套构建，若通过 LEGACY_ENVD_IMAGE 指定替代制品则须不可变摘要。普通 Task profile 不能用任意镜像自称已支持，也不凭环境变量确认能力。配置错误、采集失败、丢包/截断/容量限制明确为不可用或部分；原始来源不可用或达限时不再无证启动新命令。没有证据不记零或完整，也不增加审查或处置流程。既有支持路径和原历史读取不被迁移。
2. **权限不由 Agent 掌握。** 复用原 envd AgentNetworks 和原 TrafficCollector 归档，只信可信启动器的原身份。新的三模式都在可信 setns 后让实际命令以低 UID、无额外能力、no-new-privs 运行，并拒绝显式 privileged；不能用旧 sudo、setuid、共享可改配置或其他 Agent 的 netns/capture 冒充来源。默认兼容指网络路径，不保留新任务的 root 旁路。配置模式单独约束 INPUT/FORWARD、IPv6、Docker 内置 DNS 和旧 envd 的宽转发；新版三条路径均使用原始来源采集，不启动旧 HTTP MITM；既有 HTTP 流量视图继续读原历史。若路径无法真实隔离，不开放该发布。
3. **VPN。** 新 Task 使用按原 ID 归属的 Docker internal 执行桥，Agent envd 只挂其执行面。Docker internal 桥会先丢目标不在桥内网段的直传包；沿现有可信 WireGuard 技术在原 envd 与网关间建立固定内部链路，桥只传两端本地 UDP，网关解包后再进入 VPN 或 SOCKS 路径。该内部链路不新增用户配置或服务。独立可信网关拥有外部可用链路及原 TUN，控制访问用原固定目标、认证的 relay（不是通用代理），其另一端在独立可信控制 bridge，与数据 uplink 分开。容器内 Runtime 以 LEGACY_CONTROL_NETWORK 明示自己的可信服务 bridge；宿主 Runtime 用隔离管理 bridge 和随机 localhost relay 端口。配置与客户端认证只在网关。开启时确认实际 OpenVPN 与 TUN 状态，从相同低权限 Solver 路径完成原 HTTP(S) GET 并收到发布指定的实际状态后，只经原 TUN 转发获准 IPv4 TCP；网关默认丢弃其余流，外层只放原 peer。Agent 不能到旧 direct bridge、共享管理网、其他 Task 或 relay 管理端口。VPN 故障不回退任何直接出口。
4. **SOCKS5。** 同样以实际 internal 执行桥和独立受信网关隔离。首片候选为 [Ubuntu Noble 固定包 redsocks 0.5-2build4](https://packages.ubuntu.com/noble/redsocks)，复用其 [上游透明 TCP-to-SOCKS5 实现](https://github.com/darkk/redsocks)。网关仅从原 envd 执行面接收 TCP，经可信规则透明 REDIRECT、校验原 DNAT 后送原 SOCKS5 上游；无 NAT 原始转发权限，不允许 Agent 直接连接网关监听或管理地址。网关内核外连只放行原精确 SOCKS 上游；即使代理错误也没有直达路径。上游认证只在可信网关，Agent 不持材料。真实 Solver 同路预检必须取得原 HTTP(S) 端点的指定响应状态，不能把 redsocks 本地接受 TCP 当成上游就绪。清空代理环境的普通 socket 在健康时若成功，必须有真实上游 SOCKS5 CONNECT 正证；停上游、禁目标或不支持协议时不回退。首片仅验数字 IPv4 TCP，禁 BIND/UDP ASSOCIATE、IPv6、未批准地址和配置面 DNS；不把 HTTP CONNECT、任意透明协议或全协议当已支持。透明行为与入口 DNAT 防旁路经小能力探针通过后才定制品；若失败，先调整计划，不暗换成普通代理变量。默认 GET /、期望 200，可发布有界 path、status 与 HTTP/HTTPS。固定已验 IPv4 连接；HTTPS 按原可选 hostname（或数字 IP SAN）严格校验，不额外解析、不跟随跳转、不读业务正文或任意 Header。可复用已有普通健康端点，无需部署专用回显服务。业务 HTTP 内容规则不是平台网络探测。
5. **采集/控制始终分开。** 三条路径都在 Agent 网卡端、内部封装、VPN 加密或 SOCKS 汇聚之前取证；平台同路预检/管理另有身份，不能把共享网关外层包记给 Agent。模型、MCP、平台控制走原独立链并保存可关联观测，不将 PCAP 当成 TLS 明文或完整解密。对默认和配置两类，首片真实验收数字 IPv4 TCP；其他协议按既有默认路由或配置限制如实记录，不作全协议承诺。

## 执行、停止和复验

- Runtime supervisor 在实际 provision/find/恢复核原冻结摘要、容器与网络身份和状态；旧 find 会启动容器，收尾采用只读查原对象，绝不重开已撤权出口。配置网络就绪先于 running 和求解命令；未确认或故障记录阻断，不发直连权限。原短期许可或等效失联守护先撤数据面，再做可能出错的抓包/工作区归档。默认无网关，走原 envd 受信网络 fence；若不响应，停止原 envd 并如实记录不能归档，不能重启它绕过。配置模式先撤/停独立原网关并 fence 原 envd；两种路径均先于 drain 和归档，控制 relay 可完成原只读对账。不凭超时/404 判原网关退出；只操作已验证的原 ID。每次恢复按原 Task 网络意图与新 run 的新执行来源，不重用历史流、原采集来源或已失效许可。
- 验证前先做小隔离 Linux/Docker 能力探针：实际 TUN、确实 SOCKS5 握手/负证、最低权限 Agent 不可改原网卡或停采集。必要实际验收用正常用户黑板创建与执行入口、假模型和三种可信部署状态的顺序小场景：默认实际命令及 per-Agent 归档、VPN 同路真实 TCP 及断路、SOCKS 标准上游实际 TCP 及断路。捕获两 Agent 来源的代表性场景足够，另外两模式按真实来源核一次；与本次执行合同等价的已有证据才可复用。再验清空代理环境、直连、管理/其他 Task、禁协议、非授权提升与原停止；不用真实 VPN、SOCKS、模型或靶场。实际配置路径证明前不填写正式发布。补一组真实 PG 状态与重试/旧服务/恢复门验证，必要静态和干净 make check。最终 exact 候选独审后按任务本地提交，不推送/不合 main。
