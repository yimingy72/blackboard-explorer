# P4h：原生后台 helper 接入

实施方案，经三路审核，基于 `0c436c3`。沿用 [开发方案](平台架构重构开发方案-20261105.md) §4、5、11、12、15、[P1 Pi 接缝](P1-Pi接缝验证-20261106-report.md) 和 [P4g 前台实现](P4g-原生helper接入-20261108-report.md)。本轮按 GPT-6.1 Sol high 开发、独立多 Agent 审核，按以下已审边界实现，并通过前台兼容、后台受监督异步及实际链路验证；结果见 [实施报告](P4h-原生后台helper接入-20261108-report.md)。

## 1. 交付与执行方式

新原生 Task 可以在初次可信 launch 冻结启用后台 helper。当前主 Worker 通过真实模型工具发出局部目标，拿到明确的受理结果后继续普通 Pi 回合；原 Assignment 仍有效时，子可继续运行、完成或由原父明确取消。保持 P4g 的一个父最多一个未清子、主工作优先、无位立即返回、同 Task 席位/预算/Sandbox、独立子 binding/SDK/journal，以及原题范围和只读命令记录。后台启用缺省关闭，旧 Task 和已持久化的前台 prepare 字节不改。首片只继承 `read_file`、受服务器限制的前台 `exec_command` 及可信注入的当前题目信息；不开放后台 Shell、递归、业务写入、任意插件工具或命令处置。

选择**同一 TaskRunner 内受监督异步**：复用 P4g 已审核的官方 pi-subagents foreground ToolDefinition 和锁定宿主补丁，实际工具仍调用该插件的前台子 SDK（`async:false`），由 TaskRunner 持有生命周期 promise，父工具不等待子完成。父普通模型回合结束只代表本次响应结束，P4a 的 Worker business turn/Assignment、原 binding 和 permit 仍存续；它不触发取消。原父 SDK 替换/关闭、Assignment 终止或失去有效父范围则停止子。待验证的门槛是真实父模型工具返回后、原父回合已结束时，同一子仍可发送模型/工具请求，并且原插件宿主的最终确认和 dispose 证明不受影响。

不启用上游 detached daemon，不把 P1 的 daemon 夹具算作本片通过，也不新建 Node 进程、第二个 Agent 循环、sidecar 或任务服务。P1 已证明真实 daemon 可以脱离父调用运行，但生产接入还需要跨进程身份、窄 IPC、启动握手、原 process instance 退出证据和通知替换；本片无需跨 Pod 或 Runner 进程存活。若同进程的真实 SDK/插件不能满足父普通回合独立结束或终止正证，保持后台 gate 关闭，报告该接缝；不自动切 daemon。

## 2. 工具、一次启动和期限

- 仅冻结启用后台的主 Worker 暴露受信本地工具：`delegate_helper_background`（有界目标、当前 scope 可读的 Fact 引用和预期产物，与前台同权限）、`background_helper_status`（按原 `child_run_id` 只读状态及已保存结果）和 `cancel_helper`（只写同一原子取消意图）。查询及取消都只限本人当前父 Assignment。已有前台能力独立保留，父子共享同一借位规则。实际模型工具白名单和服务端均检查；helper、Lead、其他 Worker 和旧绑定无权调用。查询及取消调用也以真实父 `ToolInvocation`、确认 journal 和短 MCP 能力验证，不将 Runner-control 信任通道变为普通模型授权入口。
- 复用 P4g Task 锁、原 invocation 摘要、`runner_bindings.business` 的 ChildRun 绑定及 `native_helpers_active` 席位索引。先派独立 ready 主工作；helper 借位检查原 epoch 已注册和在途绑定，达 32 拒绝新增 helper，原主派工规则不变。领取写一次固定 launch 意图；只首次回执携带可信 prepare 与子能力，重复读取状态/结果，无第二个有效 launch。仍由唯一受控宿主 acquire/prepare，普通 poll 不创建第二个 SDK。
- TaskRunner 先注册独立、未启动的 ChildRun 槽，再确认原领取身份的受理。BB 在同一事务把原父工具调用以不可变 `accepted` 结果结账，清父调用未决闩锁；同调用重试只读取相同结果。该回执表示受控运行已登记，不表示子已发模型、成功或退出。宿主只在拿到该回执或同原领取的明确读回后启动一次插件；如领取/实际启动不明，保留原记录和占位，不重发。父调用受理后可以发后续模型；在受理前的原未知不能伪装成普通拒绝。子结果、终态和投递状态写在原 ChildRun 关联的独立字段（可复用原调用 JSONB），不覆盖父工具的受理结果。取消工具单独持久记录“已请求”，不能提前显示已停止。
- 父 reserve/launch/受理只短等确认，仍在原父 `min(now+60s, 原 Task 硬截止, 父能力到期)` 内。子在登记时独立冻结 `min(now+180s, 原 Task 硬截止)`，不沿用父工具超时或父 JWT；此界限不续长。受理后子用自身 AbortController、TaskRunner 停止、父 binding 生命周期及子截止；不再继承会随普通工具/回合结束的信号。父本地冻结、许可过期、binding dispose 及 TaskRunner shutdown 仍显式撤销所有该父/该 Task 持有的子。子 30 秒运行许可经现有原 owner poll 续期，每次核父 Assignment/代次、当前 scope、未取消/暂停/停止和预算，最多到子截止。既有最多 5 分钟的短模型/MCP JWT 本片按子截止截短，覆盖最多 180 秒的子运行，所以不增加 JWT 续签 API。Runner 控制凭据按既有 Task 路径轮换；子终态走可信控制，不依赖过期子执行凭据，不复制父模型/MCP JWT。未知/过期/撤权拒绝新执行，续许可不清 hold。

## 3. 结果、取消与恢复

- 宿主等待同一原插件 run、SDK、最终已确认 journal 和确切 dispose；Sandbox 命令/工具及 scope 仍用 P4g 的原结果和封存核对，不凭插件结果或通知声明物理结束。成功、明确取消或确证未启动的结果有界加摘要，只追加原 ChildRun 证据。缺 terminal、原副作用不明或失去 owner 保持 draining/unknown 和旧占位；可核晚证据只归原记录，不补零、不重试。显式取消、超时、父换题/scope 变化、人工/预算暂停、Task stop/delete/deadline 都先在 Task 锁下撤权，再经原 close/abort 与独立 Sandbox cleaner 收尾。父被撤换时等待子正证，不向旧进程发裸 PID 信号。
- 已确认终态后，若原父 binding/turn/Assignment/generation/epoch/scope 仍有效且无 hold，同一事务保存最终结果、以 ChildRun 派生唯一 `message_id`，并直接用 `RunnerControl._enqueue` 把 follow_up 输入绑定给原父，不依赖 `NativeWorkers._input` 扫描普通邮箱（它只投原 Assignment 首条）。结果作为不可信文本携带原来源；不导入插件 raw watcher 通知。重复结果只读回；以原 `bbx.input` journal/native application 证明标记送达，丢回执同原消息/命令身份复核，不多唤醒。若旧父已失效或 Task 有 hold、停止或暂停，只有历史，不排输入，也不在同 binding 以后解 hold 时自动补投；仍有权限的原父可用只读状态查询。若已排原输入但是否应用不明，保留原未决证据，不因缺 ACK 推断未送，不转发/重播到新 epoch。
- P4c/d 的暂停快照继续纳入子 binding/收尾，显式检查后台子仍未决的状态，不能仅因为父调用 `accepted` 已完成就进入暂停完成。P4e/f 的冻结快照和恢复 gate 单独核后台 ChildRun 的 launch/terminal/result、原输入回执以及原子模型/工具/命令/费用；接受回执不证明子没跑，原进程正退出只证明无残留，不能补结果。旧子不自动恢复，不重写原冻结索引，恢复只允许原主工作走既有新会话。原 Task 正证停止可以按已有生命周期回收终态占位，未决的旧效果仍留史。

## 4. 实施落点与必要验证

| 落点 | 改动 |
| --- | --- |
| `native_helpers.py`、`runner_control_api.py`、`runner_control.py`、`native_worker_dispatch.py` | 同锁借位与一次受理/取消，区分父结果与原 ChildRun 终态/投递，原父精确输入、permit 和级联；优先复用现有 JSONB 与命令/收据 |
| `native_runner_bootstrap.py`、`native_fees.py`、`native_mcp_routes.py`、`native_pause.py`、`native_recovery.py` | 冻结能力、本地模型工具白名单、复用 P4g helper route、暂停和恢复不能跳过原子未决状态；继续单一 Task key |
| `task-runner/src/{helper-host,runner,session,platform}.mjs` 与现有锁定插件/Node tests | 同一宿主的独立监督、正常父回合和父关闭分离、取消/终态证明、只接受真实父模型工具调用，不另建 SDK 循环；无必要不改上游补丁 |
| `packages/contracts/src/bbx_contracts/{runner,runner_bootstrap}.py`、协议/API 生成快照 | 后台可选能力、两个期限、原 ChildRun 状态和受理/取消/结果合同；关闭能力的旧 wire 不加字段；混合 OpenAPI/TS 只应用本片差量 |

1. 一个 Node 正向场景：真实父模型发后台委派、完成普通回合/继续工作，原子仍用自己的 SDK 与受控工具；结果正证后一次投原父。一个故障场景覆盖启动回执丢失或取消，验证无二次启动、不假造关闭、不扩大权限。
2. 一个真实 PostgreSQL 定向场景：共用原借位与优先、父受理持久后仍可进行模型准入；核取消只能原父、结果重复/晚到不跨题、原输入已用 CAS 防重复，以及暂停/原 epoch 未决子不能因父已受理而放行。只加受风险影响的相邻回归。
3. 一条真实本地 Kubernetes 正向链，用隔离唯一网关和假模型，先确认原 Worker 准备，再验后台子跨父普通回合、实际 Sandbox 非 root/原父 attribution、同 Task key 和至少一次真实子运行许可续期、确认关闭后归还席位、只一次给原父投递，最后正证停止保卷。必要的取消和不重放由 Node/PG 故障场景覆盖；不扩 20 席位或逐 Agent 物理网络矩阵。若实际链未过不算生产开启。最终干净候选 `make check`、受影响生成合同检查；不调用真实模型或靶场。
