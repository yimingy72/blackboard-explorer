# 成果树与成果整理 Agent

2026-10-18 用户批准 [完整方案](../proposals/Blackboard-progress-tree-design.md)，并补充：大量意图和 Fact 需要全局梳理，不能把原始对象逐条改写成节点。

成果树是普通黑板的独立阅读投影；原黑板仍是求解共享记忆，只有 Close 裁定目标。成果整理 Agent 不属于 Explore/Derive/Close，不登记 AgentRun、不占求解槽、不创建 Ubuntu。它只读绑定任务与固定来源截止版本的黑板、登记证据和初始附件，只能通过结构化工具维护成果树，不能派工、写 Fact/Intent 或改变求解预算/终态。

树从目标出发，以意图为线索跨意图聚合方向、因果、关键尝试和阶段结论，允许同一来源支持多个分支，避免一意图/一 Fact 对应一个节点。总览必须说明整体已知、主要推进方向、关键未决问题。节点包含清晰的子问题、发现及范围、为何重要、下一步、限制与带引用的关键过程；标题具体表达对象和结果，不使用“已记录”“核对中”等空泛状态替代内容。保留排除项、反例与争议，来源不足只能标记待补证。模型不写坐标、HTML或JS；结构单根、无环、引用同任务且在来源上界内。

复用 MAF Agent、AgentSession、工具、中间件、模型连接器与持久 checkpoint；不使用 Workflow。新增 task_progress 投影和 progress_jobs 租约队列，复用事件、会话、消息存储；问答与自动更新同任务串行。图候选成功完成后 CAS 原子发布；每次完整调用先持久化 Session/用量收据，失败候选仍按实际已执行调用结算。未知执行保留预留，不盲重放，不声称提供方严格只执行一次。

整理独立限额，创建时明确展示额外 ¥2 默认上限、允许调整/关闭；旧任务保持不启用，用户显式启用才创建整理配置。不改变原 task.usage 或预算。费用预留、确认及未知待结算合计受独立上限约束；达限只暂停整理。原任务总费用与整理费用在展示中分项聚合。

自动更新采用10秒合并、至少60秒间隔，按领域事件有界分页推进来源水位，初次回填可连续处理积压批次但仍受限额限制。心跳/工具/费用/消息及 progress.* 不形成总结触发源；progress.* 不修改求解 last_change_version、不触发调度。保持稳定系统前缀与增量上下文，保留完整会话历史。

前端任务内增加成果树视图，复用 React Flow、布局 Worker、坐标保存、InspectorLayout、Ant Design/X、证据与会话组件。默认完整树和收起的右侧详情，展示可读结论、依据、关键过程、缺口和贡献者；点击来源可定位原黑板。支持节点提问及全局问答、拖动/折叠/缩放/保存视角，局部更新，不全树跳动。

状态结合服务端来源状态和明确标记的归纳，不把 proposed Fact 视为验证通过，只有 Close 的裁定可显示目标已达成。争议或引用变化立即使节点显示来源变动，等待新摘要。历史回放同时限制图发布时间与来源状态，使用不可变证据身份，历史模式只读；不能让未来 Session 或最新文件混入旧摘要。

任务终态的最终整理有界、异步，不阻塞 Ubuntu 销毁或任务完成；会话继续保留。续跑保持树和会话，旧轮提交不能覆盖新轮。归档加入当时成果树及整理会话/用量，后续问答不篡改旧归档。删除停止认领，处理活动租约后清理所有整理数据，迟到回调不能复活。模型与提示词沿用平台配置，成果角色设置独立于三种求解 Worker。
