# 使用与部署

本页描述本机正式站 P12 的使用与部署。P13 会话展示和职责调整已暂停，尚未上线，详见 [暂停交接](tasks/P13-会话显示与职责边界-20261112-handoff.md)。组件和开发入口见 [工程说明](工程说明.md)，当前版本和历史里程碑见 [HANDOFF](HANDOFF.md)。

## 现有本机正式站

正式站使用原 Kind 集群；直接打开 [127.0.0.1:15800/login](http://127.0.0.1:15800/login)，沿用原账号。应用、Runtime、PostgreSQL、MinIO 与内部控制代理均在 `bbx-platform`；旧 Docker 业务站已停止。若本机浏览器转发断开，先确认旧转发已退出，再使用部署时的 kubeconfig 重连：

```sh
kubectl --kubeconfig "$BBX_KIND_KUBECONFIG" --context kind-bbx-local-native-k8s \
  -n bbx-platform port-forward --address 127.0.0.1 service/blackboard 15800:80
```

转发只供本机浏览器使用，断开不停止集群内任务或存储。现有站点的只读健康检查、原地重部署、首次安装和备份恢复见 [Kubernetes 部署手册](../deploy/kubernetes/p9/README.md)。实机迁移证据见 [P9 实施报告](tasks/P9-平台全量本地Kubernetes-20261111-report.md)。

## 源码开发与部署入口

源码依赖、普通检查和隔离集成见 [工程说明](工程说明.md#源码检查)。正式站只使用 [Kubernetes 部署手册](../deploy/kubernetes/p9/README.md)，已有站点走原地维护流程。旧 Compose 环境的命令仅用于独立开发环境，不能在正式站旁再启动一套共享原数据的写者。

平台共用一套账号、存储、Pi 模型和 MCP 目录。两种模式分别依据已验的发布配置开放创建，共同 Runtime 为任务启动 OpenSandbox 与 Pi 会话。某模式未通过发布检查时，工作台会显示暂不可用。

### 模型、MCP 和并行任务

在顶部“模型管理”和“MCP 管理”维护平台目录，在“Agent 配置”维护角色授权。新任务选择启用的模型并冻结该任务的调用配置。新任务预算和模型费率以 USD 表示，历史金额与币种按原账本保留。终态只读复盘和模型测试与求解费用分别记录。到达金额阈值后停止发起新调用，已在途调用仍可能产生费用。AgentGateway 不参与当前请求，旧费用不会重新计算。

`MAX_RUNNING_TASKS` 设置同一 Runtime 的任务并行数；超出容量的任务排队。两种模式各任务仍拥有自己的执行环境、会话、预算和档案。运行重型命令或同时使用 VPN 时，并行数也须符合部署的执行容量。

## 从任务到报告

1. 登录后点“新建任务”，先选模式，再填写任务名（可省略）、完整目标和完成要求。黑板模式可填写领域背景、逐项验收条件，以及可选的目标域名记录；CTF 用“完成要求”描述交付范围，不显示领域背景、目标域名或任务级 MCP 选择。请把适用的访问和任务范围写在当前任务内。
2. 选择启用的模型、金额阈值和时长。CTF 表单还可选择思考强度和队友上限；思考强度默认沿用发布角色配置，显式选择固定到本次任务。模型目录更新不替换现有任务的冻结版本。普通黑板可另开自动成果整理，按页面填写独立上限。
3. 创建后手动启动。黑板工作台展示 Fact、Intent、Agent 与验收；Explore 可提交达成声明，由 Close 依据证据裁定。CTF 工作台按题目、分工与成员展示进展，由 Lead 根据原要求收尾。结束后看报告和归档；普通任务只有符合条件时才可显式续跑。

### 初始附件

| 附件 | 当前正式站限制与行为 |
| --- | --- |
| 普通共享附件 | 单件 **16 MiB**，每组最多 **20 件、合计 24 MiB**。接受各种格式并按原字节保存。 |
| CTF 私有配置 | 统一附件区可另选一个 `.ovpn`，**1 B 至 128 KiB**，原字节加密保存，不进入共享列表或工作目录。连接时才校验配置。 |

P12 两种模式使用同一普通上传服务；当前 CTF 发布开启了共享附件配置，因此该服务对黑板模式也执行 16/24 MiB 限额。黑板页仍可能沿用旧的 50 MiB/200 MiB 浏览器提示，请以当前服务端限制为准。

同名普通附件用不同文件 ID 区分。任务启动时恢复到 `/workspace/shared/inputs/<file-id>/<filename>`；在顶部“目标”中查看登记的附件并下载原件。平台不会因上传而自动解压、执行或生成 Fact。修改前先复制到工作目录。上传或创建任务本身不会调用模型。上传失败可重试或移除；如果未收到创建回执，重试同一草稿请求，避免重复创建。未绑定的附件组 24 小时过期；需要时重新上传。任务绑定后的原件不可从上传接口改写。

点击工作台中的 Agent 可打开对话，顶部“目标”可就地展开目标、要求和附件。时长、结束原因与运行统计见状态区；验收依据从目标详情、裁定历史或报告查看。黑板 Fact/Intent 可展开正文与原文。P12 原生 CTF 对话面板可能没有显示已保存的思考和工具记录，参见下方[会话说明](#与-agent-对话和删除任务)。

## 网络模式与排障

黑板模式使用部署发布固定的网络策略。默认出网使用该发布的 DNS 和路由边界；如果管理员已配置强制 VPN 或 SOCKS5，则必须通过该路径的检查才允许任务执行，连接故障时不会改为直连。CTF 模式沿用已发布的独立任务网络；只有获授权的 Lead 可以管理任务 VPN，Worker 没有网络管理权限。上传私有配置成功只表示已保存，不能代替连接时的校验。两种模式的任务网络均与模型服务的连接配置分开。

工作文件位于 `/workspace/agents/agent-N/`，原始附件位于 `/workspace/shared/inputs/`。命令按任务和 Agent 的权限执行。工作台命令页只读显示命令、退出码和超时等记录，没有审计操作入口。原始环境无法确认时，页面会保留已确认记录；未知的模型费用或工具结果不会通过自动重跑来补造。

## 任务流量与 HTTPS 解码

新任务及续跑新轮默认采集；任务顶部点击“流量”，或在 Agent 会话点击流量图标查看该 Agent。数据包、解码 HTTP/HTTPS 事务和模型/工具逻辑调用统一按时间排列，不再分标签页。上方列表显示来源帧号、时间、Agent、端点、协议、长度和 Info；下方为协议树及十六进制/ASCII，分隔栏可拖动。事务和逻辑调用以 `R` 前缀编号，内容详情提供格式化请求、响应和属性；它们不计为额外 wire 包。

筛选框使用服务端官方 sharkd 的 Wireshark 显示过滤器，语法错误直接显示原生错误。示例：`tcp.port == 443`、`ip.addr == 192.0.2.1 && tcp.flags.syn == 1`、`http.response.code == 200`。轮次与 Agent 单独限定采集范围。启用表达式时只返回原生数据包匹配结果，逻辑调用没有包字段，不能伪造匹配。`frame.number`、`tcp.stream` 等按独立采集源解释；同时查看多个 Agent 时相同帧号/stream 号不表示同一条连接。

普通任务和原生 CTF 的采集按 Task、Agent、执行代次和运行轮次归属。受控命令的原始 PCAP 在来源封存后可读，未封存、丢包或不完整的来源会显示状态；不能把未采到当作没有流量。已封存字节用于 Wireshark 原生过滤、协议树和原文件下载，读取不重放命令。旧格式档案在有原索引或密钥时提供相应解析；没有就显示不可用。显式续跑产生独立新轮，历史 PCAP 继续按原轮次读取。

## 检查与评测

以下为日常开发参考；P13 暂停期间不执行检查或评测。

```sh
make check              # 静态检查与普通测试；假模型，无 DeepSeek 费用
make test-integration   # Docker 集成测试；不调用真实模型
```

`make test-integration` 会按 Makefile 构建测试需要的镜像，包括可选代理镜像；这不表示日常运行必须启用代理。显式运行真实模型评测，或从工作台启动使用真实模型的任务，会产生模型费用。旧 `make eval-run` 启动器已退役，历史结果仍可评分。显式端到端命令、任务参数及保留复盘工作台的方法见 [Agent runtime](../services/agent-runtime/README.md)；批量评分见 [评测运行器](../eval/runner/README.md)。`single` 是单 Explore 并发的调度配置，仍使用黑板与 Close，不能当作完全没有黑板的单 Agent 架构。历史 E1/E2 样本使用旧网络与旧 Profile，不能与当前默认直连配置直接比较。

## 按 Agent 查看贡献与复盘

Agent 标签上显示其创建的 Fact、Intent 数量，并用相同颜色标识这些对象的节点背景和作者。认领他人的意图不会改变该意图的创建者颜色。点击 Agent 后，可展开“产出”定位对象，从会话“更多操作 → 运行信息”查看耗时、调用数与 token；数量只表示已提交记录。需要事件、裁定历史、时间轴或工作区时，点击顶部“更多任务操作 → 复盘记录”。Fact/Intent 的阅读排版会整理旧正文的编号条目和长段落，点击“原文”查看或复制存储的原始文字。


## 与 Agent 对话和删除任务

在普通黑板任务中，点 Agent 标签或节点打开右侧面板。运行中消息通常在下一轮送达；长命令或当前模型请求不会被输入立即中断。已结束的普通任务在支持时可继续只读问答，复盘模型费用独立记录。历史回放视图不能发送消息。打开记录本身不会触发模型调用。

**P12 原生 CTF 的已知显示缺口：** 对话面板读取的兼容会话记录可能为空，实际 Runner 日志仍可能含已确认的思考和工具记录。页面空白不能据此判断 Agent 没有工作；请结合题目记录、运行状态与已确认回执。P13 候选拟补上有界展示并标注来源，目前线上没有这项能力。

在任务列表点击“删除”，确认后清理该任务的黑板、全部会话、消息、证据、报告与归档；运行中需先结束任务。删除中的任务会显示“删除中”，清理异常由后台重试，不应手工删数据库行或清空所有数据卷。


## Agent、模型与 MCP 配置

普通 Worker 页分别编辑 Explore、Derive、Close 的提示词与可配置工具。目录列出实际工具及参数；Explore 的命令和文件读写为一组，Derive 与 Close 没有沙箱。保存后供新建任务使用，已创建任务与续跑保持原快照，只有明确选择的工具刷新按续跑合同生效。CTF Lead/Worker 页面显示部署已发布的权限与提示词，不在页面修改发布；成果整理的提示词和工具从下一整理轮生效，模型及价目在任务首次启用整理时冻结，整理预算与求解分开。

模型管理使用 OpenAI 兼容 Chat Completions。填写可达并获准的 HTTPS 服务地址、实际模型 ID、输入/输出限制和所需能力；支持的出站地址由部署配置。密钥保存在平台加密存储，不从回读接口返回。四项美元单价为输入、输出、缓存读和缓存写；未定价时可以测试连接，任务需要可用凭据、适合的能力和价目。模型测试可能向所填供应商发出请求。已创建任务使用冻结版本，历史账本的币种和已记录金额不会按当前价重算。

独立的 MCP 管理页使用公网 HTTPS Streamable HTTP；CTF 创建页没有任务级 MCP 选择器。先保存草稿、显式发现工具，再选择可发布工具与角色并发布。发现只列工具，不调用业务工具。只有 Explore、CTF Lead 与 CTF Worker 可以获明确授权；目录发布与给具体任务授予工具是两件事。Derive、Close 和成果整理不使用外部 MCP。备份应另保留原服务端签名与凭据加密密钥。

## 完成前推导复核

只有明确目标范围、直接完成证据充分且无关键未验证事项时，Close才能声明completion_basis=explicit并记录完成理由，从而允许不启动derive直接收尾。其余情况先完成现有方向，静止后由derive复核，再由Close再次裁定。复核产生新Intent会回到探索；无新方向须说明排除理由，不能用空回执冒充通过。图谱/Agent列表将此类derive显示为“完成复核”，目标详情可看明确完成依据。

新事实、意图或争议变化会使旧复核失效；预算、时间、人工停止仍优先于继续探索。关闭“主动并行推导”不关闭必要复核。single参数仍仅限制一个Explore，但必要derive/Close仍参与，历史评估的“无derive”口径不再适用于新版。


## 续跑与证据阅读

Explore 先用本次已授予的 `read_file` 读回工作区文件，再用 `post_fact.evidence` 登记 `type`、`path`、`summary`；初始附件可引用原登记路径。只在正文或命令提及文件路径不会登记文件。任务归档保存已确认会话和必要证据，不保留未登记的临时缓存或进程。Derive 和 Close 可按已授予的 `read_evidence` 分页读取登记证据，不直接访问沙箱。模型目录中的图片输入能力不等于角色拥有看图工具。

普通任务仅在原执行资源退出已确认、归档可读且当前发布与原环境兼容时可显式续跑。追加额度以 USD 表示，累加已有消耗；新环境只恢复已登记的必要文件。模型、目标、验收与旧归档保持，未确认操作或费用不会自动重放或填零。原生 CTF 当前不承诺跨任务运行代次的显式续跑；已结束记录可以按原权限复盘。

## CTF 题目与收尾

题目、当前 Assignment、候选与可信验证分别保留。题目状态、成员本轮结束或候选文本均不能代替平台验收；Lead 仅按原授权及可信回执提交、核对和结束任务。处理未知执行结果时先核对保存的回执和状态，不重做结果未知的操作。历史实现见 [团队交流审查报告](tasks/CTF-team-communication-audit-report.md) 和 [控制链审查报告](tasks/CTF-control-audit-report.md)；其中的旧配置工具、Provider、人民币计费和容器运维命令仅用于解释历史，不适用于正式站。
