# 使用与部署

本页描述当前 `main` 的本地运行方式。项目是通用问题求解引擎，黑板式多 Agent 是协作机制。设计规则以 [`docs/design/`](design/黑板式探索架构设计.md) 为准；历史测试结果和阶段性限制见 [HANDOFF](HANDOFF.md) 与对应任务报告。

## 准备与启动

在仓库根目录执行。复制 `.env.example` 为 `.env`，自行设置数据库、对象存储、服务令牌、`ADMIN_USERS` 和 `DEEPSEEK_API_KEY`；不要提交或分享 `.env`。如果 runtime 访问模型需要宿主机代理，在 `.env` 配置 `RUNTIME_HTTP_PROXY` 与 `RUNTIME_HTTPS_PROXY`。下面的构建需要 Docker 和已安装的 uv、pnpm。镜像下载或构建需要宿主机代理时，按本机网络情况为命令单独设置代理；这些变量不会自动赋予执行容器代理出网。

```sh
UV_CACHE_DIR=/private/tmp/bbx-uv-cache uv sync --locked
make web-install web-build
make image-exec-env image-agent-runtime image-blackboard
docker compose --project-name blackboard-explorer up -d --wait
```

工作台地址是 <http://127.0.0.1:58000/login>，登录凭据来自你配置的 `ADMIN_USERS`。以上为基础服务，使用自建目标的公网地址时无需启动仓库内的评测目标。`make up` 只执行基础 `docker compose up -d`，不构建镜像，也不启动开发叠加文件。

需要使用仓库内置目标时，先构建素材并叠加开发 Compose：

```sh
make eval-targets
docker compose --project-name blackboard-explorer -f docker-compose.yml -f docker-compose.dev.yml up -d --wait
```

`eval-targets` 在执行网络中提供内置目标素材。当前目标和选择方法见 [评测目标](../eval/targets/README.md)及[评测任务](../eval/tasks/README.md)。

## 从任务到报告

1. 登录后在“新建任务”填写目标、领域资料和可检查的完成条件，再选择 Profile 与预算。自建目标的地址、访问约束和操作边界应写入任务资料；不要假设 Agent 能从其他任务继承这些信息。
2. 启动任务后，在工作台查看 Agent、Fact、Intent、关系和事件。Fact 是 Agent 提交的发现，仍需结合证据核对；它不会因文字相似而被代码自动丢弃。各 Agent 根据同步的黑板信息自行判断是否重复。
3. Explore 可以声明目标已满足，调度器据此安排 Close；只有 Close 的裁定会改变任务的完成状态并生成报告。若证据不足，报告应说明缺口。任务结束后可以查看报告和工作区归档；终态任务不能重新启动，要换网络或资料须新建任务。

任务页标题下方显示已持续时间。状态行下方设分割线，下一行同时显示结束原因与运行统计；验收理由和缺口可从目标节点详情或裁定历史查看。图谱展示当前版本的全部对象，不提供筛选或自动折叠；右下角保留紧凑缩略图。事实和意图的详情正文使用 Markdown 排版，路径、命令和代码块可清晰阅读。常驻 Agent 条显示该任务的所有 Agent，从 1 独立编号，已结束者也保留；点击条目或拓扑中的 Agent 可打开右侧对话记录。新运行会保存初始上下文、黑板注入、模型返回内容与工具调用；长内容按需展开并可下载。模型未返回推理文本时不生成替代内容。旧任务只展示已保存的工具调用和回执，并标明上下文未记录。

## 网络模式与排障

默认配置是 `EXEC_EGRESS_MODE=direct`、`EXEC_NETWORK_INTERNAL=false`：新建的 Ubuntu 执行容器经 Docker 网关直接访问外部地址，不注入 `HTTP_PROXY`/`HTTPS_PROXY`。任务表单里的 `egress_allowlist` 在此模式只记录需求，不限制连接。执行容器仍保留独立用户、文件权限和内部控制接口鉴权。宿主机用于拉镜像/下载依赖的 `127.0.0.1:7897`，以及 Agent runtime 访问 DeepSeek 时可设置的 `RUNTIME_HTTP_PROXY`/`RUNTIME_HTTPS_PROXY`，都不决定执行容器的出网方式。Docker Desktop 上，runtime 的宿主机代理地址通常写为 `http://host.docker.internal:7897`。

只有确实需要部署级白名单时，才切换到 `EXEC_EGRESS_MODE=proxy`、`EXEC_NETWORK_INTERNAL=true`，在 `.env` 中设置 `EGRESS_ALLOWLIST`，构建可选代理镜像并启用其 Compose profile：

```sh
make image-egress-proxy
docker compose --project-name blackboard-explorer --profile egress-proxy -f docker-compose.yml -f docker-compose.dev.yml down --remove-orphans
docker compose --project-name blackboard-explorer --profile egress-proxy -f docker-compose.yml -f docker-compose.dev.yml up -d --wait
```

先结束仍在运行的任务，再切换模式并重建网络；不要在已有任务的执行容器上期待设置即时生效。上述 `down` 不带 `-v`，保留 PostgreSQL/MinIO 数据卷。没有使用内置目标时，可去掉两处 `-f docker-compose.dev.yml`。从代理模式切回直连也需要带 `--profile egress-proxy` 执行 `down --remove-orphans` 清理旧代理容器，再把 `.env` 改回直连设置并按基础模式 `up`。白名单由部署级 `EGRESS_ALLOWLIST` 决定，任务字段不会动态更新它；代理细节见 [egress-proxy](../services/egress-proxy/README.md)。

可用 `docker network inspect blackboard-explorer_exec --format '{{.Internal}}'` 核对执行网络：默认直连为 `false`，代理隔离为 `true`。若看到代理返回的 `403 Filtered`，检查是否启用了代理模式和部署级白名单；直连模式下的 HTTP 403 也可能是目标服务自身响应。`Network is unreachable` 先检查执行网络是否为 internal、容器是否在预期网络和目标路由是否可达。已有终态任务的报告不会因改配置而变化；请新建任务重试。

## 检查与评测

```sh
make check              # 静态检查与普通测试；假模型，无 DeepSeek 费用
make test-integration   # Docker 集成测试；不调用真实模型
```

`make test-integration` 会按 Makefile 构建测试需要的镜像，包括可选代理镜像；这不表示日常运行必须启用代理。`make e2e`、`make eval-run`、`make test-live` 和工作台真实任务会请求 DeepSeek，产生费用。显式端到端命令、任务参数及保留复盘工作台的方法见 [Agent runtime](../services/agent-runtime/README.md)；批量评分见 [评测运行器](../eval/runner/README.md)。`single` 是单 Explore 并发的调度配置，仍使用黑板与 Close，不能当作完全没有黑板的单 Agent 架构。历史 E1/E2 样本使用旧网络与旧 Profile，不能与当前默认直连配置直接比较。

## 按 Agent 查看贡献与复盘

Agent 标签上显示其创建的 Fact、Intent 数量，并用相同颜色标识这些对象的节点背景和作者。认领他人的意图不会改变该意图的创建者颜色。点击 Agent 后，可展开“产出”定位对象，展开“运行概况”查看耗时、调用数与 token；数量只表示已提交记录。需要事件、裁定历史、时间轴或工作区时，点击顶部“复盘记录”。Fact/Intent 的阅读排版会整理旧正文的编号条目和长段落，点击“原文”查看或复制存储的原始文字。


## 与 Agent 对话和删除任务

点击 Agent 标签或节点，在右侧输入框发送消息；Ctrl/⌘+Enter 可发送。运行中消息将在下一模型轮次送达，长命令或当前模型请求不会被输入立即中断。任务结束后仍可在同一处继续只读问答，复盘模型费用单独记录。历史回放视图不可发送，返回实时后即可继续。

新版本启动的 Agent 自动持久化原生 Session；旧任务可基于已有记录建立 legacy 复盘会话，界面会说明原会话未保存。仅查看页面不会调用模型，发送消息才会请求模型。会话一直保留到删除任务。

在任务列表点击“删除”，确认后清理该任务的黑板、全部会话、消息、证据、报告与归档；运行中需先结束任务。删除中的任务会显示“删除中”，清理异常由后台重试，不应手工删数据库行或清空所有数据卷。


## 人民币预算与完整 worker 提示词

内置 default/single 新版为 CNY，输入10表示10元；固定高峰单价每百万token为0.04/2/8元（缓存命中/未命中/输出）。费用是本地估算，供应商实扣可能因峰谷价而不同。TaskView.cost_currency 从任务固定 Profile 读取，旧美元任务显示US$且保留原始账本；所有worker须同币种。历史配置仍可查看、复制和选择，选择旧版时注意创建页面明确标注的币种，不能只改 currency 而不改价格数值。

Agent 配置 → 选版本 → Explore/derive/Close，直接查看完整提示词。点击“编辑并发布新版本”可分别编辑；“高级 YAML”可修改模型价格等完整配置。两个入口共享草稿，无效YAML须修正后才能切回worker编辑。提示词中的Jinja变量和分支按运行上下文填充；种子与Explore、judge/final与Close分别复用模板。发布不覆盖旧版，也不改变已创建任务。
