# 使用与部署

本页描述当前代码的本地运行方式，已部署环境的实际版本以 HANDOFF 为准。项目是通用问题求解引擎，黑板式多 Agent 是协作机制。设计规则以 [`docs/design/`](design/黑板式探索架构设计.md) 为准；历史测试结果和阶段性限制见 [HANDOFF](HANDOFF.md) 与对应任务报告。

## 现有本机正式站

正式站使用原 Kind 集群；直接打开 [127.0.0.1:15800/login](http://127.0.0.1:15800/login)，沿用原账号。应用、Runtime、数据库和对象存储均在集群中。若本机浏览器转发断开，先确认旧转发已退出，再使用部署时的 kubeconfig 重连：

```sh
kubectl --kubeconfig "$BBX_KIND_KUBECONFIG" --context kind-bbx-local-native-k8s \
  -n bbx-platform port-forward --address 127.0.0.1 service/blackboard 15800:80
```

转发只供本机浏览器使用，断开不停止集群内任务或存储。现有站点的只读健康检查、原地重部署、首次安装和备份恢复见 [Kubernetes 部署手册](../deploy/kubernetes/p9/README.md)。实机迁移证据见 [P9 实施报告](tasks/P9-平台全量本地Kubernetes-20261111-report.md)。

## 源码开发与旧 Compose 部署

以下命令仅用于单独的源码开发或原有 Compose 环境。操作 P9 正式站时使用上述 Kubernetes 入口和 [P9 部署清单](../deploy/kubernetes/p9/README.md)，避免启动第二套平台写者。

平台只有一个登录入口，共用一套 PostgreSQL、对象存储、Pi 模型和 MCP 配置。登录后从“新建任务”选择“黑板模式”或“CTF 模式”，选择在任务创建后固定。两种模式由同一个 Runtime 启动 OpenSandbox 和 Pi 会话；各模式的发布环境分别验明后才会开放创建。

首次部署按 `.env.example` 在部署机器填写本地账号、存储和签名配置。已有部署保留原 Compose 项目、数据卷和密钥，不换项目名或覆盖数据库。基础站点可先启动，仅在可信集群及两种模式的发布文件就绪后启动共同 Runtime：

```sh
make web-install web-build image-blackboard image-agent-runtime
docker compose up -d --wait
docker compose --profile shared-runtime up -d --wait
```

第二条 Compose 命令适用于已按 `.env.example` 配置发布文件、Linux 版 kubectl、可信 kubeconfig 和私有控制地址的部署。集群需能访问发布中固定的 Runtime / Blackboard 地址；浏览器仍只访问同一个站点。没有通过验收的模式会显示暂不可用，不会创建到另一站或退回旧执行器。

### 模型、MCP 和并行任务

在顶部“模型管理”和“MCP 管理”维护平台目录，在“Agent 配置”维护角色授权。新任务选择启用的模型并冻结该任务的调用配置。费用按原账本归集，已有任务保留原币种；终态只读复盘和模型测试与求解费用分别记录。AgentGateway 不参与当前请求，旧费用不会重新计算。

`MAX_RUNNING_TASKS` 设置同一 Runtime 的任务并行数；超出容量的任务排队。两种模式各任务仍拥有自己的执行环境、会话、预算和档案。运行重型命令或同时使用 VPN 时，并行数也须符合部署的执行容量。

## 从任务到报告

1. 登录后在“新建任务”填写简短任务名、完整目标、领域资料和可检查的完成条件，可添加初始附件，再选择任务模式、模型、推理强度与预算。任务名可省略，旧任务以目标摘要展示；完整目标在工作台顶部“目标”中就地展开。任务使用所选模型的能力与快照；修改平台目录不会替换既有任务的模型。自建目标的地址、访问约束和操作边界应写入任务资料；不要假设 Agent 能从其他任务继承这些信息。
2. 启动任务后，在工作台查看 Agent、Fact、Intent、关系和事件。Fact 是 Agent 提交的发现，仍需结合证据核对；它不会因文字相似而被代码自动丢弃。各 Agent 根据同步的黑板信息自行判断是否重复。
3. Explore 可以声明目标已满足，调度器据此安排 Close；只有 Close 的裁定会改变任务的完成状态并生成报告。若证据不足，报告应说明缺口。任务结束后可以查看报告和任务归档；归档完成后可通过“续跑任务”追加预算和时长，保留原黑板与会话；目标和验收范围变化时建议新建任务。

初始附件每个最多50 MiB，最多20个、总计200 MiB。同名文件按不同文件ID保存，启动前恢复到 `/workspace/shared/inputs/<file-id>/<filename>`；工作台顶部“目标”的附件入口可查看路径并下载原件。上传不自动解压、执行或生成Fact。需修改时先复制到自己的工作目录或其他共享路径；原件即使未被Fact引用，也保留在必要文件归档和续跑恢复中。创建任务仍需手动点击启动，上传和创建不会调用模型。

上传失败可重试或移除，创建结果未确认时重试同一冻结请求，避免重复建任务。附件组24小时未绑定即过期，点击“重新上传附件”可保留当前草稿并重传；离开创建页会取消未绑定组，清理失败及遗留对象由后台每5分钟分批重试。已绑定文件不可从上传接口改写；删除任务才会清理对应输入与存档。

任务页标题下方显示已持续时间。状态行下方设分割线，下一行同时显示结束原因与运行统计；验收理由和缺口可从目标节点详情或裁定历史查看。图谱展示当前版本的全部对象，不提供筛选或自动折叠；右下角保留紧凑缩略图。事实和意图的详情正文使用 Markdown 排版，路径、命令和代码块可清晰阅读。常驻 Agent 条显示该任务的所有 Agent，从 1 独立编号，已结束者也保留；点击条目或拓扑中的 Agent 可打开右侧对话记录。新运行会保存初始上下文、黑板注入、模型返回内容与工具调用；长内容按需展开并可下载。模型未返回推理文本时不生成替代内容。旧任务只展示已保存的工具调用和回执，并标明上下文未记录。

## 网络模式与排障

黑板模式使用部署发布固定的网络策略。默认出网使用该发布的 DNS 和路由边界；如果管理员已配置强制 VPN 或 SOCKS5，则必须通过该路径的检查才允许任务执行，连接故障时不会改为直连。CTF 模式沿用已发布的独立任务网络和 Lead 按需启用 VPN 的权限。两种模式的网络均与模型服务的连接配置分开。

工作文件位于 `/workspace/agents/agent-N/`，原始附件位于 `/workspace/shared/inputs/`。命令按任务和 Agent 的权限执行，命令、退出码、超时和采集记录可在工作台检查。原始环境无法确认时，页面会保留已确认记录；未知的模型费用或工具结果不会通过自动重跑来补造。

## 任务流量与 HTTPS 解码

新任务及续跑新轮默认采集；任务顶部点击“流量”，或在 Agent 会话点击流量图标查看该 Agent。数据包、解码 HTTP/HTTPS 事务和模型/工具逻辑调用统一按时间排列，不再分标签页。上方列表显示来源帧号、时间、Agent、端点、协议、长度和 Info；下方为协议树及十六进制/ASCII，分隔栏可拖动。事务和逻辑调用以 `R` 前缀编号，内容详情提供格式化请求、响应和属性；它们不计为额外 wire 包。

筛选框使用服务端官方 sharkd 的 Wireshark 显示过滤器，语法错误直接显示原生错误。示例：`tcp.port == 443`、`ip.addr == 192.0.2.1 && tcp.flags.syn == 1`、`http.response.code == 200`。轮次与 Agent 单独限定采集范围。启用表达式时只返回原生数据包匹配结果，逻辑调用没有包字段，不能伪造匹配。`frame.number`、`tcp.stream` 等按独立采集源解释；同时查看多个 Agent 时相同帧号/stream 号不表示同一条连接。

普通任务和原生 CTF 的采集按 Task、Agent、执行代次和运行轮次归属。受控命令的原始 PCAP 在来源封存后可读，未封存、丢包或不完整的来源会显示状态；不能把未采到当作没有流量。已封存字节用于 Wireshark 原生过滤、协议树和原文件下载，读取不重放命令。旧格式档案在有原索引或密钥时提供相应解析；没有就显示不可用。显式续跑产生独立新轮，历史 PCAP 继续按原轮次读取。

## 检查与评测

```sh
make check              # 静态检查与普通测试；假模型，无 DeepSeek 费用
make test-integration   # Docker 集成测试；不调用真实模型
```

`make test-integration` 会按 Makefile 构建测试需要的镜像，包括可选代理镜像；这不表示日常运行必须启用代理。`make test-live` 和使用已配置真实模型的工作台任务可能产生费用。旧 `make eval-run` 启动器已退役，历史结果仍可评分。显式端到端命令、任务参数及保留复盘工作台的方法见 [Agent runtime](../services/agent-runtime/README.md)；批量评分见 [评测运行器](../eval/runner/README.md)。`single` 是单 Explore 并发的调度配置，仍使用黑板与 Close，不能当作完全没有黑板的单 Agent 架构。历史 E1/E2 样本使用旧网络与旧 Profile，不能与当前默认直连配置直接比较。

## 按 Agent 查看贡献与复盘

Agent 标签上显示其创建的 Fact、Intent 数量，并用相同颜色标识这些对象的节点背景和作者。认领他人的意图不会改变该意图的创建者颜色。点击 Agent 后，可展开“产出”定位对象，从会话“更多操作 → 运行信息”查看耗时、调用数与 token；数量只表示已提交记录。需要事件、裁定历史、时间轴或工作区时，点击顶部“更多任务操作 → 复盘记录”。Fact/Intent 的阅读排版会整理旧正文的编号条目和长段落，点击“原文”查看或复制存储的原始文字。


## 与 Agent 对话和删除任务

点击 Agent 标签或节点，在右侧输入框发送消息；Ctrl/⌘+Enter 可发送。运行中消息将在下一模型轮次送达，长命令或当前模型请求不会被输入立即中断。任务结束后仍可在同一处继续只读问答，复盘模型费用单独记录。历史回放视图不可发送，返回实时后即可继续。

新版本启动的 Agent 自动持久化原生 Session；旧任务可基于已有记录建立 legacy 复盘会话，界面会说明原会话未保存。仅查看页面不会调用模型，发送消息才会请求模型。会话一直保留到删除任务。

在任务列表点击“删除”，确认后清理该任务的黑板、全部会话、消息、证据、报告与归档；运行中需先结束任务。删除中的任务会显示“删除中”，清理异常由后台重试，不应手工删数据库行或清空所有数据卷。


## Agent、模型与 MCP 配置

普通 Worker 页分别编辑 Explore、Derive、Close 的提示词与可配置工具。目录列出实际工具及参数；Explore 的命令和文件读写为一组，Derive 与 Close 没有沙箱。保存后供新建任务使用，已创建任务与续跑保持原快照，只有明确选择的工具刷新按续跑合同生效。CTF Lead/Worker 页面显示部署已发布的权限与提示词，不在页面修改发布；成果整理的提示词和工具从下一整理轮生效，模型及价目在任务首次启用整理时冻结，整理预算与求解分开。

模型管理使用 OpenAI 兼容 Chat Completions。填写可达并获准的 HTTPS 服务地址、实际模型 ID、输入/输出限制和所需能力；支持的出站地址由部署配置。密钥保存在平台加密存储，不从回读接口返回。四项美元单价为输入、输出、缓存读和缓存写；未定价时可以测试连接，任务需要可用凭据、适合的能力和价目。模型测试可能向所填供应商发出请求。已创建任务使用冻结版本，历史账本的币种和已记录金额不会按当前价重算。

MCP 管理使用公网 HTTPS Streamable HTTP。先保存草稿、显式发现工具，再选择可发布工具与角色并发布。发现只列工具，不调用业务工具。只有 Explore、CTF Lead 与 CTF Worker 可以获明确授权；目录发布与给具体任务授予工具是两件事。Derive、Close 和成果整理不使用外部 MCP。备份应另保留原服务端签名与凭据加密密钥。

## 完成前推导复核

只有明确目标范围、直接完成证据充分且无关键未验证事项时，Close才能声明completion_basis=explicit并记录完成理由，从而允许不启动derive直接收尾。其余情况先完成现有方向，静止后由derive复核，再由Close再次裁定。复核产生新Intent会回到探索；无新方向须说明排除理由，不能用空回执冒充通过。图谱/Agent列表将此类derive显示为“完成复核”，目标详情可看明确完成依据。

新事实、意图或争议变化会使旧复核失效；预算、时间、人工停止仍优先于继续探索。关闭“主动并行推导”不关闭必要复核。single参数仍仅限制一个Explore，但必要derive/Close仍参与，历史评估的“无derive”口径不再适用于新版。


## 续跑与证据阅读

Explore 先用本次已授予的 `read_file` 读回工作区文件，再用 `post_fact.evidence` 登记 `type`、`path`、`summary`；初始附件可引用原登记路径。只在正文或命令提及文件路径不会登记文件。任务归档保存已确认会话和必要证据，不保留未登记的临时缓存或进程。Derive 和 Close 可按已授予的 `read_evidence` 分页读取登记证据，不直接访问沙箱。模型目录中的图片输入能力不等于角色拥有看图工具。

普通任务仅在原执行资源退出已确认、归档可读且当前发布与原环境兼容时可显式续跑。追加额度以 USD 表示，累加已有消耗；新环境只恢复已登记的必要文件。模型、目标、验收与旧归档保持，未确认操作或费用不会自动重放或填零。原生 CTF 当前不承诺跨任务运行代次的显式续跑；已结束记录可以按原权限复盘。

## CTF 题目与收尾

题目、当前 Assignment、候选与可信验证分别保留。题目状态、成员本轮结束或候选文本均不能代替平台验收；Lead 仅按原授权及可信回执提交、核对和结束任务。处理未知执行结果时先核对保存的回执和状态，不重做结果未知的操作。历史实现见 [团队交流审查报告](tasks/CTF-team-communication-audit-report.md) 和 [控制链审查报告](tasks/CTF-control-audit-report.md)；其中的旧配置工具、Provider、人民币计费和容器运维命令仅用于解释历史，不适用于正式站。
