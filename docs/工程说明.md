# 工程说明

截至 2026-11-12，本机正式站为 P12。本文描述当前工程入口和运维边界。P13 改动仍在独立候选源码中，尚未提交、构建或上线；候选验证进度见 [P13 暂停交接](tasks/P13-会话显示与职责边界-20261112-handoff.md)。

## 组件与数据流

| 组件 | 主要职责 | 源码入口 |
| --- | --- | --- |
| Web | 单站登录、创建表单、黑板及 CTF 工作台、Agent 对话、命令与流量查看 | [web/src](../web/src) |
| Blackboard / App | 登录与授权、任务与角色配置、领域事件、调用回执、账本、归档读取与实时订阅 | [API](../services/blackboard/src/bbx_blackboard/api.py)、[领域规则](../services/blackboard/src/bbx_blackboard/domain)、[存储](../services/blackboard/src/bbx_blackboard/store) |
| 共同 Runtime | 调度、任务资源生命周期、与 Runner 的受控交接、Pi 模型调用和费用回执 | [Runtime](../services/agent-runtime/src/bbx_runtime)、[任务 Runner](../services/agent-runtime/task-runner) |
| 执行与采集 | OpenSandbox 工作环境、任务文件和工具、任务网络与流量来源 | [sandbox-execution](../services/sandbox-execution)、[envd](../services/envd)、[流量处理](../services/agent-runtime/src/bbx_runtime/traffic) |
| 共用契约与模板 | 跨服务消息、授权范围、记录格式、默认角色内容 | [packages/contracts](../packages/contracts)、[profiles](../profiles) |
| 平台存储 | PostgreSQL 保存任务、状态、账本和索引；MinIO 保存附件、证据、报告、采集件和归档对象 | [数据库迁移](../services/blackboard/migrations)、[对象存储](../packages/objects)、[Kubernetes 部署手册](../deploy/kubernetes/p9/README.md) |

用户从同一 App 创建和查看任务，浏览器不直接连接 Runner 或存储。App 校验任务和角色的发布配置，Runtime 通过单一监督者领取工作，启动任务的 OpenSandbox 与 Pi 会话。Pi 管理模型与工具的回合；Python 管理调度、预算、授权、持久事务和资源退出。工作区、会话和费用按任务隔离，两个模式共用平台并行容量。部署清单默认允许两个运行中任务，超出后排队。

P6 已将模型管理切换到平台自有的 OpenAI 兼容目录，AgentGateway 只作历史背景。调用使用创建或启用相关能力时冻结的模型版本与价目。新任务为 USD；旧账本保留原币种。达到金额阈值会抑制新调用，已经在途的调用仍可能结算。未确认的结果或费用保留原状态；不能用重放、填零或手工完成来抹平不确定性。

## 角色、网络与记录

- 黑板的 Fact 是带依据的主张；Intent 是探索方向。Explore 提交，Derive 复核和提出方向，Close 按证据裁定。成果整理只读任务资料、写入成果树，不执行命令或接管裁定。
- 原生 CTF 的 Lead 管理成员和 Assignment。任务网络管理只开放给已获相应发布授权的 Lead；Worker 没有 VPN 管理权限。任务网络、平台模型访问路径和独立的 MCP 授权分别管理。全局 MCP 目录仍在，CTF 创建表单没有任务级 MCP 选择器。
- 命令页面用于只读查看工具记录、退出码和超时等结果，没有审计操作入口。两种模式的 Agent 流量都按任务、Agent、执行代次和轮次归集；原始包、解码事务和逻辑调用是不同来源。缺采、未封存和不完整有各自状态，不能用缺失推断无流量。
- 会话显示和可执行检查点是不同层。P12 的原生 CTF 页面仍可能读到空的 `agent_sessions`，而实际 Runner 日志已有确认记录。P13 候选增加有界的只读展示及来源证明；不会用展示来启动或继续任务。其独立收集器和终态归档导入均未上线。

## 源码检查

以下命令供恢复开发后在隔离源码目录使用，当前 P13 暂停期间不运行。源码开发使用 Python 3.12、uv、Node.js 22.21+ 和仓库指定的 pnpm 版本；按锁文件装依赖。普通检查使用假模型。

```sh
uv sync --locked
make pi-install
make check
make web-install
make web-check
```

`make check` 包括 Ruff、Pyright、Pi 和普通 Python 测试。Docker 集成用 `make test-integration`，应与正式站隔离。涉及发布时，应分别验证 PostgreSQL、浏览器与目标 Kubernetes 准入；完整检查必须对最终候选重跑，历史绿灯不能替代。真实模型、外部 MCP 和任务 VPN 不是普通检查的前置条件。
